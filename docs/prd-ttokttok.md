> **"지식이 똑똑 노크해요."**
> 숏폼 피드로 책을 발견하고, 그 자리에서 바로 읽기 시작하는 모바일 웹 서비스

|---|---|
| 문서 버전 | v1.0 (2026-08-27) |

## 1. Executive Summary

**똑똑**은 인스타그램 릴스/유튜브 쇼츠의 소비 문법으로 책을 발견하게 하는 전자책 플랫폼이다. 세로 스크롤 피드에 도서 소개 카드 게시물과 짧은 영상 게시물이 흐르고, 관심이 생기면 그 자리에서 EPUB 뷰어가 열려 바로 읽기 시작한다.

- **핵심 루프**: 피드에서 발견 → 뷰어에서 읽기 → 진행률/보관함으로 재방문 → 다시 피드
- **북극성 지표**: 콘텐츠 조회 → 뷰어 진입 **전환율**, 1인당 **열람 시간** (모두 전문 도서 기준 — 링크형 도서는 구매 링크 깔때기로 별도 측정)
- **MVP 원칙**: 콘텐츠 공급은 관리자 단독(장르별 큐레이션 채널 페르소나). 사용자는 소비 + 소셜 인터랙션(좋아요·댓글·공유 전부 실동작)만.
- **콘텐츠 수급**: 도서는 두 형태 — **전문 도서**(저작권 만료작 등 본문 보유, 관리자가 EPUB 업로드)와 **링크형 도서**(인기도서 등 본문 미보유 — 카드 소개 + 외부 서점 구매 링크(ISBN 자동생성)만). 미리보기·발췌 열람은 없다 (§5.11, 결정 기록 §11-29).
- **플랫폼/스택**: 모바일 우선 반응형 웹. Next.js + Vercel + Supabase + epub.js.

### 비목표 (MVP에서 하지 않는 것)
- 사용자 콘텐츠 게시(UGC) — 업로드는 관리자만
- 결제/구독 — 수익화 없음, 구매는 외부 서점 링크로만
- 포인트·레벨·지식 성좌 등 보상형 게이미피케이션 (기록형만 제공)
- 추천 개인화(ML) — 가중 랜덤 + 인기 가중치까지만
- 네이티브 앱 / PWA 푸시
- 다국어 — 한국어 단일

## 2. 배경과 문제 정의

- 독서 앱(밀리의 서재 등)은 "읽으려는 사람"을 위한 도구다. "읽을 생각이 없던 사람"을 책으로 끌어들이는 접점이 없다.
- 반면 숏폼(릴스/쇼츠)은 의도 없이 열어도 소비가 시작되는 포맷이지만, 그 발견이 독서로 이어지는 경로가 끊겨 있다 (책 소개 릴스를 봐도 → 서점 검색 → 구매 → 앱 설치… 마찰이 크다).
- **똑똑은 발견과 독서 사이의 마찰을 0으로 만든다**: 카드에서 흥미 → 탭 한 번 → 뷰어에서 첫 장이 열린다.

### 성공 지표
| 지표 | 정의 | MVP 목표 성격 |
|---|---|---|
| 뷰어 전환율 | 게시물 조회 대비 뷰어 진입 비율 (전문 도서) | 핵심(북극성) |
| 열람 시간 | 뷰어 체류 시간 / 사용자 | 핵심 |
| 완독·챕터 완료율 | 진행률 이벤트 기반 | 보조 |
| 재방문율 | 7일 내 재방문 | 보조 |
| 좋아요·공유 수 | 소셜 인터랙션 | 보조 |
| 구매 링크 클릭 | 링크형: post_view → 시트 → purchase_link_click | 보조 |

## 3. 타깃 사용자

- **주 타깃**: 틈새 시간에 스마트폰으로 숏폼을 소비하는 20~40대. 독서 의향은 있으나 실행이 안 되는 층.
- **장르**: 전 장르 (경제경영·자기계발·소설·인문·에세이·과학 등). 장르별 큐레이션 채널이 피드 정체성을 담당.

## 4. 정보 구조 (IA)

```
똑똑 (모바일 웹)
├─ 홈 (/)               ← GNB 1. 카드 게시물 피드 (세로 스크롤, 인스타 포스트형)
│   └─ 게시물 상세 (딥링크 /p/[postId])
├─ 릴스 (/reels)         ← GNB 2. 영상 게시물만 보는 전면 스냅 피드
├─ 알림 (/notifications) ← 홈 상단 오버레이 바의 알림 종에서 진입 (GNB 아님, 로그인 필요)
├─ 채널 (딥링크 /channel/[slug]) ← 홈 카드·탐색 채널 목록의 채널 아바타/항목 탭으로 진입 (GNB 아님, §5.9)
│   └─ 채널 스코프 릴스 뷰어 (/channel/[slug]/reels) ← 그리드의 영상 게시물 탭 시 진입, 카드 게시물은 그대로 게시물 상세로 (§5.9, 결정 기록 §11-58)
├─ 탐색 (/discover)      ← GNB 3. 검색 + 추천 + 장르 칩 + 급상승
├─ 프로필 (/profile)     ← GNB 4. 학습 중 / 보관함 / 완독 / 활동 (로그인 필요)
├─ 뷰어 (/read/[bookId]) ← EPUB 웹뷰어 (풀스크린, GNB 없음)
├─ 로그인 (/login)       ← 소셜로그인 (구글/카카오)
└─ 어드민 (/admin)       ← 관리자 role 전용
    ├─ 도서 관리 (EPUB 업로드, 메타데이터, 구매 링크)
    ├─ 게시물 관리 (카드 조합 작성 / 영상 등록)
    ├─ 채널 관리 (큐레이션 채널 페르소나)
    └─ 신고 처리 (댓글 모더레이션)
```

디자인 톤: **모바일 우선**, 데스크톱에서는 중앙 모바일 프레임 유지. 테마는 라이트가 기본이고 사용자가 다크·시스템을 고를 수 있다 (결정 기록 §11-34).

## 5. 기능 명세

### 5.1 홈 피드

**홈(`/`)은 인스타 포스트형 카드 피드, 릴스(`/reels`)·게시물 상세(`/p/[postId]`)는 전면 오버레이 피드다** (IA 개편 결정 기록 §11-48). 한 게시물은 정확히 한 탭에만 나타난다 — 정렬 RPC(`get_feed_v4`)에 홈은 `type='cards'`, 릴스는 `type='video'`를 넘긴다.

**홈 — 카드 목록** (IA 개편 결정 1·3·4·11)

- 게시물은 **템플릿 카드 한 종류만** (§5.2) — **페이지네이션 없는 한 장**. 템플릿이 정한 영역들이 세로로 쌓인다 (결정 기록 §11-41). 좌우 스와이프도 인디케이터 도트도 없다 — 2026-08-28 개정에서 캐러셀 모델을 버렸다. 영상 게시물은 홈에 나타나지 않는다 — 릴스 전용이다.
- **세로 스크롤 목록** — 릴스와 달리 스냅이 걸리지 않는다. 카드는 한 화면에 하나가 아니라 여러 장이 이어지는 목록이다.
- **카드 한 장의 구조** — 오버레이가 아니라 위에서 아래로 **쌓는다**: 크롬이 컨텐츠를 가리지 않으므로 스크림도 세이프존도 필요 없다.
  1. **채널 헤더** — 아바타 + 채널명. 탭하면 채널 페이지(§5.9).
  2. **본문(가변 높이)** — 템플릿 카드 한 장(§5.2). 세이프존이 아니라 평범한 카드 패딩으로 여백을 준다 — 피할 크롬이 없기 때문이다. 상자는 4:5 같은 고정 비율이 아니라 내용에 맞춰 늘어난다 — 폭 320~480px과 도서명 1~3줄 전 조합을 만족하는 고정 비율이 없었고(좁을수록 자연 높이가 늘고 넓을수록 준다), 넘칠 때 커버가 눌려 찌그러지는 게 겉으로 안 드러나는 문제였다(실측은 DESIGN.md Layout).
  3. **액션 줄** — ♥ 좋아요(카운트) · 💬 댓글(카운트) · ↗ 공유(카운트) · **읽기/도서**. 전면 피드가 채운 원형 아이콘을 쓰는 것과 달리, 홈이 기본 탭이 되며 숏폼→뷰어 전환을 짊어지게 된 이 버튼은 **글자가 붙은 채운 버튼**이다(결정 2). **CTA는 도서 유형에 따라 이원화**(결정 기록 §11-31): 전문 도서는 "읽기" → 뷰어 직행, 링크형 도서는 "도서" → 도서 상세 시트(§5.12).
  4. **도서 바** — 도서 커버 + 카테고리 · 제목 · 저자/역자/출판사, 탭하면 도서 상세 시트(§5.12).
  카드 사이 구분은 여백이 아니라 카드 하단 경계선이 맡는다 — 목록은 **풀블리드**(좌우 패딩 없음)라야 한다. 좌우에 패딩을 주면 카드 폭이 줄어 글이 더 줄바꿈되며 카드가 그만큼 더 길어진다 — 상자가 가변이라 "넘친다"는 아니고 스크롤이 늘어난다는 뜻이다(실측은 DESIGN.md Layout).
- **상단 헤더**(결정 기록 §11-53, 예전엔 오버레이였다 — §11-47)는 목록의 구조적 형제다: 좌측 로고 "똑똑", 우측 알림 종 — 탭하면 알림(/notifications)으로 간다. 안 읽은 알림이 있으면 종 위에 개수 배지 — 전체 안 읽음이 아니라 목록과 같은 최신 50개 창 안에서만 센다(§5.5). 오버레이였을 때는 카드 목록에 전면 피드의 세이프존 같은 회피 장치가 없어 이 바가 위 56px 띠의 탭을 전부 삼켰다 — 카드의 읽기 CTA를 누르면 알림 종이, 채널 헤더를 누르면 바 자신이 잡혔다. 구조적 헤더로의 전환은 원래 다음 단계(결정 8)로 미뤄 뒀었는데, 릴스가 같은 크롬 상수를 공유해 함께 움직여야 한다는 이유였고 입력이 죽는다는 사실을 모른 채 내려진 결정이었다 — 그래서 릴스는 그대로 두고 홈만 먼저 옮겼다. 릴스는 전면 피드라 이 헤더가 없다(결정 8).
- **조회 로깅**: 카드가 뷰포트에 1초 이상 노출되면 조회 1회 기록 (비로그인은 세션 ID 기준, 게시물 단위). 급상승 그리드·인기 가중치의 데이터 소스. **같은 세션이 같은 게시물을 24시간 안에 다시 봐도 세지 않는다**(§11-64) — 그보다 짧으면 한 사람의 재방문이 급상승 순위를 뒤집는다.
- **빈 상태·에러 상태**(결정 기록 §11-55): 카드가 하나도 없으면 "아직 게시물이 없어요.", 첫 페이지를 못 불러왔으면 "피드를 불러오지 못했어요. 잠시 후 다시 시도해 주세요."로 다른 문구를 보여준다 — `getFeed`가 RPC·본문 조회 실패 때도 빈 배열을 돌려주므로 구분하지 않으면 실패가 곧 백지 화면이 된다(알림(§11-47)과 같은 문제, 같은 해법). 다음 페이지가 실패하면(이미 카드가 있는 상태) 화면을 지우지 않고 그 자리에 "다시 시도" 버튼만 보여준다.

**릴스·게시물 상세 — 전면 오버레이 피드**

숏폼 피드의 표준 문법을 따른다.

- **세로 스와이프/스크롤** = 게시물 간 이동 (스냅 스크롤, 한 화면에 게시물 하나)
- 영상 게시물 — 풀스크린 영상 (§5.3). 게시물 상세(`/p/[postId]`)는 카드·영상 두 유형 모두 이 전면 레이아웃으로 연다.
- **공통 UI — 오버레이 계층** (결정 기록 §11-27, 설계 `docs/superpowers/specs/2026-09-01-home-feed-overlay-design.md`):
  - 우측 세로 액션 바: ♥ 좋아요(카운트), 💬 댓글(카운트), ↗ 공유(카운트), **📖 읽기**
    - 뷰어 진입 CTA "읽기"가 이 그룹의 마지막(엄지에 가장 가까운) 자리를 차지한다. 나머지가 고스트 아이콘인 것과 달리 채워진 원형으로 두어 핵심 전환 버튼의 위계를 유지한다.
    - **CTA는 도서 유형에 따라 이원화** (결정 기록 §11-31): 전문 도서 게시물은 "읽기" → 뷰어 직행. 링크형 도서 게시물은 같은 자리에 "도서 보기" → 도서 상세 시트(§5.12).
  - 하단 바 (경계선으로 카드 영역과 분리): **도서 커버 + 카테고리 · 제목 · 저자/역자/출판사**가 본체이고 탭하면 도서 상세 시트(§5.12)로 간다. 채널 아바타는 오른쪽 끝에 두고 탭하면 채널 페이지(§5.9)로 간다 — 목적지가 다르므로 분리하며, 텍스트 링크로 대체하지 않는다(44px 터치 타깃).
  - 컨텐츠는 풀블리드이고 크롬이 그 위에 얹힌다. 크롬은 게시물 유형·테마와 무관하게 흰색 한 벌이며, 하단 검정 스크림 `rgb(0 0 0 / 0.45)` 120px와 글리프 그림자가 가독성을 담당한다. **상단 스크림은 없다** — 홈이 전면 피드이던 시절 흰색 고정 상단 바를 위해 96px가 있었으나, 그 바가 구조적 헤더로 옮겨가며 지킬 대상이 사라져 걷어냈다(§11-57). 카드 본문은 상단 20px·좌우 각 60px·하단 96px 세이프존으로 크롬을 피한다.
- **조회 로깅**: 게시물이 뷰포트에 1초 이상 노출되면 조회 1회 기록 (비로그인은 세션 ID 기준). 급상승 그리드·인기 가중치의 데이터 소스. **같은 세션이 같은 게시물을 24시간 안에 다시 봐도 세지 않는다**(§11-64) — 그보다 짧으면 한 사람의 재방문이 급상승 순위를 뒤집는다.

**피드 정렬 — 가중 랜덤 + 인기**

- 후보: 발행된 게시물 중 **호출한 화면이 요청한 유형**만. 정렬 RPC(`get_feed_v4`)가 유형 인자를 받는다 — 홈은 `type='cards'`, 릴스는 `type='video'`. 인기 가중의 중앙값 기준도 필터 안쪽에서 계산된다 — 영상은 영상들 사이에서, 카드는 카드들 사이에서 평가돼야 한다.
- 점수 = `random() × popularity × freshness × seen_penalty`
  - `popularity` = `1 + min(ln(1 + like_count + view_count×0.1) / 4, 2)` → **[1, 3]**. 상한이 핵심이다. 상한이 없으면 조회 격차가 난수를 압도해 낮은 쪽이 영영 나오지 않는다 (§11-38).
  - `freshness`: 발행 7일 이내 게시물에 ×1.5
  - `seen_penalty`: 세션 내 3일 이내 본 게시물에 ×0.25. 제외가 아니라 **후순위** — 콘텐츠가 적을 때 피드가 비어 버린다.
- 정렬 seed는 **방문(브라우징 세션) 단위로 고정**한다. 쿠키에 심어 요청 사이에 유지한다 — 매 요청 새로 뽑으면 다음 페이지가 첫 페이지와 겹치고, 새로고침마다 순서가 재배열돼 "있던 게시물이 사라진" 것처럼 보인다. 브라우저를 닫으면 새 순서를 뽑는다.
- 페이지네이션은 커서 기반, 요청당 5~10개 프리페치. 커서는 `(정렬점수 문자열, 게시물 id)` 쌍이며 클라이언트는 이를 해석하지 않는다 (결정 기록 §11-37). 점수 문자열에는 **점수의 시간 기준점(as_of)이 함께 실린다** — 한 번의 페이지네이션 동안 점수가 변하지 않아야 하기 때문이다 (결정 기록 §11-59).
- **점수는 페이지네이션 시작 시각에 고정된다.** `freshness`·`seen_penalty`·`view_count`를 전부 그 시각 기준으로 계산해, 1페이지를 보는 행위가 2페이지의 점수를 바꾸지 못하게 한다. 고정하지 않으면 방금 본 게시물의 점수가 4배 떨어져 키셋 커서(`점수 < 커서`) 바로 아래로 굴러떨어지고, 1페이지가 2페이지에 통째로 다시 나온다 (결정 기록 §11-59).
- **모든 발행 게시물은 노출 기회를 갖는다.** 인기 가중에 상한을 두고, 아직 충분히 노출되지 않은 게시물(조회 50 미만)은 인기 페널티를 면제해 중앙값 가중을 준다 — "안 보이니 조회가 안 쌓이고, 조회가 없으니 계속 안 보이는" 고리를 끊기 위함 (결정 기록 §11-38).
- 같은 도서의 게시물이 연속 노출되지 않도록 셔플 후 제약 적용.

### 5.2 템플릿 카드 게시물

**아키텍처 (2026-08-28 개정, 결정 기록 §11-41)**: 게시물 본문은 **페이지네이션 없는 한 장**이고, 템플릿의 단위는 카드가 아니라 **화면 안의 영역(region)**이다. 2단계 구조:

- **게시물 템플릿**(`POST_TEMPLATES`) — 어떤 영역이 어떤 순서로 들어가는지 **고정**한다. 관리자는 순서를 못 바꾼다.
- **영역**(`REGION_REGISTRY`) — UI 유형(variant)을 여러 개 가진다. 관리자가 게시물마다 영역별 유형을 고른다. 예: 장르 영역의 `genre-template-b` = 좌측 정렬 · 20px · 700.

카드 레코드는 게시물당 1행(post_id가 PK)으로 저장된다:

```json
{
  "template": "a",
  "regions": {
    "hook": { "variant": "a", "text": "오늘은 운수가 좋다, 너무 좋다" },
    "desc": { "variant": "a", "text": "행운이 계속될수록 불안해지는 하루." }
  }
}
```

**MVP 게시물 템플릿 (2종)**

| 키 | 이름 | 영역 순서 |
|---|---|---|
| `a` | 문장 중심 | hook → desc |
| `b` | 장르 포함 | genre → hook → desc |

**현재 사용 영역 (3종)** — 이전 cover/biblio 저장값은 읽지 않으며 도서 정보는 하단에서 표시한다.

| 키 | 영역 | 관리자 입력 | UI 유형 |
|---|---|---|---|
| `genre` | 장르 | 없음 | a 캡션 / b 헤드라인(좌측·20px·700) |
| `hook` | 훅 문구 | text, **필수** | a 중앙 강조 / b 좌측 |
| `desc` | 부연 설명 | textarea, 선택 | a 중앙 / b 좌측 |

- **regions에는 영역별 유형·텍스트만 담는다.** 도서에서 오는 값은 `post.book_id` 조인으로 렌더 시점에 읽으므로 복제되지 않는다 — 도서 정보를 고치면 모든 게시물에 즉시 반영된다.
- 렌더 폴백: 알 수 없는 **템플릿**이거나 필수 입력(훅)이 비면 그 게시물만 스킵한다(피드를 죽이지 않는다). 알 수 없는 **유형**은 스킵하지 않고 defaultVariant로 폴백한다 — 유형이 코드에서 사라졌다고 게시물이 통째로 사라지는 것보다 기본 모양이 낫다.
- **인용구·상세정보는 게시물이 아니라 도서의 메타정보다** — 도서 상세 시트(§5.12)의 2·3번째 섹션으로 노출된다. 인용구는 도서 폼에서 입력(`books.quote` / `quote_source`, 도서당 1개), 상세정보는 기존 도서 필드로 자동 구성된다.
- 템플릿·유형 추가는 코드 배포로 이루어진다 (영역 컴포넌트 + 레지스트리 등록 + 이 표 갱신). CMS에서 템플릿을 새로 "디자인"하는 기능은 없음.
- 제외(v2 백로그): 영상 카드 블록, 큐레이션 인터스티셜(AI 추천/SPECIAL CURATION 류)

### 5.3 영상 게시물

- **독립 게시물 유형** (카드 블록이 아님). 피드에서 풀스크린으로 재생.
- 소스 2가지 병행:
  - **영상 묶음 업로드**: 관리자가 원본을 PC에서 변환 → 여러 화질의 ZIP 하나를 Supabase Storage에 직접 업로드 → 미리보기 후 발행. HLS 자동 화질, JPEG 첫 화면, 720 이하 MP4 호환본을 사용하며 **음소거 자동재생 + 루프**를 유지한다. 기존 단일 MP4도 계속 재생한다. [운영 안내](./video-operations.md).
  - **유튜브 임베드**: 유튜브 URL/ID 등록 → IFrame Player API로 뷰포트 연동 재생·루프·음소거를 제어한다. 재생/일시정지는 플레이어 자체 버튼이 맡는다.
- **컨트롤 주체는 유형별로 나누고, 모양은 맞춘다** (2026-09-02 개정). mp4는 우리 컨트롤이 재생/일시정지를 맡고(화면 탭 + 멈춘 동안 가운데 글리프), 유튜브는 **플레이어 자체 버튼**이 맡는다 — 유튜브의 상태 전환 글리프는 끌 파라미터가 없고 가리는 것은 임베드 약관 위반이며, 축소·덮개로 우회하면 정작 그 버튼을 눌러야 할 때 못 누른다. 대신 구성을 같게 한다: 가운데 원형 글리프 + 우측 상단 음소거 버튼. 음소거 버튼은 두 유형이 같은 컴포넌트를 쓴다(`controls=0`에서는 유튜브가 음소거 UI를 주지 않는다). 자동재생은 항상 음소거로 시작하고, 유튜브 쪽 제목 바·"동영상 더보기" 바는 크롭으로 가린다 (설계: `docs/superpowers/specs/2026-09-02-video-controls-design.md`).
- **화면을 덮는 시트가 열리면 재생을 멈추고, 닫히면 재개한다** — 도서 상세·댓글·로그인 시트 전부. 시트 뒤에서 소리가 계속 나고 데이터가 흐르는 것을 막는다. 단, 사용자가 직접 멈춰 둔 영상은 시트를 여닫아도 멈춘 채로 남는다(마지막으로 표현한 의사를 지킨다). 판정은 뷰포트 조건과 같은 자리에서 한 번에 한다 — "화면에 보이고 시트에 덮이지 않았을 때만 재생".
- 영상 게시물에도 도서 연결(`book_id`)과 "바로 읽기" CTA, 소셜 액션 바가 동일하게 붙는다.
- **전환 시 로드 관리** (2026-09-10): 현재 영상 재생을 우선하고 버퍼에 여유가 생긴 뒤 이동 방향의 이웃 한 개만 준비한다. 데이터 절약·느린 연결에서는 미리 읽기를 생략한다. 화면 밖·숨긴 탭의 영상은 정지하고 불필요한 로드는 해제한다. MP4 지연·실패·자동재생 차단에는 안내와 재시도 경로를 제공한다. 단일 고화질 원본의 한계와 후속 화질별 변환 작업은 [조사·적용 기록](./reels-playback-optimization.md)에 구분한다.

### 5.4 전자책 뷰어

- **포맷**: EPUB. 관리자가 파일 업로드 → Supabase Storage (비공개 버킷, signed URL로 서빙).
- **렌더링**: epub.js 기반 웹뷰어.
  - 페이지 넘김(탭/스와이프), 글자 크기 조절, 밝기/테마(다크·라이트·세피아), 목차 이동
  - 진행률 표시 (챕터 x/y + 퍼센트)
- **대상**: 전문 도서(EPUB 보유)만 뷰어를 연다. 챕터 잠금·미리보기 개념 없음 — 열리면 끝까지 읽힌다 (결정 기록 §11-29). 링크형 도서는 뷰어에 진입하지 않는다 — 구매 안내는 도서 상세 시트(§5.12)가 담당.
- **진행률 저장**:
  - 로그인 사용자: 서버 저장 (EPUB CFI + 퍼센트), 기기 간 동기화
  - 게스트: localStorage 저장 + 로그인 시 서버로 병합
- 진행률 100% 도달 시 완독 처리.

### 5.5 소셜 인터랙션 (전부 실동작)

| 기능 | 동작 | 로그인 |
|---|---|---|
| 좋아요 | 토글, 게시물당 1회, 카운트 실시간 반영 | 필요 (미로그인 탭 시 로그인 시트) |
| 댓글 | 작성/삭제(본인), 최신순 목록, 더 보기 페이지네이션, 바텀시트 UI | 필요 |
| 답글(대댓글) | 댓글당 1단 고정. 인라인 확장(접힘 기본, "답글 N개 보기"), 오래된 순 | 필요 |
| 댓글 좋아요 | 댓글·답글 모두 토글. 카운트는 트리거가 관리하고, 상태는 색이 아니라 하트 **채움**으로 구분 | 필요 |
| 공유 | Web Share API(OS 공유시트) + 링크 복사 폴백. 딥링크 `/p/[postId]`, OG 메타 자동 생성. 공유 버튼 탭 시 카운트 +1 | 불필요 |
| 조회수 | 뷰포트 1초 노출 기준 자동 로깅 | 불필요 |
| 알림 | 대상은 **2종뿐**(내 댓글에 달린 답글, 내 댓글에 눌린 좋아요) — 본인 행위는 제외. 좋아요는 댓글별로 **묶고**(같은 댓글에 여러 명이 좋아요 → 한 줄), 답글은 묶지 않고 개별 표시. 목록은 **한 번에 50개**씩 보여주고 "이전 알림 더 보기"로 그 이전을 잇는다(키셋 커서, URL 상태 — `NOTIFICATION_PAGE_SIZE`). 목록에서 항목을 **탭해야** 읽음 처리(진입 시 자동 일괄 처리는 없다. 다만 사용자가 직접 누르는 "모두 읽음" 버튼은 있다 — §11-63), 탭하면 대상 댓글을 시트 최상단에 고정한 채 댓글 시트로 이동(§5.1 알림 종). 안 읽은 수 배지는 **전체 안 읽음**을 세고(§11-63 — 더 보기·모두 읽음이 생겨 51번째 이후도 닿을 수 있게 된 뒤의 값이다), **60초 폴링 + 창 포커스**로 갱신(Realtime 미사용) | 필요 |

**댓글 모더레이션**
- 댓글마다 **신고** 버튼 (사유 선택: 스팸/욕설/기타)
- 어드민 신고 큐: 신고된 댓글 확인 → 삭제 or 기각
- **금칙어 필터**: 등록 시점에 금칙어 포함 여부 검사 → 차단 (금칙어 목록은 어드민에서 관리)
- 삭제된 댓글은 soft delete ("삭제된 댓글입니다" 표시 없이 목록에서 제외). **최상위 댓글을 지우면 그 답글도 함께 숨긴다** — 고아 답글이 남으면 모더레이션이 무의미하고, 자리표시자를 두면 위 규칙과 충돌한다 (§11-43). 삭제된 댓글에는 답글도 달 수 없다("삭제된 댓글에는 답글을 달 수 없어요") — 개별 삭제된 답글도 대상이라 그 루트가 살아 있어도 막힌다 (§11-43)

### 5.6 탐색 (/discover)

레퍼런스 구성을 준용한다:

1. **검색바** (상단): 도서 제목 / 저자 / 채널명 대상. Postgres `ILIKE` + trigram 유사도 수준 (풀텍스트 인프라 없음). 결과는 도서·채널 섹션으로 구분 표시, 도서 결과 탭 시 도서 상세 시트(§5.12).
2. **오늘의 추천**: 관리자가 어드민에서 지정한 추천 도서 배너 (수동 큐레이션, 3~5개 로테이션)
3. **관심 분야 칩**: 장르 카테고리 (경제경영/자기계발/소설/인문/에세이/과학…) → 탭 시 해당 장르 게시물 그리드
4. **급상승 그리드**: 최근 7일 조회수 상위 게시물 썸네일 그리드 (조회수 오버레이 표시). 탭 시 게시물 상세(`/p/[postId]`)로 진입 — 릴스 개편으로 피드가 홈 카드/릴스 영상 둘로 갈려 "피드로 진입"이 가리킬 대상이 모호해졌고, 가중 랜덤·세션 시드·키셋 커서로 도는 피드를 임의 게시물 위치에 맞추는 것은 상당한 작업이라 상세로 보낸다(설계 결정 10, 결정 기록 §11-58).

### 5.7 프로필 (/profile) — 기록 + 활동

- 비로그인 접근 시 로그인 유도 화면.
- 상단 요약: 닉네임/아바타(소셜 계정 기반), **완독 도서 수**, 읽는 중 도서 수
- 탭 구성:
  - **학습 중**: 진행률 있는 도서 목록 (커버 + "챕터 x/y" 진행 바) → 탭 시 이어읽기
  - **보관함**: 찜한 도서 (도서 상세 시트의 찜 버튼으로 추가) → 탭 시 도서 상세 시트(§5.12)
  - **완독**: 완독 도서 목록
  - 학습 중·완독은 전문 도서만 대상 — 링크형 도서는 진행률·완독이 없다 (찜만 가능).
  - **활동**: 세그먼트 토글 2개 — 좋아요한 게시물(도서 커버 3열 그리드, 탭 시 해당 **게시물**로 이동)과 내가 쓴 댓글·답글(최신순 목록, 탭 시 해당 게시물로 이동). 각 50개까지.
- 제외(v2): 포인트, 레벨/칭호, 연속 학습 스트릭, 지식 성좌

### 5.8 인증

- **게스트 우선**: 피드·탐색·뷰어(게스트 진행률은 로컬)는 비로그인으로 전부 사용 가능
- **로그인 트리거**: 좋아요/댓글/찜/프로필 진입 시 로그인 바텀시트
- **수단**: 소셜로그인만 — **구글, 카카오** (Supabase Auth OAuth). 이메일 가입 없음.
- 최초 로그인 시 `profiles` 레코드 생성 (닉네임 = 소셜 프로필명, 수정 가능)

### 5.9 채널 (큐레이션 페르소나)

- 관리자가 운영하는 **장르별 채널 3~5개** (예: 돈이 되는 서재(경제경영), 밤의 문장들(소설/에세이), 생각의 근육(인문)…)
- 채널 = 이름 + 아바타 + **커버 이미지** + 장르 + 소개. 모든 게시물은 채널 명의로 발행. 커버는 어드민이 URL로 넣고(아바타와 같은 방식) 없으면 화면이 아바타 블러 → 단색으로 폴백한다.
- 피드/게시물에서 채널 아바타 탭 시 **채널 홈** — 위에서 아래로 (1) 커버 히어로: 커버 사진 위에 뒤로가기, 아바타, 채널명, 장르 칩 + 게시물 수(발행 전체의 정확한 수), 소개 2줄, 두 칸 액션 바 "영상 이어보기(영상 0건이면 숨김) | 채널 공유", (2) 발행 게시물의 **정방형 3열 타일 모자이크** — 카드는 저장된 배경 + 훅 문구 3줄, 영상은 포스터(업로드)·유튜브 썸네일 + 재생 글리프. 그리드에 조회수는 없다(2026-09-11, 결정 기록 §11-68, 설계 `docs/superpowers/specs/2026-09-11-channel-home-redesign-design.md`).
- **채널 그리드 항목의 목적지는 게시물 유형에 따라 갈린다**: 카드 게시물은 지금처럼 게시물 상세(`/p/[postId]`)로 가고, 영상 게시물은 채널 스코프 릴스 뷰어(`/channel/[slug]/reels?start=<postId>`)로 간다 — 그 채널의 영상만 발행 역순으로 이어 보며, 탭한 게시물에서 시작한다(설계 결정 7, 결정 기록 §11-58).
- **채널 스코프 릴스 뷰어는 영상 30개로 자른다**: 페이지네이션이 없어 한 채널의 영상이 30개를 넘으면 그 뒤는 뷰어에 아예 보이지 않는다 — `/reels`처럼 끝에 다가가면 다음 페이지를 미리 받는 동작이 없다(결정 기록 §11-58). 채널당 영상이 그만큼 쌓이면 그때 페이지네이션을 붙인다.
- **채널별 콘텐츠 제약**: 소설·에세이 채널은 전문 도서 중심, 경제경영·자기계발 채널은 링크형 도서 전용으로 설계한다 — 해당 장르에 만료 저작물이 없다 (§5.11).
- 팔로우 기능은 v2.

### 5.10 어드민 CMS (/admin)

- **접근**: Supabase Auth 계정 중 `role = admin`인 계정만. 미들웨어에서 라우트 보호.
- **도서 관리**:
  - **3D 표지 제작**: 신규 등록과 기존 도서 수정에서 제목·저자를 가져와 기본 책 모델에 적용한다. 클래식·모던·문학 템플릿, 숲·밤·와인 팔레트, 좌우 회전(-180~180°)·위아래 기울기(-90~90°)·두께(10~50mm)를 고를 수 있다. 마우스·터치 드래그 또는 방향키로 360° 돌려 앞뒤 표지·책등·종이를 확인하며, 선택한 각도로 이미지를 만든다. 둥근 양장판과 따뜻한 종이, 은은한 광택은 Complete Shelf의 공개 구현을 참고한다. 「이미지로 적용」은 로컬 미리보기만 바꾸고 도서 「저장」에서 800×1200 투명 PNG와 재편집 설정을 함께 저장한다. 미적용 편집 중 저장, 새 이미지 적용 후 제목·저자 변경은 재적용 안내로 막는다. 일반 이미지 업로드는 기존 방식으로 가능하며 직접 교체하면 3D 설정을 비운다. 생성 도구는 열 때만 불러오고 독자 화면은 이미지만 읽는다. 표지는 PNG/JPEG/WebP 최대 2MB, 관리자 서버 제출 한도는 파일·기타 필드 합계 4MB다. 긴 문구는 표지에서 자동 줄바꿈·축소한다(제목 120자, 저자 80자 이내).
  - 도서 등록/수정: 메타데이터(제목, 저자, 옮긴이, 출판사, 커버, 카테고리, ISBN, 페이지, 출간일, 소개, 목차) 직접 입력 + 관리 정보(수급 출처, 권리 근거), EPUB 파일 업로드(전문 도서 — 없으면 링크형), 구매 링크(링크형: 자동 생성 미리보기 + 수동 덮어쓰기 필드)
  - **위키문헌 목록에서 고르기** (`/admin/books/wikisource`): 가져올 수 있는 작품이 표로 먼저 보이고, 행의 「가져오기」를 누르면 저자·분류 입력 없이 등록된다. 표에는 작품명·저자·장르·출간 연도가 있고 검색·필터·정렬·페이지가 된다. 목록의 범위는 **소설 계열과 시집**이다(실측 **293편**, 2026-09-09) — 위키문헌 분류를 긁어 모으고(365편), 장으로 쪼개진 문서(`하위 문서` — 상위 문서를 지정해야 ws-export가 장을 따라간다)·친일문학·저작권 만료 태그(`PD-old-*`)가 없는 문서·저자를 못 읽은 문서는 애초에 표에 담지 않는다. 여기에 더해 **저자 문서의 사망 연도·국적을 직접 읽어 §5.11(1962년 이전 사망)을 그대로 적용한다** — 해외 저자·북한 저자·사망 연도 불명·1962년 이후 사망·저자 문서 없음이 이 단계에서 걸린다(결정 기록 §11-65). `PD-old-*` 태그는 후보를 모으는 그물일 뿐 이 판정을 대신하지 않는다. 그래도 등록 금지 저작자(§5.11, 손으로 쓴 명단)의 작품은 **표에는 남기고 목록 화면에서만 가린다** — 저자 문서 기준만으로는 명단을 대체할 수 없다(실측: 「저자:정지용」은 1950년 사망·북한 분류 없음으로 기계 검사를 통과하지만 명단이 막는다). 번역물도 같은 이유로 `translator` 컬럼과 화면 숨김을 남겨 두지만, 원저자가 외국인인 경우가 대부분이라 대개 저자 검사 단계에서 먼저 걸러져 지금 표에는 번역물이 0건이다 — 지우면 "왜 이 작품이 목록에 없나"에 답할 수 없으므로 유지한다. 후보는 `wikisource_works` 표에 담고 화면은 그 표만 읽는다(위키문헌 API를 직접 부르지 않는다) — `npm run wikisource:sync -- --dry-run`으로 확인한 뒤 `npm run wikisource:sync`로 갱신한다. 위키문헌 레이트 리밋이 세서(2초 간격에서도 걸린다) 화면이 매번 API를 부르게 둘 수 없다. **목록에 없는 작품은 주소 입력 화면(아래)으로 가져온다** — 위키문헌에 장르 분류가 없는 작품(「홍염」), 수필·시 낱편, PD 태그 없는 문서, 저자를 알 수 없는 문서(「모비딕」)가 그렇다 — 그 화면에서 사람이 저자를 입력하면 금지 명단 검사가 그 입력에 걸린다 (결정 기록 §11-65). **판정 근거는 행에 남기고 화면이 렌더할 때마다 다시 확인한다** — 기준(1962년·장르 범위·태그 조건)을 바꿔 배포하면 화면이 낡은 승인으로 「가져오기」를 계속 내놓기 때문이다. 검증값이 없거나 지금 기준과 어긋나는 행은 사유와 함께 「동기화 필요」로 보이고 가져올 수 없다 — 동기화를 다시 돌리면 풀린다 (결정 기록 §11-66).
  - **위키문헌 임포트** (`/admin/books/import`): 문서 주소(또는 제목)·저자·카테고리만 받아 EPUB을 수급·정리해 올리고 도서 행을 **바로 만든 뒤** 수정 화면으로 보낸다. 자동으로 채우는 값은 제목(`dc:title`)·본문·수급 출처뿐이다 — 저자는 ws-export가 `dc:creator`를 넣지 않아 원천이 없고, 소개·인용구·목차·권리 근거는 편집·법적 판단이라 기계가 채우지 않는다 (결정 기록 §11-49). 등록 금지 저작자(§5.11)는 임포트 시점에 거부한다. 소개나 권리 근거가 빈 도서는 목록에 `미완성` 배지로 표시된다.
- **게시물 관리**:
  - 카드 게시물 작성: 채널 선택 → 도서 선택 → 게시물 템플릿 선택 → 영역별 UI 유형 선택 + 훅·부연 문구 입력 → 발행/임시저장. 영역 구성·순서는 템플릿이 고정한다(§5.2) — 순서 조정 UI가 없다. 영역 값은 영역 키로 저장되어 템플릿을 바꿔도 입력이 살아남는다
  - **실시간 미리보기**: 작성 화면 우측에 480×812 프레임을 두고 입력·템플릿·순서를 즉시 반영한다. 프레임 폭 480px은 홈 카드가 실제로 받는 폭이다 — 카드는 풀블리드라 `(main)` 프레임 상한(`--container-frame`)을 그대로 받고, 어드민은 보통 그 상한보다 넓은 데스크톱 화면에서 쓴다. 미리보기는 사용자 화면과 **같은 컴포넌트를 그대로 쓴다** — 카드 게시물은 홈과 같은 `PostCard`, 영상 게시물은 릴스·게시물 상세와 같은 `PostItem`(닮게 그리면 언젠가 한쪽만 고쳐진다 — 결정 기록 §11-56). 프레임은 조작할 수 없다(inert): 미리보기에서 누른 좋아요·공유가 실제 집계에 섞여선 안 된다. 필수 입력(훅)이 빈 화면은 점선 자리표시로 그려 무엇을 채워야 하는지 알린다 (결정 기록 §11-40)
  - 영상 게시물 작성: 채널/도서 선택 → 변환 ZIP 업로드·자동/개별 화질 미리보기 또는 유튜브 URL → 발행
  - 발행일은 **처음 발행하는 순간에만** 기록한다. 수정할 때마다 갱신하면 오래된 글이 방금 쓴 글이 되어 피드 신선도 가중(§5.1)과 채널 정렬이 통째로 흔들린다.
  - 목록: 상태(발행/임시), 발행일(임시는 작성일), 조회·좋아요·댓글 수 확인, 수정/삭제. 각 행에 게시물 id와 사용자 화면(`/p/{id}`) 링크를 둔다 — 발행이 실제로 나갔는지 관리자가 바로 확인할 수 있어야 한다
  - 중복: 한 도서에 게시물이 여러 개인 건 막지 않는다(피드가 이를 전제로 설계됐다 — §5.1 흩뿌리기). 도서를 고르면 기존 게시물 수를 경고로 보여줄 뿐이다 (결정 기록 §11-36)
- **채널 관리**: 채널 CRUD
- **탐색 큐레이션**: "오늘의 추천" 도서 지정
- **모더레이션**: 신고 큐 (신고 사유·댓글 원문 확인 → 삭제/기각), 금칙어 목록 관리
- UI는 기능 우선의 심플한 관리 화면 (디자인 투자 최소화). WYSIWYG·비주얼 에디터 없음 — 폼 기반 데이터 입력.
- **삭제 확인**: 되돌릴 수 없는 삭제(도서·게시물·채널·댓글·금칙어)는 버튼 바로 위에 뜨는 확인 팝오버를 거친다. 무엇을 지우는지가 이미 그 줄에 적혀 있으므로 화면을 덮는 모달은 쓰지 않는다.
- **알림**: 성공은 3초 토스트로 띄우고 주소의 결과 쿼리를 지운다 — 남겨 두면 새로고침할 때마다 다시 뜬다. 오류는 관리자가 고칠 때까지 읽혀야 하므로 배너로 남긴다 (결정 기록 §11-39).
- **테마**: 라이트 고정 — 어드민에는 테마 전환 UI가 없다. 서비스 쪽 선택값은 그대로 보존되어, 어드민을 나가면 사용자가 고른 테마로 돌아온다 (결정 기록 §11-35).

### 5.11 콘텐츠 수급

**원칙**: API로 수급 가능하면 API(위키문헌), 아니면 수동. 수급 후에는 메타·본문·관리 정보(수급 출처·권리 근거)를 전부 자체 DB/Storage에 보관한다 — 열람 경로는 외부 콘텐츠에 의존하지 않는다 (예외: 영상 게시물의 유튜브 임베드 §5.3). 도서 메타는 관리자 직접 입력 — 알라딘 TTB 프리필은 v2 백로그.

**만료 판별 규칙 (한국 저작권법)**

2013-07-01 개정으로 보호기간이 사후 50년 → 70년이 되었으나, 시행 전 이미 만료된 저작물에는 소급 적용되지 않는다.

| 저작자 사망 | 적용 | 상태 |
|---|---|---|
| ~1962-12-31 | 구법 사후 50년 | **만료 — 전문 공개 가능** |
| 1963-01-01~ | 사후 70년 | 존속. 최초 만료는 2033년 말 |

→ **전문 공개 가능한 콘텐츠 풀은 2033년까지 고정된다.** 1962년 이전 사망 저작자 명단이 곧 등록 가능 목록의 전체다. 신규 유입을 기대할 수 없으므로 수급 계획은 이 고정 풀을 전제로 세운다.

**번역 저작권 — 등록 전 필수 확인**

원저작물이 만료여도 **한국어 번역본은 번역자의 저작권이 별도로 존속**한다. 해외 고전(도스토옙스키·헤세 등)은 전문 공개할 수 없다 — 링크형 도서로만 취급.

**등록 금지 목록**

- 월북·납북 작가(정지용·이태준·박태원·홍명희·김기림) — 사망 연도 불확실 또는 북한에서 1963년 이후 사망
- 근대 작가로 오인하기 쉬운 존속 저작권 — 백석(1996), 박경리(2008)

**소스**

| 소스 | 확보 방식 | 포맷 |
|---|---|---|
| 공유마당 어문 `gongu.copyright.or.kr` | 수동 다운로드 (다운로드 시 설문 응답 요구, 저작물 조회 API 없음) | PDF / HWP / TXT, 일부 EPUB |
| 한국 위키문헌 `ko.wikisource.org` | MediaWiki API + `ws-export.wmcloud.org` — 자동화 가능한 유일 경로 | EPUB 직접 생성 |
| 링크형 도서(인기도서) | 본문 수급 없음 — 메타·커버만 관리자 입력 | — |

EPUB이 아닌 원본은 변환 후 어드민 업로드 (변환 스크립트는 `scripts/`).

**위키문헌 EPUB의 정리와 라이선스 표시**

ws-export는 FreeSerif 4종(약 7.7MB)을 항상 임베드하고, 위키문헌 자신의 껍데기(로고가 박힌 표지 페이지, 기여자 목록 "About this digital edition", 본문 끝 「라이선스」 상자)를 함께 넣는다. 우리 판본의 첫 화면이 남의 로고일 수는 없고 폰트는 쓰이지도 않으므로(뷰어가 자체 CSS를 물린다) 받아온 뒤 걷어낸다 — `src/lib/wikisource.ts`.

다만 `content.opf`의 `dc:rights`와 `dc:contributor`는 **남긴다.** 파일에 들어 있는 문자열 그대로는 `Creative Commons BY-SA 3.0` · `GNU Free Documentation License` · `Wikisource`다. 원문 자체는 만료 저작물이고 이 표기는 위키문헌 기여자의 편집·주석에 붙는 것이다. 화면에 보이지 않는 출처 기록이므로, 지우는 것은 표시 정리가 아니라 권리 표시를 떼는 별개의 판단이 된다 (결정 기록 §11-50).

정규식으로 XML을 다루는 처리라 위키문헌이 마크업을 바꾸면 조용히 헛돈다. 그래서 ① 업로드 직전 관문(`assertClean`)이 껍데기가 남았는지 확인하고 ② `src/lib/wikisource.test.ts`가 조립한 픽스처로 회귀를 잡는다.

본문 앞머리의 **안내문(hatnote)도 걷어낸다.** 위키문헌은 동음이의 안내를 본문 맨 앞에 붙이는데, 「탈출기」는 "성경의 책에 대해서는 출애굽기 문서를 참조하십시오."로 시작한다 — 독자가 펼친 첫 문장이 남의 사이트 내비게이션일 수는 없다.

그리고 **ws-export가 본문 없는 껍데기를 내주는 때가 있다.** 「감자」(원문 6,516자)가 본문 2자짜리 EPUB으로 나왔고 「백치 아다다」·「자유종」도 같았다. HTTP 200에 EPUB 형식도 맞고 챕터 파일도 하나 있어서, 글자수를 세지 않으면 빈 책이 그대로 등록된다. 그래서 `assertClean`이 본문 글자수를 세어 500자 미만이면 막는다 — 실측 간격이 넓어 경계는 넉넉하다(껍데기 2~50자, 가장 짧은 실제 작품 7,000자, 시 한 편짜리 문서도 약 1,000자로 통과).

이 정리가 바뀌면 **이미 올라간 파일은 옛 상태로 남는다** (`seed.mjs`는 스토리지에 파일이 있으면 재사용한다). `npm run epubs:refresh`가 `source='wikisource'`인 도서를 전부 다시 받아 교체한다 — 위키문헌 문서 제목은 `books.source_ref`에서 읽고, 업로드 직전에 `assertClean`으로 껍데기가 실제로 없는지 검사하며, 실패한 책은 건너뛰고 나머지를 계속한다.

**표지 — 자체 제작**

만료작에는 "원래 표지"가 없다. 시중 판본의 표지는 그 출판사의 저작물이고 우리 판본의 표지도 아니므로 가져다 쓸 수 없다. 우리 판본의 표지는 우리가 만든다 (`npm run covers`, 결정 기록 §11-28).

- 생성물은 `covers` 공개 버킷에 `{book.id}.png`로 올라가고 `books.cover_url`에 반영된다. 재실행하면 덮어쓴다.
- **컬럼이 담는 것이 경로냐 URL이냐가 갈린다**: `books.epub_path`는 순수 경로(비공개 버킷이라 URL이 없다), `books.cover_url`과 `post_videos.video_path`는 `getPublicUrl()`이 만든 공개 URL이다. 스토리지 API는 경로만 받으므로 지울 때는 URL을 되돌려야 한다 — `src/lib/storage-path.ts`가 그 변환을 한 곳에서 담당한다.
- 제목 해시로 팔레트를 고정해 같은 책은 늘 같은 색이다. DESIGN.md가 "색은 도서 커버가 낸다"고 규정하므로, 무채색 UI에서 **표지만 유채색**이다.
- 링크형 도서는 소개하는 시중 판본의 표지를 도서 식별 목적으로 사용한다 (구매 유도 맥락의 관행적 사용) — 관리자가 업로드.
- 표지가 없는 도서는 `BookCover`의 타이포그래피 폴백으로 렌더된다 — 임시방편이 아니라 상시 경로다.

**권리 비대칭 — 설계 전제**

| 권리 | 대상 | 규모·장르 |
|---|---|---|
| 전문 공개 가능 | 한국 근대문학 만료작 | 소수 정예. 소설·시·수필에 편중 |
| 링크형만 가능 | 그 외 전부 | 콘텐츠 대다수 |

둘은 대등한 갈래가 아니다. 경제경영·자기계발 장르는 전문 공개 가능 도서가 0건이며, 채널 구성이 이 제약을 받는다 (§5.9).

**링크형 도서의 인용 규칙**

링크형 도서는 본문을 싣지 않는다. 카드의 훅·인용구는 짧은 인용 수준(문장 단위)을 지키고 출처(도서·페이지)를 표기한다. 출판사·저작권자가 게시 중단을 요청하면 해당 도서·게시물을 즉시 비공개 처리한다.

**Phase 1 시딩 원칙 — 단편 우선**

근대 **단편**(「운수 좋은 날」·「메밀꽃 필 무렵」·「봄봄」·「날개」 등)으로 시딩한다. 30분 내 완독이 가능해 발견 → 읽기 → 완독이 한 세션에 닫히고, 완독률(§2 보조 지표)이 출시 직후부터 측정된다. 장편 위주로 시딩하면 완독 데이터가 수개월간 비어 있다.

### 5.12 도서 상세 시트

도서의 정식 상세 화면. 별도 페이지 없이 **바텀시트 하나로 통일**한다 (결정 기록 §11-30).

- **진입점** (전부 같은 시트): 피드 하단 바의 도서 정보 탭 · 링크형 도서 게시물의 "도서 보기" CTA · 탐색 검색 결과 도서 탭 · 프로필 보관함 항목 탭
- **내용 (3단, §11-41)**: 헤더(커버·제목·저자/역자·출판사·카테고리) 아래 ① 소개 → ② **인용구**(`books.quote`, 없으면 생략 — 출처가 없으면 "제목 · 저자"로 표기) → ③ **상세 정보**(출판사·페이지·출간일·ISBN·목차) · 찜 버튼
- **하단 액션 (도서 유형별)**:
  - 전문 도서: **"바로 읽기"** → 뷰어(§5.4)
  - 링크형 도서: 외부 서점 구매 버튼 **교보문고 / 예스24 / 알라딘** — 도서 ISBN으로 각 서점 검색 URL **자동 생성**, 관리자가 도서별 개별 URL **수동 덮어쓰기** 가능 (`purchase_links`)
- 시트는 딥링크가 없다 — 공유는 게시물 딥링크(`/p/[postId]`)로만.

**RLS 원칙**
- 읽기: `posts(published)`·`post_cards`·`books`(메타)·`channels` 등은 공개 read
- 쓰기: `likes`/`comments`/`comment_likes`/`bookmarks`/`reading_progress`는 본인 행만, `reports`는 로그인 사용자 insert만
- `comments`의 UPDATE는 RLS 위에 **컬럼 GRANT로도** 좁혀져 있다 — 테이블 단위 UPDATE를 revoke하고 `deleted_at`만 재부여했으므로(20260903000001), RLS를 통과하는 요청이라도 `deleted_at` 외 컬럼은 기본적으로 막힌다. 새로 컬럼을 추가해도 grant 목록에 넣기 전까지는 UPDATE가 열리지 않는다 — RLS 정책만 보고 "된다"고 판단하지 말 것 (§11-45)
- `notifications`는 받은 사람만 select·update할 수 있고, **insert 정책이 없다** — 행은 `notify_on_reply`/`notify_on_comment_like` 두 security definer 트리거만 만든다(20260903000002). `comments`와 같은 패턴으로 UPDATE도 컬럼 GRANT로 더 좁혀서 `read_at`만 재부여했다 — RLS를 통과해도 `type`·`comment_id` 같은 다른 컬럼은 클라이언트가 못 바꾼다(§11-45와 동일 근거, §11-47)
- 어드민 쓰기(`books`, `posts`, `channels` 등)는 `role='admin'` 체크 (service role or RLS policy)
- EPUB 파일: private bucket + 서버에서 signed URL 발급 (전문 도서 전용 — 챕터 잠금 없음)

## 7. 비기능 요구사항

- **성능**: 피드 스크롤 60fps 목표 — 게시물 가상화(앞뒤 2~3개만 마운트), 이미지 next/image 최적화, 영상 지연 로드·뷰포트 이탈 시 정지
- **반응형**: 360px~ 모바일 최적화, 태블릿/데스크톱은 중앙 모바일 프레임(max-width ~480px)
- **SEO/공유**: 게시물 딥링크에 OG 태그 (도서 커버/제목/훅 문구) — 공유 유입의 랜딩 품질
- **접근성**: 자동재생 영상 기본 음소거, 대체 텍스트, 키보드 페이지 넘김(뷰어)
- **분석 이벤트**(최소): `post_view`, `reader_open`(핵심 전환 — 전문 도서 전용), `reader_progress`, `book_complete`, `like`, `comment`, `share`, `book_sheet_open`(도서 상세 시트), `purchase_link_click` — Supabase 테이블 or 경량 애널리틱스로 수집. 링크형 깔때기는 post_view → book_sheet_open → purchase_link_click으로 별도 집계 (결정 기록 §11-32).
- **저작권 운영 원칙**: 본문 열람은 전문 도서(저작자 **1962년 이전 사망** 만료작 또는 권리 확보분)만. **한국어 번역본은 번역자 저작권이 별도 존속하므로 해외 고전은 전문 공개 불가.** 링크형 도서는 본문을 싣지 않는다 — 카드의 짧은 인용(출처 표기)과 메타·커버만. 판별 규칙·인용 규칙·등록 금지 목록은 §5.11.

### 8.1 shadcn/ui 사용 전략

**왜 shadcn/ui인가**
- 컴포넌트가 `node_modules`가 아니라 **프로젝트 코드로 복사**된다 → 숏폼 피드처럼 비표준 UI를 만들 때 라이브러리와 싸우지 않고 직접 고칠 수 있다.
- Radix UI 프리미티브 기반이라 **접근성(포커스 트랩, 키보드 내비, ARIA)이 기본 제공** → 바텀시트·다이얼로그를 직접 만들 때 생기는 a11y 부채를 피한다.
- Tailwind 토큰과 CSS 변수로 테마가 구성되어 **테마 전환**과 궁합이 좋다 — 컴포넌트를 건드리지 않고 `:root`·`.dark` 변수 블록만으로 끝난다.

**초기 설치 컴포넌트**

| 컴포넌트 | 사용처 |
|---|---|
| `drawer` (Vaul) | 댓글 시트, 도서 상세("더보기"), 로그인 시트 — 모바일 바텀시트의 핵심 |
| `dialog` | 어드민 확인 모달, 신고 사유 선택 |
| `button`, `input`, `textarea`, `label`, `form` | 어드민 CMS 폼 전반, 댓글 입력 |
| `select`, `checkbox`, `switch` | 어드민(템플릿 카테고리 선택, 발행 상태, 접근 유형) |
| `avatar` | 채널 아바타, 프로필 |
| `badge` | 장르 칩, 상태 뱃지(발행/임시) |
| `tabs` | 프로필(학습 중/보관함/완독/활동), 어드민 섹션 |
| `sonner` (toast) | 좋아요·찜·복사 완료 피드백 |
| `skeleton` | 피드·그리드 로딩 상태 (CLS 방지) |
| `table` | 어드민 도서/게시물/신고 목록 |
| `progress` | 뷰어 진행률, 프로필 챕터 진행 바 |
| `scroll-area` | 목차 리스트, 긴 댓글 목록 |

**shadcn을 쓰지 않는 영역** — 다음은 라이브러리 없이 직접 구현한다. 숏폼 특유의 제스처·성능 요구가 기성 컴포넌트와 맞지 않는다.
- 홈 피드의 세로 스냅 스크롤 (CSS Scroll Snap + IntersectionObserver)
- 카드 좌우 스와이프 캐러셀 (터치 제스처 직접 처리 — `embla-carousel` 검토 가능)
- 우측 세로 액션 바 오버레이
- EPUB 뷰어 셸 (epub.js가 iframe을 직접 제어)

**테마 토큰** — `globals.css`의 CSS 변수로 다크 팔레트를 정의하고, 컴포넌트에서는 시맨틱 토큰(`bg-background`, `text-muted-foreground`)만 사용한다. 원시 hex 값을 컴포넌트에 직접 쓰지 않는다.

### 영상 전송 개선 — 2026-09-11 확정

관리자는 PC 변환 도구에서 원본 하나를 여러 화질의 ZIP 묶음으로 만든 뒤 업로드한다. 해상도별 개별 업로드, 유료 영상 SaaS, 서버 변환 작업은 도입하지 않는다. 퍼가기 방어는 보류한다. 사용자 재생은 HLS 자동 화질과 제한된 이웃 준비를 사용하며 기존 단일 MP4와 YouTube는 유지한다. 새 영상은 JPEG 미리보기와 720 이하 MP4 호환본을 포함한다.

데이터 모델 추가: post_videos.hls_path·poster_path(text), renditions(jsonb), asset_group_id(uuid FK). video_path는 호환 재생 주소로 유지한다. video_uploads는 id·created_by·created_at·status(uploading/ready/deleting)·manifest·public_base를 보관한다. 관리자만 읽고 서버만 준비 완료를 기록한다. save_video_post RPC가 게시물과 영상 상세를 함께 저장해 실패 시 모두 되돌린다. 기존 조회 수·도서 연결·최초 발행일을 보존한다.

파일별 진행률·중단·실패한 파일 재시도·자동 및 개별 화질 미리보기·미사용 묶음 정리를 제공한다. 사용 중인 묶음 삭제와 삭제 중인 묶음 연결은 DB 잠금으로 막는다. 운영 적용 순서는 DB 추가 마이그레이션 → 두 앱 배포 → 샘플 확인 → 기존 영상 순차 교체다. [현행 운영 안내](./video-operations.md).
