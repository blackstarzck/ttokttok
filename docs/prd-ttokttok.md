# PRD — 똑똑 (Ttokttok)

> **"지식이 똑똑 노크해요."**
> 숏폼 피드로 책을 발견하고, 그 자리에서 바로 읽기 시작하는 모바일 웹 서비스

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 (2026-08-27) |
| 상태 | 확정 — 인터뷰(grill 세션) 기반 합의 완료 |
| 프로젝트 성격 | 개인 사이드 프로젝트 |
| 대상 독자 | 구현 담당(본인 + Claude Code) — 실행용 스펙 |

---

## 1. Executive Summary

**똑똑**은 인스타그램 릴스/유튜브 쇼츠의 소비 문법으로 책을 발견하게 하는 전자책 플랫폼이다. 세로 스크롤 피드에 도서 소개 카드 게시물과 짧은 영상 게시물이 흐르고, 관심이 생기면 그 자리에서 EPUB 뷰어가 열려 바로 읽기 시작한다.

- **핵심 루프**: 피드에서 발견 → 뷰어에서 읽기 → 진행률/보관함으로 재방문 → 다시 피드
- **북극성 지표**: 콘텐츠 조회 → 뷰어 진입 **전환율**, 1인당 **열람 시간**
- **MVP 원칙**: 콘텐츠 공급은 관리자 단독(장르별 큐레이션 채널 페르소나). 사용자는 소비 + 소셜 인터랙션(좋아요·댓글·공유 전부 실동작)만.
- **콘텐츠 수급**: 퍼블릭 도메인 도서(전문) + 출판사 공개 샘플(1챕터 미리보기)을 관리자가 EPUB으로 업로드. 미리보기 종료 시 외부 서점 구매 링크(ISBN 자동생성)로 연결.
- **플랫폼/스택**: 모바일 우선 반응형 웹. Next.js + Vercel + Supabase + epub.js.

### 비목표 (MVP에서 하지 않는 것)
- 사용자 콘텐츠 게시(UGC) — 업로드는 관리자만
- 결제/구독 — 수익화 없음, 구매는 외부 서점 링크로만
- 포인트·레벨·지식 성좌 등 보상형 게이미피케이션 (기록형만 제공)
- 추천 개인화(ML) — 가중 랜덤 + 인기 가중치까지만
- 네이티브 앱 / PWA 푸시
- 다국어 — 한국어 단일

## 2. 배경과 문제 정의

- 독서 앱(밀리의 서재 등)은 "읽으려는 사람"을 위한 도구다. "읽을 생각이 없던 사람"을 책으로 끌어들이는 접점이 없다.
- 반면 숏폼(릴스/쇼츠)은 의도 없이 열어도 소비가 시작되는 포맷이지만, 그 발견이 독서로 이어지는 경로가 끊겨 있다 (책 소개 릴스를 봐도 → 서점 검색 → 구매 → 앱 설치… 마찰이 크다).
- **똑똑은 발견과 독서 사이의 마찰을 0으로 만든다**: 카드에서 흥미 → 탭 한 번 → 뷰어에서 첫 장이 열린다.

### 성공 지표
| 지표 | 정의 | MVP 목표 성격 |
|---|---|---|
| 뷰어 전환율 | 게시물 조회 대비 뷰어 진입 비율 | 핵심(북극성) |
| 열람 시간 | 뷰어 체류 시간 / 사용자 | 핵심 |
| 완독·챕터 완료율 | 진행률 이벤트 기반 | 보조 |
| 재방문율 | 7일 내 재방문 | 보조 |
| 좋아요·공유 수 | 소셜 인터랙션 | 보조 |

---

## 3. 타깃 사용자

- **주 타깃**: 틈새 시간에 스마트폰으로 숏폼을 소비하는 20~40대. 독서 의향은 있으나 실행이 안 되는 층.
- **장르**: 전 장르 (경제경영·자기계발·소설·인문·에세이·과학 등). 장르별 큐레이션 채널이 피드 정체성을 담당.

## 4. 정보 구조 (IA)

```
똑똑 (모바일 웹)
├─ 홈 (/)               ← GNB 1. 세로 스크롤 숏폼 피드
│   └─ 게시물 상세 (딥링크 /p/[postId])
├─ 탐색 (/discover)      ← GNB 2. 검색 + 추천 + 장르 칩 + 급상승
├─ 프로필 (/profile)     ← GNB 3. 학습 중 / 보관함 / 완독 (로그인 필요)
├─ 뷰어 (/read/[bookId]) ← EPUB 웹뷰어 (풀스크린, GNB 없음)
├─ 로그인 (/login)       ← 소셜로그인 (구글/카카오)
└─ 어드민 (/admin)       ← 관리자 role 전용
    ├─ 도서 관리 (EPUB 업로드, 메타데이터, 구매 링크)
    ├─ 게시물 관리 (카드 조합 작성 / 영상 등록)
    ├─ 채널 관리 (큐레이션 채널 페르소나)
    └─ 신고 처리 (댓글 모더레이션)
```

디자인 톤: 레퍼런스(short-form-phi)와 같은 **다크 테마, 모바일 우선**. 데스크톱에서는 중앙 모바일 프레임 유지.

## 5. 기능 명세

### 5.1 홈 피드

숏폼 피드의 표준 문법을 따른다.

- **세로 스와이프/스크롤** = 게시물 간 이동 (스냅 스크롤, 한 화면에 게시물 하나)
- 게시물 유형은 2가지가 피드에 혼재:
  1. **템플릿 카드 게시물** — 카드 여러 장을 **좌우 스와이프** (인스타 캐러셀 방식, 하단 인디케이터 도트)
  2. **영상 게시물** — 풀스크린 영상
- **공통 UI — 분할 레이아웃** (오버레이 아님, 결정 기록 §11-27):
  - 우측 세로 액션 바: ♥ 좋아요(카운트), 💬 댓글(카운트), ↗ 공유(카운트), **📖 읽기**
    - 뷰어 진입 CTA "읽기"가 이 그룹의 마지막(엄지에 가장 가까운) 자리를 차지한다. 나머지가 고스트 아이콘인 것과 달리 채워진 원형으로 두어 핵심 전환 버튼의 위계를 유지한다.
  - 하단 바: 채널 아바타 + 채널명 + 도서 제목/저자 요약 (경계선으로 카드 영역과 분리)
  - 카드는 텍스트 위주라 UI를 겹치면 읽기를 방해한다 — 영상 게시물(§5.3)이 들어오는 시점에 오버레이 재검토.
- **조회 로깅**: 게시물이 뷰포트에 1초 이상 노출되면 조회 1회 기록 (비로그인은 세션 ID 기준). 급상승 그리드·인기 가중치의 데이터 소스.

**피드 정렬 — 가중 랜덤 + 인기**

- 후보: 발행된 게시물 전체
- 점수 = `random() × (1 + log(1 + like_count + view_count×0.1)) × freshness`
  - `freshness`: 발행 7일 이내 게시물에 보정 가중치 (예: ×1.5)
- 세션 내 이미 본 게시물은 후순위. 페이지네이션은 커서 기반, 요청당 5~10개 프리페치.
- 같은 도서의 게시물이 연속 노출되지 않도록 셔플 후 제약 적용.

### 5.2 템플릿 카드 게시물

**아키텍처 (확정)**: 템플릿은 **프론트엔드에 고정된 React 컴포넌트**다. 관리자는 데이터만 입력하고, 카드 레코드는 다음 형태로 저장/전달된다:

```json
{
  "template_category": "a",
  "body": {
    "title-01": "",
    "title-02": "",
    "caption-01": "",
    "description-01": ""
  }
}
```

- 프론트에 `template_category → 컴포넌트` 레지스트리를 두고, `body`의 정해진 슬롯 키를 채워 렌더링한다.
- 게시물 = 카드의 순서 있는 목록. 관리자가 카드 유형과 순서를 조합해 게시물을 구성한다("조합을 만들어낸다"의 실체).

**MVP 카드 템플릿 세트 (3종)**

| 카테고리 | 이름 | 슬롯 (body 키) | 도서에서 읽는 값 | 비고 |
|---|---|---|---|---|
| `a` | 커버+훅 카드 | `title-01` 훅 헤드라인, `description-01` 부연(선택) | 커버, 카테고리, 제목, 저자/옮긴이, 출판사 | **기본형 — 모든 카드 게시물의 1번 카드로 필수** |
| `b` | 상세정보/목차 카드 | `title-01` 섹션 제목 | 카테고리, 출판사, 페이지 수, 출간일, ISBN, 목차 | [더보기] 탭 시 바텀시트로도 노출 |
| `c` | 인용구 카드 | `description-01` 인용 문장, `caption-01` 출처(선택) | 제목, 저자 | 공유 유발용 — 공유 시 이 카드가 OG 이미지 |

- **슬롯은 카드 고유의 텍스트만 담는다.** 도서 메타데이터는 `post.book_id` 조인으로 렌더 시점에 읽으므로 카드에 복제되지 않는다 — 도서 정보를 고치면 모든 카드에 즉시 반영된다.
- 트레이드오프: 게시물별로 도서 정보를 다르게 표시하는 "관리자 덮어쓰기"는 이 모델에서 불가능하다. 실제 필요가 확인되면 슬롯을 optional로 추가하고 `body[key] ?? book.field` 폴백을 넣는다 (결정 기록 §11-23).
- 템플릿 추가는 코드 배포로 이루어진다 (프론트 컴포넌트 + 슬롯 스키마 등록). CMS에서 템플릿을 새로 "디자인"하는 기능은 없음.
- 제외(v2 백로그): 영상 카드 블록, 큐레이션 인터스티셜(AI 추천/SPECIAL CURATION 류)

### 5.3 영상 게시물

- **독립 게시물 유형** (카드 블록이 아님). 피드에서 풀스크린으로 재생.
- 소스 2가지 병행:
  - **mp4 업로드**: 관리자가 30~60초 세로 영상 업로드 → Supabase Storage. `<video>`로 **음소거 자동재생 + 루프**, 탭으로 음소거 해제.
  - **유튜브 임베드**: 유튜브 URL/ID 등록 → 임베드 플레이어. (자동재생·제스처 제어에 제약이 있음을 인지하고 병행)
- 영상 게시물에도 도서 연결(`book_id`)과 "바로 읽기" CTA, 소셜 액션 바가 동일하게 붙는다.

### 5.4 전자책 뷰어

- **포맷**: EPUB. 관리자가 파일 업로드 → Supabase Storage (비공개 버킷, signed URL로 서빙).
- **렌더링**: epub.js 기반 웹뷰어.
  - 페이지 넘김(탭/스와이프), 글자 크기 조절, 밝기/테마(다크·라이트·세피아), 목차 이동
  - 진행률 표시 (챕터 x/y + 퍼센트)
- **접근 유형** (도서별 설정):
  - `full` — 전문 열람 (퍼블릭 도메인·자체 확보 콘텐츠)
  - `preview` — 지정 챕터(기본 1챕터)까지만. 잠긴 챕터 진입 시 **구매 안내 화면**.
- **미리보기 종료 화면 (preview 도서)**:
  - "이 책이 마음에 드셨나요?" + 외부 서점 구매 버튼: **교보문고 / 예스24 / 알라딘**
  - 링크는 도서 ISBN으로 각 서점 검색 URL을 **자동 생성**하고, 관리자가 도서별로 개별 URL을 **수동 덮어쓰기** 가능
  - 보조 CTA: 보관함에 찜
- **진행률 저장**:
  - 로그인 사용자: 서버 저장 (EPUB CFI + 퍼센트), 기기 간 동기화
  - 게스트: localStorage 저장 + 로그인 시 서버로 병합
- 진행률 100% 도달 시 완독 처리.

### 5.5 소셜 인터랙션 (전부 실동작)

| 기능 | 동작 | 로그인 |
|---|---|---|
| 좋아요 | 토글, 게시물당 1회, 카운트 실시간 반영 | 필요 (미로그인 탭 시 로그인 시트) |
| 댓글 | 작성/삭제(본인), 최신순 목록, 바텀시트 UI | 필요 |
| 공유 | Web Share API(OS 공유시트) + 링크 복사 폴백. 딥링크 `/p/[postId]`, OG 메타 자동 생성. 공유 버튼 탭 시 카운트 +1 | 불필요 |
| 조회수 | 뷰포트 1초 노출 기준 자동 로깅 | 불필요 |

**댓글 모더레이션**
- 댓글마다 **신고** 버튼 (사유 선택: 스팸/욕설/기타)
- 어드민 신고 큐: 신고된 댓글 확인 → 삭제 or 기각
- **금칙어 필터**: 등록 시점에 금칙어 포함 여부 검사 → 차단 (금칙어 목록은 어드민에서 관리)
- 삭제된 댓글은 soft delete ("삭제된 댓글입니다" 표시 없이 목록에서 제외)

### 5.6 탐색 (/discover)

레퍼런스 구성을 준용한다:

1. **검색바** (상단): 도서 제목 / 저자 / 채널명 대상. Postgres `ILIKE` + trigram 유사도 수준 (풀텍스트 인프라 없음). 결과는 도서·채널 섹션으로 구분 표시, 도서 결과 탭 시 해당 도서의 게시물 or 뷰어로.
2. **오늘의 추천**: 관리자가 어드민에서 지정한 추천 도서 배너 (수동 큐레이션, 3~5개 로테이션)
3. **관심 분야 칩**: 장르 카테고리 (경제경영/자기계발/소설/인문/에세이/과학…) → 탭 시 해당 장르 게시물 그리드
4. **급상승 그리드**: 최근 7일 조회수 상위 게시물 썸네일 그리드 (조회수 오버레이 표시). 탭 시 해당 게시물부터 시작하는 피드로 진입.

### 5.7 프로필 (/profile) — 기록형만

- 비로그인 접근 시 로그인 유도 화면.
- 상단 요약: 닉네임/아바타(소셜 계정 기반), **완독 도서 수**, 읽는 중 도서 수
- 탭 구성:
  - **학습 중**: 진행률 있는 도서 목록 (커버 + "챕터 x/y" 진행 바) → 탭 시 이어읽기
  - **보관함**: 찜한 도서 (미리보기 종료 화면·도서 상세의 찜 버튼으로 추가)
  - **완독**: 완독 도서 목록
- 제외(v2): 포인트, 레벨/칭호, 연속 학습 스트릭, 지식 성좌

### 5.8 인증

- **게스트 우선**: 피드·탐색·뷰어(게스트 진행률은 로컬)는 비로그인으로 전부 사용 가능
- **로그인 트리거**: 좋아요/댓글/찜/프로필 진입 시 로그인 바텀시트
- **수단**: 소셜로그인만 — **구글, 카카오** (Supabase Auth OAuth). 이메일 가입 없음.
- 최초 로그인 시 `profiles` 레코드 생성 (닉네임 = 소셜 프로필명, 수정 가능)

### 5.9 채널 (큐레이션 페르소나)

- 관리자가 운영하는 **장르별 채널 3~5개** (예: 돈이 되는 서재(경제경영), 밤의 문장들(소설/에세이), 생각의 근육(인문)…)
- 채널 = 이름 + 아바타 + 장르 + 소개. 모든 게시물은 채널 명의로 발행.
- 피드/게시물에서 채널 아바타 탭 시 채널 페이지(채널 정보 + 해당 채널 게시물 그리드).
- **채널별 콘텐츠 제약**: 소설·에세이 채널은 전문 공개 도서 중심, 경제경영·자기계발 채널은 샘플 전용으로 설계한다 — 해당 장르에 만료 저작물이 없다 (§5.11).
- 팔로우 기능은 v2.

### 5.10 어드민 CMS (/admin)

- **접근**: Supabase Auth 계정 중 `role = admin`인 계정만. 미들웨어에서 라우트 보호.
- **도서 관리**:
  - 도서 등록/수정: 메타데이터(제목, 저자, 옮긴이, 출판사, 커버, 카테고리, ISBN, 페이지, 출간일, 소개, 목차), EPUB 파일 업로드, 접근 유형(full/preview) + 미리보기 챕터 수, 구매 링크(자동 생성 미리보기 + 수동 덮어쓰기 필드)
- **게시물 관리**:
  - 카드 게시물 작성: 채널 선택 → 도서 선택(슬롯 프리필) → 카드 추가(템플릿 카테고리 선택 → 슬롯 필드 폼 입력) → 순서 조정 → 발행/임시저장
  - 영상 게시물 작성: 채널/도서 선택 → mp4 업로드 or 유튜브 URL → 발행
  - 목록: 상태(발행/임시), 조회·좋아요·댓글 수 확인, 수정/삭제
- **채널 관리**: 채널 CRUD
- **탐색 큐레이션**: "오늘의 추천" 도서 지정
- **모더레이션**: 신고 큐 (신고 사유·댓글 원문 확인 → 삭제/기각), 금칙어 목록 관리
- UI는 기능 우선의 심플한 관리 화면 (디자인 투자 최소화). WYSIWYG·비주얼 에디터 없음 — 폼 기반 데이터 입력.

### 5.11 콘텐츠 수급

**만료 판별 규칙 (한국 저작권법)**

2013-07-01 개정으로 보호기간이 사후 50년 → 70년이 되었으나, 시행 전 이미 만료된 저작물에는 소급 적용되지 않는다.

| 저작자 사망 | 적용 | 상태 |
|---|---|---|
| ~1962-12-31 | 구법 사후 50년 | **만료 — 전문 공개 가능** |
| 1963-01-01~ | 사후 70년 | 존속. 최초 만료는 2033년 말 |

→ **전문 공개 가능한 콘텐츠 풀은 2033년까지 고정된다.** 1962년 이전 사망 저작자 명단이 곧 등록 가능 목록의 전체다. 신규 유입을 기대할 수 없으므로 수급 계획은 이 고정 풀을 전제로 세운다.

**번역 저작권 — 등록 전 필수 확인**

원저작물이 만료여도 **한국어 번역본은 번역자의 저작권이 별도로 존속**한다. 해외 고전(도스토옙스키·헤세 등)은 전문 공개할 수 없다 — 샘플 범위로만 취급.

**등록 금지 목록**

- 월북·납북 작가(정지용·이태준·박태원·홍명희·김기림) — 사망 연도 불확실 또는 북한에서 1963년 이후 사망
- 근대 작가로 오인하기 쉬운 존속 저작권 — 백석(1996), 박경리(2008)

**소스**

| 소스 | 확보 방식 | 포맷 |
|---|---|---|
| 공유마당 어문 `gongu.copyright.or.kr` | 수동 다운로드 (다운로드 시 설문 응답 요구, 저작물 조회 API 없음) | PDF / HWP / TXT, 일부 EPUB |
| 한국 위키문헌 `ko.wikisource.org` | MediaWiki API + `ws-export.wmcloud.org` — 자동화 가능한 유일 경로 | EPUB 직접 생성 |
| 출판사 공개 샘플 | 개별 확보 | EPUB |

EPUB이 아닌 원본은 변환 후 어드민 업로드 (변환 스크립트는 `scripts/`).

**표지 — 자체 제작**

만료작에는 "원래 표지"가 없다. 시중 판본의 표지는 그 출판사의 저작물이고 우리 판본의 표지도 아니므로 가져다 쓸 수 없다. 우리 판본의 표지는 우리가 만든다 (`npm run covers`, 결정 기록 §11-28).

- 생성물은 `covers` 공개 버킷에 `{book.id}.png`로 올라가고 `books.cover_url`에 반영된다. 재실행하면 덮어쓴다.
- 제목 해시로 팔레트를 고정해 같은 책은 늘 같은 색이다. DESIGN.md가 "색은 도서 커버가 낸다"고 규정하므로, 무채색 UI에서 **표지만 유채색**이다.
- 출판사 샘플 도서는 해당 판본의 표지를 출판사에서 함께 제공받아 어드민으로 업로드한다.
- 표지가 없는 도서는 `BookCover`의 타이포그래피 폴백으로 렌더된다 — 임시방편이 아니라 상시 경로다.

**권리 비대칭 — 설계 전제**

| 권리 | 대상 | 규모·장르 |
|---|---|---|
| 전문 공개 가능 | 한국 근대문학 만료작 | 소수 정예. 소설·시·수필에 편중 |
| 샘플만 가능 | 그 외 전부 | 콘텐츠 대다수 |

둘은 대등한 갈래가 아니다. 경제경영·자기계발 장르는 전문 공개 가능 도서가 0건이며, 채널 구성이 이 제약을 받는다 (§5.9).

**Phase 1 시딩 원칙 — 단편 우선**

근대 **단편**(「운수 좋은 날」·「메밀꽃 필 무렵」·「봄봄」·「날개」 등)으로 시딩한다. 30분 내 완독이 가능해 발견 → 읽기 → 완독이 한 세션에 닫히고, 완독률(§2 보조 지표)이 출시 직후부터 측정된다. 장편 위주로 시딩하면 완독 데이터가 수개월간 비어 있다.

## 6. 데이터 모델 (Supabase Postgres)

```
channels
  id uuid PK, name text, slug text UNIQUE, avatar_url text,
  genre text, description text, created_at timestamptz

books
  id uuid PK, title text, author text, translator text, publisher text,
  cover_url text, category text, isbn text, page_count int,
  pub_date_paper date, pub_date_ebook date, intro text,
  toc jsonb,                     -- ["1장. …", "2장. …"]
  epub_path text,                -- Storage 경로 (private bucket)
  file_size_mb numeric,
  access_type text CHECK (access_type IN ('full','preview')),
  preview_chapter_limit int,     -- preview일 때 열람 가능 챕터 수 (기본 1)
  purchase_links jsonb,          -- {kyobo?: url, yes24?: url, aladin?: url} 수동 덮어쓰기용, null이면 ISBN으로 자동 생성
  created_at timestamptz

posts
  id uuid PK, channel_id uuid FK, book_id uuid FK,
  type text CHECK (type IN ('cards','video')),
  status text CHECK (status IN ('draft','published')),
  published_at timestamptz,
  -- 비정규화 카운터 (트리거 or RPC로 증감)
  like_count int DEFAULT 0, comment_count int DEFAULT 0,
  share_count int DEFAULT 0, view_count int DEFAULT 0

post_cards
  id uuid PK, post_id uuid FK, sort_order int,
  template_category text,        -- 'a' | 'b' | 'c' (프론트 레지스트리 키)
  body jsonb                     -- { "title-01": "", "caption-01": "", ... }

post_videos
  post_id uuid PK/FK,
  source_type text CHECK (source_type IN ('upload','youtube')),
  video_path text,               -- upload일 때 Storage 경로
  youtube_id text,               -- youtube일 때
  duration_sec int

profiles
  id uuid PK (= auth.users.id), nickname text, avatar_url text,
  role text DEFAULT 'user',      -- 'user' | 'admin'
  created_at timestamptz

likes        (user_id, post_id) PK 복합, created_at
comments     id PK, post_id FK, user_id FK, content text,
             deleted_at timestamptz NULL, created_at
reports      id PK, comment_id FK, reporter_id FK, reason text,
             status text CHECK (status IN ('open','deleted','dismissed')), created_at
bookmarks    (user_id, book_id) PK 복합, created_at          -- 보관함(찜)
reading_progress
             (user_id, book_id) PK 복합, epub_cfi text,
             percent numeric, completed_at timestamptz NULL, updated_at
view_logs    id bigserial PK, post_id FK, user_id uuid NULL,
             session_id text,    -- 게스트 식별용
             created_at
banned_words id PK, word text UNIQUE
featured_books (탐색 '오늘의 추천') book_id FK, sort_order, active bool
```

**RLS 원칙**
- 읽기: `posts(published)`·`post_cards`·`books`(메타)·`channels` 등은 공개 read
- 쓰기: `likes`/`comments`/`bookmarks`/`reading_progress`는 본인 행만, `reports`는 로그인 사용자 insert만
- 어드민 쓰기(`books`, `posts`, `channels` 등)는 `role='admin'` 체크 (service role or RLS policy)
- EPUB 파일: private bucket + 서버에서 signed URL 발급 (preview 도서는 뷰어 레벨에서 챕터 잠금 — MVP에서는 클라이언트 제어 수준을 허용, 파일 분리 서빙은 v2)

## 7. 비기능 요구사항

- **성능**: 피드 스크롤 60fps 목표 — 게시물 가상화(앞뒤 2~3개만 마운트), 이미지 next/image 최적화, 영상 지연 로드·뷰포트 이탈 시 정지
- **반응형**: 360px~ 모바일 최적화, 태블릿/데스크톱은 중앙 모바일 프레임(max-width ~480px)
- **SEO/공유**: 게시물 딥링크에 OG 태그 (도서 커버/제목/훅 문구) — 공유 유입의 랜딩 품질
- **접근성**: 자동재생 영상 기본 음소거, 대체 텍스트, 키보드 페이지 넘김(뷰어)
- **분석 이벤트**(최소): `post_view`, `reader_open`(핵심 전환), `reader_progress`, `book_complete`, `like`, `comment`, `share`, `purchase_link_click` — Supabase 테이블 or 경량 애널리틱스로 수집
- **저작권 운영 원칙**: 전문 열람 허용은 저작권 만료(저작자 **1962년 이전 사망**) 또는 권리 확보 콘텐츠만. **한국어 번역본은 번역자 저작권이 별도 존속하므로 해외 고전은 전문 공개 불가.** 그 외는 출판사가 공개한 샘플 범위 내로 제한. 판별 규칙·등록 금지 목록은 §5.11.

| 레이어 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | Vercel 배포 |
| 인증 | Supabase Auth | 구글·카카오 OAuth |
| DB | Supabase Postgres | RLS 사용 |
| 스토리지 | Supabase Storage | EPUB(private), 커버/영상(public or signed) |
| 뷰어 | epub.js | React 래퍼(react-reader 등) 검토 |
| 스타일 | Tailwind CSS | 다크 테마 우선 |

| 상태/데이터 | React Query(TanStack) + Supabase JS | 커서 기반 피드 |

### 8.1 shadcn/ui 사용 전략

**왜 shadcn/ui인가**
- 컴포넌트가 `node_modules`가 아니라 **프로젝트 코드로 복사**된다 → 숏폼 피드처럼 비표준 UI를 만들 때 라이브러리와 싸우지 않고 직접 고칠 수 있다.
- Radix UI 프리미티브 기반이라 **접근성(포커스 트랩, 키보드 내비, ARIA)이 기본 제공** → 바텀시트·다이얼로그를 직접 만들 때 생기는 a11y 부채를 피한다.
- Tailwind 토큰과 CSS 변수로 테마가 구성되어 **다크 테마 우선 설계**와 궁합이 좋다.

**초기 설치 컴포넌트**

| 컴포넌트 | 사용처 |
|---|---|
| `drawer` (Vaul) | 댓글 시트, 도서 상세("더보기"), 로그인 시트 — 모바일 바텀시트의 핵심 |
| `dialog` | 어드민 확인 모달, 신고 사유 선택 |
| `button`, `input`, `textarea`, `label`, `form` | 어드민 CMS 폼 전반, 댓글 입력 |
| `select`, `checkbox`, `switch` | 어드민(템플릿 카테고리 선택, 발행 상태, 접근 유형) |
| `avatar` | 채널 아바타, 프로필 |
| `badge` | 장르 칩, 상태 뱃지(발행/임시) |
| `tabs` | 프로필(학습 중/보관함/완독), 어드민 섹션 |
| `sonner` (toast) | 좋아요·찜·복사 완료 피드백 |
| `skeleton` | 피드·그리드 로딩 상태 (CLS 방지) |
| `table` | 어드민 도서/게시물/신고 목록 |
| `progress` | 뷰어 진행률, 프로필 챕터 진행 바 |
| `scroll-area` | 목차 리스트, 긴 댓글 목록 |

**shadcn을 쓰지 않는 영역** — 다음은 라이브러리 없이 직접 구현한다. 숏폼 특유의 제스처·성능 요구가 기성 컴포넌트와 맞지 않는다.
- 홈 피드의 세로 스냅 스크롤 (CSS Scroll Snap + IntersectionObserver)
- 카드 좌우 스와이프 캐러셀 (터치 제스처 직접 처리 — `embla-carousel` 검토 가능)
- 우측 세로 액션 바 오버레이
- EPUB 뷰어 셸 (epub.js가 iframe을 직접 제어)

**테마 토큰** — `globals.css`의 CSS 변수로 다크 팔레트를 정의하고, 컴포넌트에서는 시맨틱 토큰(`bg-background`, `text-muted-foreground`)만 사용한다. 원시 hex 값을 컴포넌트에 직접 쓰지 않는다.
