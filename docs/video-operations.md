# 영상 변환·업로드 운영

2026-09-11 결정: 무료 PC 변환 + 기존 Supabase 공개 저장소 + 자동 화질 재생. 원본·재생본의 퍼가기 방어는 이번 범위에서 제외한다. 관리형 영상 SaaS나 별도 변환 서버는 필요하지 않다. FFmpeg와 hls.js는 무료지만 기존 저장소의 용량·전송량 과금/무료 한도는 그대로 적용된다.

## 관리자가 하는 일

1. `scripts/convert-video.cmd`를 실행하고 원본 하나를 선택한다. Node.js 22.18 이상, FFmpeg/ffprobe(PATH 등록), 프로젝트 의존성이 필요하다. FFmpeg 배포판은 libx264, AAC, zscale, tonemap을 포함해야 한다.
2. 원본 옆에 생성된 `*-web-시간.zip`을 관리자 → 새 영상 게시물의 **변환한 영상 ZIP**에서 선택한다. 화질별로 따로 올리지 않는다. 변환은 PC에서 진행되며 웹 서버의 요청 시간 제한을 사용하지 않는다.
3. 화질·길이·전체 용량·첫 화면을 확인하고 **영상 업로드**를 누른다. 완료 후 자동/개별 화질로 미리보기하고 발행 또는 임시저장한다. 미리보기는 조회 수를 올리지 않는다.
4. 전송이 끊기면 같은 화면의 **실패한 파일 이어 올리기**로 재시도한다. 완료된 파일은 재전송하지 않는다. 중단 버튼은 전송만 멈춘다. 화면을 닫거나 다른 ZIP으로 바꾸면 새 업로드가 시작되며 이전 기록은 미사용 파일 관리에 남는다.
5. `/admin/videos`에서 미완료·미사용 묶음을 확인한다. 백업과 새 영상 재생을 확인한 뒤 삭제한다. 실제 게시물에서 사용하는 묶음은 서버가 삭제를 거부한다. 삭제가 중간에 실패하면 같은 항목에서 재시도한다.

권장 영상은 30~60초다. 변환 도구는 최대 10분, ZIP 내부 합계 512MiB, 개별 파일 50MiB까지 허용한다. 긴 영상의 호환 MP4가 50MiB를 넘으면 길이를 줄여야 한다. 실제 Supabase 버킷의 개별 파일 제한이 더 작으면 업로드가 거부된다. ZIP은 서버로 보내지 않으므로 관리자 서버 액션의 4MB 제한을 올릴 필요가 없다.

## 관리자 화면에서 mp4 직접 변환

2026-09-12부터 영상 칸(「영상 파일 또는 변환한 ZIP」)이 mp4·mov를 받는다. 파일을 고르면 크기·길이가 보이고 **「변환」**을 누르면 브라우저 안의 FFmpeg(wasm, 단일 스레드)가 PC 도구와 파일 단위로 같은 묶음(화질별 HLS·`fallback.mp4`·`poster.jpg`·`manifest.json`)을 메모리에 만든다. 브라우저 경로는 720p까지 만들고 1080p가 필요하면 PC 도구를 쓴다. 그 뒤 「영상 업로드」부터는 ZIP을 올렸을 때와 같다. 변환 도구(약 31MB)는 처음 한 번 내려받고, 서버로는 아무것도 보내지 않는다.

- 상한: 길이 180초, 파일 300MB. 넘으면 PC 변환 도구의 ZIP을 올리라고 안내한다(PC 도구는 10분·512MiB).
- HDR 원본은 브라우저에서 거부한다 — 톤매핑 필터가 없다. PC 도구를 쓴다.
- 「변환 중단」은 변환만 멈춘다. 파일을 바꾸면 처음부터다.
- 게시물 영상과 도서 트레일러(도서 폼의 「트레일러」 섹션)가 같은 칸을 쓴다.
- 변환은 관리자 기기의 CPU를 쓴다. 60초 영상 기준 480+720 실측은 약 2.5분(veryfast)이며, 자세한 조건은 설계 문서 §4.4에 있다.

## 생성물과 재생

- 짧은 변 기준 480/720/1080, 원본보다 큰 화질은 생성하지 않는다. 작은 원본은 해당 크기의 한 화질만 생성한다. 가로·세로·정사각·회전 메타데이터를 처리하며 프레임은 30fps로 맞춘다. HDR은 SDR/BT.709로 변환한다.
- H.264/AAC, 약 2초의 키프레임 정렬 TS 구간, HLS master/화질 목록, JPEG poster, 720 이하 MP4 호환본, 버전 1 manifest를 ZIP에 넣는다. 음성이 없는 영상에는 음성을 만들지 않는다.
- 압축 품질 기준(CRF 23)에 화질별 최대 전송량을 함께 설정한다. 단순한 도서/문구 영상에 고정 전송량을 강제하지 않는다. 여러 화질과 호환본을 보관하므로 전체 저장 용량은 원본보다 커질 수 있고, 관리자에서 실제 묶음 용량을 표시한다.
- HLS를 지원하는 브라우저는 자체 재생기를 사용한다. 나머지는 실제 영상이 필요할 때만 hls.js를 불러온다. 처음에는 최저 화질에서 시작하고 네트워크/화면에 따라 자동 선택한다. 자체 재생 경로의 시작 화질은 브라우저가 결정한다.
- 현재 영상에 3초(남은 시간이 더 짧으면 남은 분량) 버퍼가 있고 250ms 이상 머무른 경우에만 이동 방향의 이웃 한 개를 준비한다. hls.js 경로는 최저 화질 첫 구간을 받은 뒤 중단한다. 자체 재생 경로는 metadata/poster만 요청하며 구간 수는 브라우저에 맡긴다.
- 데이터 절약·3G 이하·오프라인·숨겨진 탭은 사전 로딩을 끈다. 화면을 떠난 재생기/요청은 정리한다. 음소거·반복 재생·사용자 일시정지·시트 뒤 정지 동작은 유지한다.
- HLS 미지원/회복 불가능한 오류면 MP4 호환본으로 한 번 전환한다. 가능한 경우 재생 위치와 음소거·정지 상태를 유지한다. 호환본도 실패하면 재시도 화면을 표시한다. YouTube 임베드는 기존 플레이어를 사용한다.

## 저장과 실패 처리

`20260911000001_video_bundles.sql`은 `video_uploads`와 영상 상세의 `hls_path`, `poster_path`, `renditions`, `asset_group_id`를 추가한다. 기존 `video_path`는 기존 영상 주소 또는 새 호환 MP4 주소다. 기존 행은 변경 없이 재생된다.

관리자 인증 후 업로드별 고유 `bundles/UUID` 경로를 발급한다. 브라우저에서 관리자 세션으로 Storage에 직접 전송하며 작은 파일은 최대 3개 동시, 6MiB 초과 파일은 TUS 이어 올리기를 사용한다. 경로별 캐시는 1년이며 교체 시 새 UUID를 사용한다.

브라우저와 서버 모두 manifest·파일 크기·내부 상대 경로·재생 목록을 확인한다. 외부 URI·상위 경로·암호화 키 참조·파일 누락은 거부한다. 준비 완료 상태는 서버만 기록할 수 있다. 게시물 저장 RPC는 관리자 권한과 검증 완료 상태를 확인하고 게시물/영상 상세를 한 트랜잭션으로 변경한다. 폼의 기존 영상 주소를 신뢰하지 않는다. 도서·채널 검증 또는 저장 실패 시 기존 게시물과 최초 발행일을 보존한다.

정리는 업로드 행을 잠그고 참조 여부를 다시 확인한 후 삭제 상태를 기록한다. Storage 쓰기도 같은 행 잠금을 사용하므로 준비 완료된 묶음 덮어쓰기와 삭제 뒤 늦은 업로드의 파일 재생성을 막는다. 삭제 중인 묶음은 게시물에 연결할 수 없다. 게시물 삭제/영상 교체 후 묶음은 명시적인 정리까지 남는다.

도서 트레일러(`book_trailers`)도 같은 묶음 표를 쓴다. 한 묶음은 게시물·트레일러 중 **한 곳에만** 붙고(`save_video_post`·`save_book_trailer`가 서로의 참조를 거부), `claim_video_cleanup`은 트레일러 참조도 사용 중으로 본다. `/admin/videos`가 「트레일러에서 사용 중」과 도서 링크를 보인다.

기존 단일 MP4는 기존 삭제 흐름을 따른다.

## 기존 영상 전환과 배포 순서

1. `node --env-file=.env scripts/prepare-existing-videos.mjs`로 단일 파일 영상을 조사한다. `--convert --limit 5`를 추가하면 PC 백업·SHA-256 재확인·변환 묶음 생성까지 한다. 원본과 DB 연결은 변경하지 않는다. 기록은 Git에서 제외된 `.tmp/video-migration-*`에 저장된다. 장기 백업은 운영자가 별도 보관해야 한다.
2. **DB 추가 마이그레이션 → 관리자/사용자 앱 배포 → 새 영상 한 건 업로드·재생 확인** 순서로 적용한다. 앱을 먼저 배포하면 새 필드 조회가 실패한다. 롤백 시 이전 앱은 `video_path` 호환본을 재생할 수 있다. 도서 트레일러 마이그레이션(`20260912000003_book_trailers`)은 관리자 앱 배포보다 먼저 적용해야 한다 — 도서 목록과 수정 화면이 `book_trailers`를 임베드로 읽는다. 사용자 앱은 이번 범위에 없어 변경이 없다. 롤백은 `book_trailers`를 drop하고 `20260911000001`의 `save_video_post`·`claim_video_cleanup` 본문을 다시 실행한다.
3. 기존 게시물 수정 화면에서 변환 ZIP을 업로드하고 확인 후 저장한다. 게시물 ID·연결 도서·조회 수·최초 발행일을 유지한다. 기존 파일의 삭제는 백업·전환 확인 이후 별도 처리한다.

2026-09-11 운영 저장소 조회 결과 단일 파일 영상은 2건이었다. 두 건 모두 PC 백업과 해시 재확인 및 ZIP 변환을 완료했다. 운영 DB 마이그레이션·앱 배포·운영 게시물 연결 교체는 아직 하지 않았다.
