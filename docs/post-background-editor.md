# 게시글 배경 편집 — 2026-09-11

## 바뀐 점

- 중앙에서 표지·도서명·저자명 중복을 제거하고 하단 도서 정보로 통합했다.
- 기존 관리자 문구·표시 방식 입력은 유지한다. 템플릿 a는 문장·설명, b는 장르·문장·설명이다. 이전 template 키와 문구는 그대로 읽는다.
- 게시글마다 단색(추천 5색/직접 선택) 또는 이미지 첨부를 선택한다. 이미지 가로·세로 위치, 어둡기, 밝은/어두운 글자를 조정한다.
- 채널 헤더와 하단 도서·액션 영역은 배경에서 제외한다. 배경이 없는 기존 게시글은 종이색이며, 이미지 로딩 중·실패 시 글자색에 맞는 대체 배경을 표시한다.
- 관리자 미리보기는 실제 홈과 같은 조각을 375×812 크기로 보여준다.

## 사용 방법

관리자 → 게시물 → 새 카드 게시물 또는 기존 게시물 수정에서 문구와 배경을 설정한다. 이미지는 JPG/PNG/WebP, 최대 3MB다. 미리보기에서 문구가 잘 읽히고 사진의 주요 부분이 잘리지 않는지 확인한 뒤 발행 또는 임시저장한다. 기존 이미지는 새 파일 없이 저장해도 유지된다. 이미지 제거 후에는 새 이미지를 넣거나 단색으로 바꾸어 저장한다.

## 저장과 파일 처리

`post_cards.background` JSONB(nullable)에 설정을 저장한다. 마이그레이션은 기존 콘텐츠를 변경하지 않는다. 서버에서 관리자 권한과 실제 이미지 해독을 검사하고 최대 1440×1800 안으로 축소한 WebP를 기존 공개 covers 버킷의 `post-backgrounds/{postId}/{uuid}.webp`에 저장한다.

폼에서 보낸 임의 이미지 주소는 사용하지 않는다. DB에서 읽은 기존 주소 또는 업로드 결과만 저장한다. 새로운 파일은 고유 경로를 사용하며 DB 저장 실패 시 회수한다. 교체·단색 전환·게시글 삭제가 완료되면 해당 게시글의 이전 배경 파일을 제거한다. 기존 도서 표지 파일은 삭제 대상이 아니다.

전체 ESLint의 기존 오류는 관리자 추천 화면의 따옴표, 댓글·독서·테마 화면의 기존 상태 처리 규칙 위반이다. 이번 범위에서 해당 화면은 수정하지 않았다.

## 운영 반영

2026-09-11 운영 DB에 `20260910000002_post_card_background.sql`을 적용했다. 기존 데이터는 변경하지 않았다. 사용자·관리자 앱은 master push에 연결된 기존 Vercel 프로젝트로 배포한다. 직접 고른 색이나 복잡한 사진의 가독성은 관리자 미리보기에서 확인해야 한다.

배포 파일에서는 작업 공간의 별도 도서 표지 제작·영상 최적화 작업을 제외했다. 이 배포 파일만 모은 일반 검증 폴더에서 두 앱 프로덕션 빌드, 자료형 검사, 기본 검사 311개, 브라우저 동작 15개, 격리 로컬 DB 연동 9개를 다시 실행해 모두 통과했다. 위의 전체 작업 공간 검사 수와 배포 파일 검사 수는 포함된 별도 기능 때문에 다르다.
