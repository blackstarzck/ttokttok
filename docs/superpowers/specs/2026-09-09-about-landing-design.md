# 소개 랜딩 (`/about`) — 첫 방문자에게 서비스를 설명한다

> **2026-09-10 개정**: 결정 4·5·6(실제 카드·실데이터·실제 화면 캡처)은 폐기됐다. 지금의 `/about`은 awesomic.com 홈 레이아웃을 복제한 정적 페이지이고 에셋 자리는 비어 있다 — [`2026-09-10-about-awesomic-clone-design.md`](./2026-09-10-about-awesomic-clone-design.md). 결정 1·2·3은 그대로 유효하다.

2026-09-09. 앱 밖에 서비스 소개 페이지를 하나 만든다.

PRD §4의 IA에는 랜딩이 **없다**. 홈(`/`)이 곧바로 카드 피드이고, 그것은 §2의
핵심 명제("발견과 독서 사이의 마찰을 0으로")를 지키려는 의도적 설계다. 그래서
이 문서는 그 명제를 건드리지 않는 자리에 소개 페이지를 놓는 방법을 정한다.

## 왜 하는가

첫 방문자는 지금 아무 설명 없이 카드 피드를 만난다. 피드는 그 자체로 소비가
시작되는 포맷이니 대개는 그걸로 충분하지만, 두 부류가 답을 못 받는다.

- **"이게 뭐 하는 서비스인가"** — 공유 링크·검색으로 흘러들어온 사람.
- **"이게 합법인가"** — 무료로 전문을 읽게 해 준다는 말을 의심하는 사람.
  §5.11의 권리 판정(저자 사망 1962년 이전, 위키문헌 수급)은 실제로 공들인
  작업인데 사용자 화면 어디에도 드러나지 않는다.

두 번째가 특히 아깝다. 신뢰 자산이 있는데 안 쓰고 있다.

## 범위

새로 만드는 것:

| 경로 | 내용 |
|---|---|
| `/about` | 소개 페이지 (서버 컴포넌트, `(main)` 그룹 **밖**) |

수정하는 것:

| 파일 | 변경 |
|---|---|
| `src/components/feed/top-bar.tsx` | 비로그인일 때만 「소개」 링크 추가 |

**손대지 않는 것**: `globals.css`, `docs/DESIGN.md`, `(main)/layout.tsx`,
`(main)/page.tsx`, 피드 컴포넌트 일체, DB 스키마, 마이그레이션.

비목표: 다국어, 이메일 수집·뉴스레터, 블로그, 가격표(수익화 없음 — PRD §1
비목표), 별도 마케팅 도메인.

## 결정 기록

### 1. 랜딩은 `/about`이고, `/`는 피드로 남는다

검토한 대안 둘:

- **`/`를 게스트 랜딩으로** — 마케팅 임팩트는 가장 크지만 §2의 "마찰 0"과
  정면으로 충돌한다. 게스트도 피드·뷰어를 전부 쓸 수 있게 설계된 §5.8의
  "게스트 우선" 원칙과 기존 `isGuest` 경로를 되돌려야 한다.
- **`/` 피드 위에 게스트 히어로 블록** — 라우트는 안 늘지만 피드의 `h-dvh` +
  스냅 계약(DESIGN.md Layout, §11-53)을 깨뜨릴 위험이 크다.

그래서 별도 라우트. `(main)` 그룹 밖에 두므로 `BottomNav`가 붙지 않고 480px
프레임에도 묶이지 않는다 — `/read`·`/admin`이 이미 같은 자리에 있다.

### 2. DESIGN.md의 타이포·여백 상한을 적용하지 않는다

DESIGN.md는 타이포 상한 24px(`titleScreen`), 여백 상한 48px(`2xl`)이고 임의
값을 금지한다. 데스크톱 소개 페이지에는 둘 다 좁다.

DESIGN.md가 정한 정식 절차는 "globals.css에 토큰을 추가하고 문서에 반영한 뒤
사용"이지만, **랜딩은 그 가이드를 따르지 않아도 된다고 결정했다.** 그래서
토큰을 늘리지 않고 Tailwind 기본 스케일(`text-5xl`, `py-24` 등)을 `/about`
안에서만 쓴다. 결과적으로 `globals.css`와 DESIGN.md를 **한 줄도 고치지
않는다** — 앱 화면에 미치는 영향이 0이다.

### 3. 그래도 색은 시맨틱 토큰만 쓴다

규칙이 아니라 선택이다. 이유 둘:

- 다크모드가 공짜로 따라온다. 원시 값을 쓰면 `.dark` 분기를 손으로 다 짜야
  하고, 한 군데 빠뜨리면 그 섹션만 흰 판으로 남는다.
- 방문자는 이 페이지에서 **탭 한 번 뒤에 무채색 앱**으로 들어간다. 랜딩만
  브랜드 색을 입히면 들어가는 순간 다른 제품처럼 보인다.

색은 **실제 도서 커버**가 낸다 (DESIGN.md 원칙 1과 같은 처방). 커버가 바뀌면
페이지 인상도 바뀐다.

### 4. 히어로 샘플은 실제 `PostCard`를 그대로 쓴다

닮게 그리지 않는다 — §11-56이 기록한 실패("닮게 그리면 언젠가 한쪽만
고쳐진다")가 그대로 반복된다. 어드민 미리보기가 사용자 화면과 같은
컴포넌트를 쓰는 것과 같은 이유다 (§5.10).

**조회 집계에 섞이지 않음을 확인했다**: `record_view`는 `card-feed.tsx:158`과
`feed-scroller.tsx:134` 두 곳에서만 불린다. `PostCard` 자신은 부르지 않으므로
피드 밖에서 렌더해도 조회수가 늘지 않는다.

**좋아요·공유는 막는다.** 카드를 `inert` 래퍼에 넣는다 (어드민 미리보기가
쓰는 기법). 랜딩이 조용히 `share_count`를 늘리면 안 된다.

**탭은 살린다.** `inert` 서브트리 옆에 형제로
`<Link className="absolute inset-0">`를 겹쳐 실제 게시물(`/p/[postId]`)로
보낸다. 카드 안에 이미 `<a>`가 있으므로 카드를 `<Link>`로 감싸면 중첩 앵커가
되어 유효하지 않은 마크업이 된다 — 그래서 조상이 아니라 형제로 얹는다.
`inert`가 서브트리를 접근성 트리에서 빼므로 이 오버레이 링크가
`aria-label`로 대체 텍스트를 진다.

### 5. 데이터는 실제 콘텐츠, 실패하면 섹션을 접는다

서버 컴포넌트에서 세 번 읽는다 (`Promise.all`):

| 쓰임 | 함수 | 왜 이것인가 |
|---|---|---|
| 히어로 샘플 카드 1건 | `getFeed(seed, null, 1, null, "cards")` | `PostCard`가 `FeedPost`를 요구한다 |
| 추천 도서 커버 | `getFeaturedBooks()` | §5.6-2 수동 큐레이션 |
| 릴스 섹션 커버 | `getFeed(seed, null, 4, null, "video")` | 영상 게시물의 도서 커버 |

**`getTrendingPosts()`는 쓸 수 없다.** 반환 타입이
`{ id, view_count, books }`뿐이라 `channels`와 `post_cards`가 없고, `PostCard`가
요구하는 `FeedPost`를 만들지 못한다. 같은 이유로 `getFeaturedBooks()`의
`DiscoverBook`도 히어로에 못 쓴다. 카드 본문·채널을 함께 주는 함수는
`getFeed`뿐이다.

`sessionId`에 `null`을 넘기는 것이 여기서는 안전하다. `(main)/page.tsx`가
경고하는 문제는 1페이지와 다음 페이지가 **다른** 세션 id로 점수를 계산해 같은
게시물이 두 페이지에 겹치는 것인데, `/about`은 1건을 받고 페이지네이션을 하지
않으므로 갈릴 페이지 경계가 없다.

`seed`는 요청마다 `crypto.randomUUID()`로 새로 뽑는다 — 방문할 때마다 다른
카드·다른 커버가 걸리고, 결정 3의 "색은 커버가 낸다"가 실제로 작동한다.

FRONTEND.md §5의 규약대로 **실패를 빈 값으로 삼키지 않는다**: 세 호출이 모두
`failed`를 함께 돌려주므로, `failed`거나 결과가 비면 그 섹션을 **렌더하지
않는다**. 소개 페이지에서 "추천 도서가 없습니다"는 정보가 아니라 흠이다.
페이지의 나머지(루프·저작권·CTA)는 데이터와 무관하므로 그대로 선다. 히어로는
카드를 못 구하면 텍스트 단독 히어로로 좁혀 선다 — 히어로가 통째로 사라지면
페이지가 제목 없이 시작한다.

### 6. 뷰어·릴스는 실제 화면을 캡처해서 쓴다

div로 가짜 제품 UI를 그리지 않는다. 실제 `/read/[bookId]`와 `/reels`를 브라우저로
띄워 스크린샷을 찍고 `public/`에 커밋한다. 가짜가 아니라 진짜 화면이다.

영상을 **재생하지는 않는다** — 랜딩에 YouTube 임베드나 자동재생 플레이어를
얹으면 LCP·INP를 그만큼 잃고, 소개 페이지가 얻는 것보다 비싸다. 실제 릴스
화면 캡처가 그 역할을 한다.

**구현 중 정정 — 릴스 섹션의 도서 커버 그리드는 뺐다.** 처음 설계는 영상
게시물의 커버를 4열로 깔는 것이었는데, 지금 DB의 영상 게시물이 참조하는 책이
위 추천 스트립과 **똑같은 세 권**이었다(하늘과 바람과 별과 시·날개·메밀꽃 필
무렵). 한 페이지에 같은 커버가 두 번 나오면 자료가 아니라 자리채우기로
읽힌다. 중복을 걸러 내면 남는 것이 0권이라 그 방법도 쓸 수 없다. 그래서
캡처와 본문만 두고, `posts`는 **게이트로만** 받는다 — 영상 게시물이 하나도
없으면 이 섹션 자체가 거짓이 되므로 그리지 않는다. 책이 넉넉히 쌓이면 다시
볼 일이다.

뷰어 캡처는 **다크로 찍는다** — `reader-settings.ts`의 `DEFAULT_PREFS.theme`이
`dark`라 그것이 실제 기본값이다. 라이트로 바꿔 찍으면 제품을 잘못 보여주는
것이 된다.

캡처할 콘텐츠가 없으면(전문 도서 0건, 영상 게시물 0건) 그 섹션을 빼고
사용자에게 알린다. 없는 화면을 그려 넣지 않는다.

### 7. 진입로는 게스트 `TopBar`의 「소개」 링크 하나

`TopBar`는 이미 `isGuest`를 받는다. 비로그인일 때만 알림 종 옆에 조용한
텍스트 링크를 놓는다. 로그인 사용자에게는 안 보인다 — 이미 아는 사람에게
소개를 권할 이유가 없다.

한 파일 수정으로 끝나고 피드 마찰을 늘리지 않는다. 프로필·탐색에도 넣는
안은 노출을 늘리는 대신 앱 IA 수정으로 번져서 접었다.

## 페이지 구성

내용 섹션 **7개**(1~7)에 상단 바와 푸터가 붙는다. 일곱 섹션의 레이아웃 계열이
전부 다르다 — 같은 형태를 두 번 쓰지 않는다.

| # | 섹션 | 레이아웃 계열 | 데이터 |
|---|---|---|---|
| 0 | 상단 바 (워드마크 + CTA 1개, 1줄, ≤64px) | sticky bar | — |
| 1 | 히어로 (헤드라인·부연·CTA / 실제 `PostCard`) | 비대칭 split | 카드 게시물 1건 |
| 2 | 핵심 루프 (발견 → 읽기 → 이어읽기) | 헤어라인 타입 밴드, **카드 없음** | — |
| 3 | 지금 읽을 수 있는 책 | 가로 스크롤 스냅 스트립 | `getFeaturedBooks()` |
| 4 | 뷰어 | split (히어로와 좌우 반전) | `/read` 스크린샷 |
| 5 | 릴스 | 제목이 위를 가로지르고 좁은 캡처 + 본문이 위를 맞춘다 | `/reels` 스크린샷 |
| 6 | 콘텐츠 출처·저작권 | 텍스트 2블록 | — |

| 8 | 푸터 (링크 + 저작권 1줄) | 헤어라인 행 |  — |

### 카피 (확정)

**히어로**
- 헤드라인: `읽을 생각 없이 열어도, 첫 장이 열립니다` (데스크톱 2줄 이내)
- 부연: `숏폼처럼 넘기다 마음이 가는 책을 만나면, 그 자리에서 바로 읽기 시작합니다. 설치도 결제도 없습니다.` (14어절)
- CTA: `피드 열기` (primary, → `/`) + `도서 목록 보기` (secondary, → `/discover`)

**핵심 루프** (제목 + 한 줄)
1. `피드에서 발견` / 장르별 큐레이션 채널이 책 한 권을 카드 한 장으로 소개합니다.
2. `탭 한 번에 읽기` / 전문 도서는 그 자리에서 뷰어가 열립니다. 로그인도 필요 없습니다.
3. `진행률로 이어읽기` / 어디까지 읽었는지 남습니다. 보관함과 완독 기록도 함께 쌓입니다.

**섹션 제목**
- 3: `지금 읽을 수 있는 책`
- 4: `발견에서 첫 장까지, 탭 한 번`
- 5: `영상으로 만나는 책`
- 6: `본문을 드리는 책은 저작권이 만료된 작품입니다`
- 7: `읽을 책은 이미 피드에 있습니다` + CTA `피드 열기`

**푸터**: 워드마크 `똑똑`, 태그라인 `지식이 똑똑 노크해요`, 링크(홈·탐색·릴스), 저작권 1줄.

### 카피 제약 (검증 대상)

- **화면에 보이는 문자열에 em-dash(`—`)·en-dash(`–`)를 쓰지 않는다.** 이 설계
  문서는 저장소 문체를 따라 쓰지만, 페이지 카피는 0개다. 하이픈이나 문장
  분리로 푼다.
- **눈속임 숫자 금지.** "293편"(§5.11 실측)은 위키문헌 *후보 목록* 크기지
  등록된 도서 수가 아니다. 오해를 부르므로 쓰지 않는다. 지표성 숫자는 아예
  넣지 않는다.
- 아이라이(eyebrow) 소문자 라벨 **0개**. 제목만으로 세운다.
- 스크롤 유도 문구(`Scroll`, `아래로`) 없음. 버전 표기·지역/시간 스트립 없음.
- CTA 라벨은 의도당 하나 — 앱 진입은 전부 `피드 열기`.

## 구현 규칙

- **서버 컴포넌트 기본.** `"use client"`는 필요한 leaf에만. 지금 설계에 상태가
  필요한 부분은 없다 — 가로 스트립은 CSS 스크롤 스냅으로 푼다.
- 모션: CSS `:hover`/`:active`/`focus-visible`만. 애니메이션 라이브러리를
  추가하지 않는다 (`motion`·`framer-motion`·`gsap` 모두 `package.json`에 없다).
  스크롤 이벤트 리스너를 붙이지 않는다.
- 아이콘은 `lucide-react`만 (이미 의존성). 손으로 SVG 경로를 그리지 않는다.
- 이미지는 `next/image` + `sizes`. 히어로 이미지에 `priority`.
- 터치 타깃 44×44px 이상, 포커스 링 유지.
- 반응형: 375px에서 단일 컬럼, `md:`(768) 이상에서 2컬럼, 컨테이너
  `max-w-6xl mx-auto`. 페이지 레벨 가로 스크롤 0.
- 메타데이터: `/about` 전용 `title`·`description`·OG 태그.
