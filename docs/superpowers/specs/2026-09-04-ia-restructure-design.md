# IA 개편 — 게시물 유형으로 탭 가르기

2026-09-04. 홈을 카드 피드로, 전면 숏폼을 릴스 탭으로 나눈다.

앞선 설계 `2026-09-02-comment-threads-design.md`가 "별건"으로 미뤄둔 작업이다.
그 문서의 결정 12(홈 상단 오버레이 바)는 **홈이 전면 피드라는 전제** 위에 서
있었고, 이 개편이 그 전제를 무너뜨린다. 그래서 이 문서는 앞 설계의 연장이
아니라 홈의 정체성을 다시 정하는 문서다.

## 왜 하는가

지금은 게시물 두 유형(`type='cards'` 템플릿 카드, `type='video'` 영상)이 한
전면 피드에 섞여 있다. 이 개편은 **유형을 탭으로 가른다** — 카드는 홈에서
카드답게, 영상은 릴스에서 영상답게 본다.

부수 효과로 두 탭의 내용이 겹치지 않는다. 논의 초기에는 "같은 게시물을
카드로"(홈과 릴스가 같은 게시물을 다른 형태로) 안을 검토했으나, 그러면 한
탭은 들어갈 이유가 없어진다는 문제가 남았다. 유형으로 가르면 그 문제가
사라진다.

## 정보 구조

| 탭 | 경로 | 내용 | 형태 |
|---|---|---|---|
| 홈 | `/` | `type='cards'` | 인스타 포스트형 카드, 일반 스크롤 |
| 릴스 | `/reels` | `type='video'` | 전면 스냅 (현재 홈 동작 그대로) |
| 탐색 | `/discover` | 변경 없음 | |
| 프로필 | `/profile` | 변경 없음 | |

GNB가 3칸에서 **4칸**이 된다.

경로 중 변하지 않는 것: `/p/[postId]`(공유 랜딩), `/notifications`,
`/channel/[slug]`, `/read/[bookId]`, `/login`, `/admin`.

## 결정 기록

### 1. 탭을 게시물 유형으로 가른다

홈 = `type='cards'`, 릴스 = `type='video'`. 한 게시물은 정확히 한 탭에만
나타난다.

`posts.type`이 이미 `'cards' | 'video'` 체크 제약으로 존재한다
(`20260827000001_init_schema.sql:109`). 새 분류 축을 만들지 않고 있는 것을
쓴다.

**대안이었던 것**: 두 탭이 같은 게시물을 다른 형태로 보여주는 안. 버린 이유는
내용이 100% 겹치면 "몰입해서 볼래?" 말고는 다른 탭에 들어갈 이유가 없고,
조회수가 두 탭에서 중복 집계되는 문제가 따라오기 때문이다.

### 2. 기본 탭은 홈(카드)

앱을 열면 카드 피드가 보인다.

**대가를 명시한다**: 북극성 지표인 숏폼→뷰어 전환을 이제 홈 카드가 짊어진다.
전면 몰입 경험이 기본 탭이 아니게 되므로, 카드의 읽기 CTA가 그 자리를 메울
만큼 강해야 한다(결정 4).

### 3. 홈 카드는 인스타 포스트형

위에서 아래로: 채널 헤더(아바타 + 채널명) → 미디어(카드 캐러셀, 하단 도트)
→ 액션 줄 → 도서 바(커버 + 제목 + 저자).

한 화면에 게시물 하나가 들어가는 크기다.

**대안이었던 것**:
- *도서 카드형* (커버 썸네일 + 훅 한 줄, 한 화면에 3~4개). 버린 이유는 공들여
  만드는 템플릿 카드 그림이 썸네일로 줄어들고, 탐색의 급상승 그리드와
  형태가 가장 가까워지기 때문이다.
- *전면 축소형* (현재 렌더러를 높이만 줄여 재사용). 구현이 가장 싸지만
  스냅만 뺀 현재 피드라 릴스 탭과 무엇이 다른지 설명하기 어렵다.

### 4. 읽기 CTA는 액션 줄 안에 글자 붙은 버튼으로

액션 줄은 `♥ 좋아요 · 💬 댓글 · ↗ 공유`가 왼쪽, **읽기**가 오른쪽 끝이다.
나머지가 아이콘인 것과 달리 채운 배경 + 글자를 준다.

동작은 §11-31을 그대로 따른다 — 전문 도서는 뷰어(`/read/[bookId]`) 직행,
링크형 도서는 같은 자리에서 도서 상세 시트. 유형 분기 로직은 이미 있다.

결정 2가 만든 부담을 여기서 갚는다. 전면 피드에서는 읽기가 채워진 원형
아이콘으로 위계를 잡았지만, 카드에서는 주변에 요소가 많아 아이콘만으로는
묻힌다.

### 5. 홈에 영상은 없다

카드 피드에 영상 게시물이 섞이지 않으므로 인라인 자동재생도, 뷰포트 기반
재생·정지 관리도, 스크롤 목록 안의 유튜브 iframe도 없다.

논의 중 "홈에 올라온 릴스는 음소거 자동재생" 안이 있었으나, 유형으로 탭을
가르기로 하면서 불필요해졌다.

### 6. 릴스는 현재 홈 동작을 그대로 옮긴다

전면 스냅 스크롤, 오버레이 크롬(우측 액션 레일, 하단 도서 정보 바), 영상
컨트롤 한 벌(`2026-09-02-video-controls-design.md`)을 그대로 쓴다.
`FeedScroller`가 릴스 전용 컴포넌트가 된다.

새로 만드는 것은 없다. `type='video'` 필터만 걸린다.

### 7. 채널 스코프 릴스 뷰어는 채널 페이지에서 들어간다

"그 채널의 영상만 위아래로 보는" 뷰어의 입구는 `/channel/[slug]`다. 채널
페이지는 이미 3열 게시물 그리드를 그리고 있어(`channel/[slug]/page.tsx:89`)
그 그리드의 영상 게시물을 탭하면 그 채널로 좁혀진 전면 뷰어가 열린다.

**입구가 여기인 이유**: 원래 구상은 홈 카드의 영상을 탭해 들어가는 것이었는데
결정 5로 홈에 영상이 없어졌다. 릴스 탭 안에서 채널 아바타로 전환하는 안도
있었으나, 전면 화면 안에서 데이터 소스가 바뀌면 뒤로가기·공유의 의미가
복잡해진다.

### 8. 상단 바 — 홈은 구조적 헤더, 릴스는 바 없음

홈은 스크롤되는 카드 목록이므로 목록 위에 붙는 sticky 헤더를 둔다(로고 +
알림 종 + 배지). 오버레이일 이유가 없다 — 오버레이였던 근거가 "전면 피드에
구조적 헤더를 넣으면 스냅 높이가 바뀐다"였는데, 홈이 더는 전면 피드가
아니다(§11-47이 이 상황을 재검토 대상으로 지목해 두었다).

릴스에는 상단 바를 두지 않는다. 알림 진입은 홈 헤더 하나로 충분하다.

### 9. 릴스 크롬은 4단계 이전으로 되돌린다

결정 8의 결과로 릴스에는 피할 상단 크롬이 없어진다. 따라서:

- `CHROME_SAFE_AREA`의 상단값을 `pt-16`(64px = 바 56 + 여유 8) →
  `pt-5`(20px, 순수 시각 여백)로 되돌린다.
- `post-item.tsx`의 상단 검정 스크림 96px(`rgb(0 0 0 / 0.38)`)을 제거한다.
  이 스크림은 흰색 고정 상단 바가 밝은 표지 위에서 읽히게 하려고 넣은 것이다.

**어제 만든 것을 되돌리는 것이 맞다.** 두 값의 근거는 "홈 = 전면 피드 + 상단
오버레이 바"였고 그 전제가 사라진다. 근거 없이 남은 수치는 다음 사람에게
거짓말이 된다.

하단 스크림 120px(`rgb(0 0 0 / 0.45)`)과 좌우·하단 세이프존은 그대로다 —
액션 레일과 도서 정보 바가 그대로 있기 때문이다.

### 10. 급상승 그리드는 게시물 상세로 보낸다

탐색의 급상승 그리드는 지금 "탭 시 해당 게시물부터 시작하는 피드로
진입"인데(§5.6), 피드가 둘로 갈리면 어느 피드인지가 모호해진다. `/p/[postId]`로
보낸다.

이미 있는 화면이고, 유형을 가리지 않으며, 공유 링크가 이미 가는 곳이고,
거기서 댓글·읽기 CTA가 다 동작한다.

**포기하는 것**: 급상승에서 들어가 그대로 다음 게시물로 흘러가는 맛. 가중
랜덤 정렬 + 세션 시드 + 키셋 커서로 도는 피드를 임의 게시물 위치에 맞추는
것은 상당한 작업이고, 그 게시물이 현재 시드의 정렬 창 안에 없을 수도 있다.

### 11. 조회 로깅을 홈 카드와 상세에도 붙인다

조회 로깅이 지금 `feed-scroller.tsx`에만 있어 **`/p/[postId]`는 조회를 세지
않는다**. 결정 10으로 급상승이 상세로 가게 되면서, 급상승 탭이 자기 재료를
못 먹이는 구멍이 드러난다.

"뷰포트에 1초 이상 노출되면 조회 1회" 규칙을 홈 카드와 상세에도 적용한다.
게시물 하나가 정확히 한 탭에만 있으므로(결정 1) 중복 집계는 없다.

**세는 단위는 게시물이다.** 카드 캐러셀을 좌우로 넘겨도 조회는 한 번이다 —
캐러셀 장수가 많은 게시물이 유리해지면 정렬이 편집 형식에 좌우된다.

### 12. 정렬은 손대지 않는다

가중 랜덤 × 인기(ln 상한) × 신선도 × seen_penalty, 세션 시드 고정, 키셋
커서 — 전부 그대로다. 랭킹 RPC에 **타입 인자만 추가**한다.

두 탭이 각각 자기 유형 안에서 같은 규칙으로 정렬된다.

**타입 인자는 널을 허용한다** — 널이면 지금처럼 전 유형을 섞어 돌려준다.
그래야 1단계에서 릴스를 먼저 세우는 동안 홈이 기존 동작을 그대로 유지한다.

## 단계

각 단계는 그 자체로 동작하는 소프트웨어를 낸다.

| 단계 | 내용 |
|---|---|
| 1 | 랭킹 RPC 타입 필터 + `/reels` 라우트 + GNB 4칸. 홈은 아직 그대로 |

| 2 | 홈을 카드 피드로 교체 (카드 컴포넌트, 읽기 CTA, 조회 로깅) |
| 3 | 상단 바 구조 전환 + 릴스 크롬 되돌리기 |
| 4 | 채널 스코프 릴스 뷰어 + 급상승 목적지 변경 |

1단계에서 릴스가 먼저 서면 홈을 바꾸는 동안에도 전면 피드가 살아 있다.

## 기록해 둘 한계

1. **릴스 탭이 얇을 수 있다.** 시드 기준 `cards` 8 : `video` 2다. 영상은 제작
   단가가 높은 쪽이라 GNB 한 칸을 채울 만큼 쌓이지 않으면 빈 탭처럼 보인다.
   콘텐츠 수급(§5.11)에 달렸고, 이 설계로는 해결되지 않는다.

2. **북극성 지표를 홈 카드가 짊어진다.** 숏폼→뷰어 전환이 전면 몰입에서
   나오던 것이 이제 카드의 읽기 버튼에서 나와야 한다. 개편 전후 전환율을
   비교할 때 이 단절을 감안해야 한다.

3. **홈과 탐색의 역할이 겹칠 수 있다.** 팔로우 그래프가 없어 홈은 "내가 고른
   것"이 아니라 "알고리즘이 고른 것"이고, 탐색도 같은 성격이다. 논의에서
   이 위험을 제기했고 감수하기로 했다.

4. **조회수의 의미가 또 한 번 바뀐다.** 결정 11로 홈 카드와 상세가 조회를
   세기 시작하면 총량이 늘어 개편 전 숫자와 직접 비교할 수 없다. 인기
   가중치에 ln 상한이 있어 순위는 덜 흔들리지만, 급상승 그리드는 직격이다.

5. **채널 스코프 뷰어는 채널 페이지에 의존한다.** 채널 페이지에 도달하는
   경로가 카드·릴스의 채널 아바타뿐이라, 그 아바타를 안 누르는 사용자에게는
   이 뷰어가 존재하지 않는 것과 같다.

## 안 하는 것

- 홈에 영상 인라인 자동재생
- 피드를 임의 게시물 위치에 맞추기
- 팔로우 그래프
- 탐색 화면 개편 (급상승 목적지 한 줄 외)
- 릴스 탭 상단 바
- 정렬 알고리즘 변경
