# 위키문헌 작품 목록 — 표에서 골라 가져오기 (설계)

## 문제

지금 위키문헌 임포트(`/admin/books/import`)는 관리자가 **위키문헌 문서 주소를 직접 찾아 붙여넣어야** 한다. 무엇을 가져올 수 있는지 앱 안에서 알 방법이 없어, 브라우저로 위키문헌을 따로 뒤진 뒤 돌아와야 한다. 저자와 카테고리도 손으로 적는다.

관리자가 원하는 것은 **가져올 수 있는 작품이 표로 먼저 보이고, 그중 하나를 골라 가져오는 것**이다. 표에 저자명·작품명·장르·출간일이 있고 검색·필터·정렬이 된다.

## 실측

설계 전에 위키문헌 API로 직접 확인했다(2026-09-08). 아래 숫자는 전부 실측이고, 설계 도중 **두 번 뒤집혔다.** 그 경위를 남기는 이유는 다음 사람이 같은 길을 되짚지 않게 하려는 것이다.

### 범위 — 소설 계열과 시집만 (사용자 결정)

분류 어휘를 조사하니 표본 596개에서 **48종**이 나왔고 드문 것 30종이 더 있었다. 처음 이 문서에 적었던 7종은 표본 몇 개로 추정한 것이고 **틀렸다.** 그중 상당수는 장르가 아니라 위키문헌 관리용 분류였다.

**목록에 담을 장르** — 소설 계열과 시집. 실측 개수:

| 분류 | 개수 | | 분류 | 개수 |
|---|---|---|---|---|
| 단편소설 | 186 | | 역사소설 | 21 |
| 장편소설 | 51 | | 소설 | 18 |
| 시집 | 50 | | 중편소설 | 13 |
| 한국의 소설 | 29 | | 신소설 | 13 |
| | | | 추리소설 | 1 |
| | | **합계(단순)** | 382 |
| | | **중복 제거** | **365** |

**17개가 둘 이상의 장르 분류에 속한다**(382 − 365). 그래서 장르를 하나만 고르는 규칙이 필요하다 — 아래 파싱 규칙의 우선순위.

**담지 않는 것과 이유:**

- **시 404 · 시조 256** — 낱편 시는 도서 한 권의 단위가 아니다. 우리 시 도서 4권은 전부 `시집`이다(진달래꽃 (시집)·님의 침묵·영랑시집·하늘과 바람과 별과 시)
- **수필 313 · 수필집 · 평론 · 논설문 · 동화 · 아동문학 · 희곡 · 서사시** — 범위 밖
- **친일문학 24** — 저작권과 무관하게 서비스에 싣지 않는다 (사용자 결정)
- **`하위 문서`** — 아래 별도 항목
- `일제 강점기의 시` 499+ · `대한민국의 시` · `대한제국의 시` — `시`의 시대별 하위 분류
- `Score 확장 기능을 사용하는 문서` 118 · `악보` 14 · `판독이 불가한 문자가 있는 작품` · `스캔으로 이동할 문헌` · `정리가 필요한 문서` · `오디오가 포함된 문서` · `복원된 문자가 있는 작품` · `중복된 인수를 사용한 틀의 호출을 포함한 문서` — 위키문헌 관리용 분류다

### 반드시 제외: `하위 문서` (장으로 쪼개진 문서)

장으로 나뉜 작품은 각 장이 별도 문서이고 `하위 문서` 분류가 붙는다.

우리 임포터는 **상위 문서 하나**를 지정하면 ws-export가 하위 장을 알아서 따라간다(`src/lib/wikisource.ts`의 설계 전제). 그래서 목록에 장이 뜨면 그것을 골라도 **1장만 들어온다** — 목록이 잘못된 선택을 유도한다.

규모는 범위에 따라 크게 다르다. PD 후보 전체(2,350개)에서는 **500개 이상**이지만, 소설 계열·시집으로 좁힌 365개 안에서는 **8개**다. 실측한 예: 「동인사담집 2/좌평 성충」·「동인사담집 4/임장군」·「전쟁과 평화/제 1권」.

수가 적어도 규칙은 유지한다 — 8개가 목록에 뜨면 8번의 잘못된 임포트를 유도한다.

### 뼈대 — 장르 분류를 긁고, 저작권 태그는 조건으로 쓴다

**여기서 판단이 두 번 바뀌었다.**

1차: 장르 분류를 뼈대로 삼으려 했다. 이미 등록된 16권으로 커버리지를 검증하니 **15/16**이었다 — 「홍염」의 분류는 `1927년 작품 / PD-old-70 / 연도 미입력 작품`뿐으로 장르가 없다. (첫 측정에서 태평천하·상록수·인간문제·꿈하늘도 누락됐는데 그건 `분류:장편소설`을 크롤 목록에서 빼먹은 실수였다. 더해도 「홍염」은 빠진다.)

2차: 그래서 저작권 태그(`PD-old-*`)를 뼈대로 바꿨다 — **16/16**이었다. 규모는 2,350개(PD-old-70 1,626 · PD-old-50 703 · PD-old-80 21, 중복 제거).

3차(최종): 범위를 **소설 계열과 시집으로 좁히기로 결정**되었으므로 어차피 장르로 걸러낸다. PD 뼈대는 2,350개를 긁어 대부분 버리는 낭비가 된다.

| 뼈대 | 후보 수 | 우리 16권 커버리지 |
|---|---|---|
| 저작권 태그 전체 | 2,350 | 16/16 |
| **소설 계열 + 시집** | **365** | **15/16** (「홍염」 누락) |

**장르 분류를 긁는다.** 「홍염」이 빠지는 것은 범위를 좁힌 대가이고, 주소 입력 화면이 그 경로다.

저작권 태그는 뼈대에서 **조건**으로 옮긴다: PD 태그가 없는 문서는 목록에서 제외한다. 번역물이 여기서 걸린다 — 「고향 (현진건 역)」은 PD 태그가 없다.

### 제외 규칙을 적용한 크기 — 최초 329개, 이후 293개로 재조정 (실측)

365개에 제외 규칙을 적용한 결과 (최초 설계, 2026-09-08):

| 단계 | 수 |
|---|---|
| 소설 계열 + 시집 (중복 제거) | 365 |
| − `하위 문서` (장) | 8 |
| − `친일문학` | 2 (「일장기의 물결」·「성암의 길」) |
| − PD 태그 없음 | 26 |
| **목록에 남는 것 (최초)** | **329** |

번역물은 위 계산에 들어 있지 않았다. 당시 판단은 **번역물은 표에서 빼지 않는다** — `translator`에 기록해 두고 목록 화면에서만 숨긴다(아래 「화면」)였다. 대개 PD 태그가 없어 위 26에서 이미 걸리므로, 표에 남는 번역물은 소수라고 봤다.

**개정 (2026-09-09, 브랜치 전체 검토):** 저작권 태그(`PD-old-*`)는 위키문헌의 판단일 뿐 PRD §5.11(저작자 1962년 이전 사망)을 직접 구현하지 않는다는 것이 드러났다 — 329편 중 8편이 실제로는 그 기준에 미달한 채 목록에 보이고 있었다. 저자 문서(`저자:이름`)의 사망 연도·국적을 직접 읽어 판정을 추가하고, PD 태그 정규식도 `PD-old-*`로 좁히자(「파초」의 `PD-공유마당`, 「자유종」의 `PD-old-95-US`가 새로 걸림) 표는 다시 줄어 **293개**가 됐다:

| 단계 | 수 |
|---|---|
| 소설 계열 + 시집 (중복 제거) | 365 |
| − `하위 문서` | 8 |
| − `친일문학` | 2 |
| − PD 태그 없음 (`PD-old-*`로 좁힌 뒤) | 28 |
| − 저자 불명 (머리말에 저자가 없음) | 1 |
| − 저자 문서 없음 | 2 |
| − 해외 저자 | 10 |
| − 북한 저자 | 20 |
| − 사망 연도 불명 | 1 |
| − 저자 확인 불가 (발표 연도가 저자 생애 밖 — 엉뚱한 저자 문서를 물었을 때의 방어선) | 0 |
| **표에 담을 것 (현재)** | **293** |

`node --env-file=.env scripts/check-table.mjs wikisource_works`로 재확인했다(2026-09-09). 전체 경위는 `docs/superpowers/plans/2026-09-08-wikisource-catalogue.md`의 「개정 — 브랜치 전체 검토가 찾은 Critical 결함」절에 있다.

**번역물을 표에서 숨기는 이유도 바뀌었다.** 처음에는 "번역물은 표에서 빼지 않는다 — `translator`에 기록해 두고 목록 화면에서만 숨긴다"가 전부였다. 지금은 그 화면 숨김이 실제로는 거의 발동하지 않는다: 번역물은 원작자가 외국인이라(예: 「전쟁과 평화」→ 레프 톨스토이) 위 「해외 저자」 단계에서 저자 검사가 먼저 걸러낸다 — 293개 표에는 번역물이 0건이다. **그렇다고 화면의 숨김 로직과 `translator` 컬럼을 지우지는 않는다.** 한국인이 이미 만료된 한국 저자의 작품을 번역한 경우(원저자 검사를 그대로 통과하는 경우)는 여전히 이론상 가능하고, `translator`는 그런 행을 구별하는 유일한 표시이기 때문이다. 다만 "왜 이 작품이 목록에 없나"라는 질문에는 이제 동기화 보고의 사유(위 표)가 먼저 답한다 — 화면 숨김은 저자 검사를 통과한 뒤에도 남는 마지막 방어선일 뿐이다.

**판정은 여전히 두 층이다.** 표에 담을지(동기화 — `isCandidate` + `checkAuthor` + `eraConsistent`)와 목록에 보일지(화면 — `isListable`)는 다른 질문이라는 원래 논거는 그대로 유효하다: 표에서 지우면 "왜 이 작품이 목록에 없나"에 답할 수 없다. 다만 그 답을 주로 담당하는 계층이 바뀌었다 — 지금은 동기화 스크립트의 사유별 집계가 그 답의 대부분이고, 화면의 `isListable`이 실제로 걸러내는 것은 금지 저작자(예: 정지용 3편, 지금도 표에는 남고 화면에서만 가려진다)뿐이다.

### 작품마다 붙는 메타데이터

`prop=categories` 실측:

```
운수 좋은 날  →  1924년 작품 / PD-old-50 / 단편소설
님의 침묵     →  1926년 작품 / PD-old-70 / 시집
태평천하      →  1938년 작품 / PD-old-50 / 장편소설
홍염          →  1927년 작품 / PD-old-70 / 연도 미입력 작품
```

- **출간 연도**: `NNNN년 작품`. 「상록수」처럼 둘이 붙은 경우가 있다(`1935년 작품 / 1936년 작품`) → 가장 이른 연도
- **장르**: 위 표의 9종. 둘 이상 붙을 수 있다(17건)
- **저작권 태그**: `PD-old-50`·`PD-old-70`·`PD-old-80`
- 데이터 품질 표시: `연도 미입력 작품`

### 저자는 본문 `머리말` 틀에서 나온다

`prop=revisions`로 위키텍스트를 받아 파싱한다. 실측한 형태:

```
{{머리말
|제목 = 운수 좋은 날
|지은이 = [[저자:현진건|현진건]]
|역자 =
|부제 =
}}
```

**항목 값은 줄바꿈으로 끝난다.** 이 사실이 파싱 규칙을 지배한다.

- 저자 항목 이름이 **둘**이다: `저자`(표본 30개 중 23)와 `지은이`(7). 둘 다 봐야 한다
- 값은 `[[저자:현진건|현진건]]` — 링크의 표시명(파이프 뒤)을 쓰고 없으면 대상명
- **`역자`가 채워져 있으면 번역물**이다

**파싱을 세 번 틀렸다. 이유를 규칙으로 남긴다:**

1. `[^|}\n]*`로 값을 끊으면 `[[저자:현진건|현진건]]` **안의 파이프에서 잘려** `[[저자:현진건`이 된다
2. `\s*`는 **줄바꿈까지 먹는다.** 값이 빈 항목(`|역자 =`)에서 다음 줄 `|부제 = `를 값으로 끌어와, 99개 중 60개가 번역물로 오판됐다
3. 정답: 줄 단위로 읽고 `=` 주변은 `[ \t]*`만 허용한다

```js
const AUTHOR     = /^[ \t]*\|[ \t]*(?:저자|지은이)[ \t]*=[ \t]*(.*)$/m;
const TRANSLATOR = /^[ \t]*\|[ \t]*역자[ \t]*=[ \t]*(.*)$/m;
const TITLE      = /^[ \t]*\|[ \t]*제목[ \t]*=[ \t]*(.*)$/m;
const LINK       = /\[\[(?:저자:)?([^|\]]+)(?:\|([^\]]*))?\]\]/;
```

**검증 (99개 표본):** 저자 추출 **98/99**. 실패는 「강촌 (두보)」 — 두보 한시로 다른 틀을 쓴다. 번역물 **1건 검출**: 「가던 길 멈춰서 — 저자 윌리엄 데이비스 / 역자 pk0001」, 영시를 위키문헌 사용자가 번역한 것으로 PRD §5.11이 "원작이 만료여도 번역본은 별개"라 규정한 정확히 그 경우다.

### 레이트 리밋이 세다 — 두 번 차단당했다

1차: 50개 묶음 + `cllimit=500` + 120ms 간격 → `You are making too many requests to the API.`

2차: 20개 묶음 + 1초 간격 → 표본 단계에서만 백오프 **11번**

3차: 20개 묶음 + 2초 간격 → **여전히 걸렸다**

하루 동안 반복 조회한 누적 할당량일 가능성도 있다. 어느 쪽이든 동기화 스크립트는 이 전제로 설계해야 한다.

## 설계

### 후보 목록을 우리 DB에 둔다

365개를 화면 열 때마다 긁으면 요청이 20회 필요하고, 위 레이트 리밋 때문에 분 단위로 걸린다. 검색·정렬·필터도 위키문헌 API로는 할 수 없다. **후보를 우리 표에 담고 화면은 우리 DB만 읽는다.**

`supabase/migrations/<다음 번호>_wikisource_works.sql` — **번호는 작업 시점에 `ls supabase/migrations/ | tail -1`로 확인한다.** master가 활발히 움직여 이 문서 작성 시점(마지막 `20260907000001`)과 달라질 수 있다.

```sql
create table public.wikisource_works (
  page_title  text primary key,   -- 위키문헌 문서 제목. books.source_ref와 같은 형식
  title       text not null,      -- 표시용 제목 (머리말의 제목, 없으면 page_title)
  author      text,               -- 머리말 저자|지은이. 파싱 실패 시 null
  genre       text not null,       -- 소설 계열 또는 시집. 이 표에 있는 근거이므로 not null
  pub_year    int,                -- 분류 "NNNN년 작품" 중 가장 이른 것
  pd_tag      text not null,      -- PD-old-50 등. 없는 문서는 담지 않으므로 not null
  translator  text,               -- 역자. null이 아니면 번역물
  synced_at   timestamptz not null default now()
);

create index wikisource_works_genre_idx  on public.wikisource_works (genre);
create index wikisource_works_author_idx on public.wikisource_works (author);
create index wikisource_works_year_idx   on public.wikisource_works (pub_year);
```

`page_title`이 기본 키다. 위키문헌 문서 하나가 후보 하나이고, `books.source_ref`와 바로 짝지어 "이미 등록됨"을 판정한다. **두 값은 반드시 같은 정규화를 거친다** — `src/lib/wikisource.ts`의 `toPageTitle`. 형식이 어긋나면 등록 여부 판정이 조용히 깨진다.

`translator`를 담는데 목록에서는 숨긴다. 이유: 동기화가 판정을 기록해 두면 나중에 "왜 이 작품이 목록에 없나"를 DB에서 답할 수 있다. 지우면 그 질문에 답할 수 없다.

RLS는 `books`의 형태를 따르되 읽기를 공개하지 않는다 — 어드민 전용 후보 목록이다:

```sql
alter table public.wikisource_works enable row level security;

create policy "wikisource_works_admin_read" on public.wikisource_works
  for select using (public.is_admin());
```

쓰기 정책은 두지 않는다. 동기화 스크립트가 유일한 필자이고 service role은 RLS를 우회한다.

### 동기화 스크립트

`scripts/sync-wikisource-works.mjs` / `npm run wikisource:sync`

1. 장르 분류 9개를 `categorymembers`로 나열(namespace 0, `cmcontinue`로 이어받기). 중복 제거하면 실측 **365개**, 요청 9회
2. 제목을 **20개씩 묶어** `prop=categories`와 `prop=revisions`를 요청 — 배치 19개 × 2속성 = 약 **38회**
3. 분류에서 장르·연도·PD 태그를, 위키텍스트에서 제목·저자·역자를 뽑는다
4. **표에서 제외**: 범위 밖 장르 / `하위 문서` / `친일문학` / PD 태그 없음 / 저자 불명(머리말에 저자가 없음)
5. **저자 문서로 권리를 판정한다** (개정, 2026-09-09): 후보에 남은 서로 다른 저자마다 `저자:이름` 문서의 분류를 한 번씩 받아(요청 약 4회) 사망 연도·국적을 읽고, PRD §5.11(1962년 이전 사망)을 직접 적용한다 — 저자 문서 없음 / 해외 저자 / 북한 저자 / 사망 연도 불명 / 1962년 이후 사망 / 저자 확인 불가(발표 연도가 저자 생애 밖)가 여기서 걸린다. **번역물은 별도 사유로 제외하지 않는다** — 원저자가 이 검사들을 통과하면 표에 남고 `translator`에 기록되며, 화면의 `isListable`이 마지막 숨김을 맡는다. 다만 원저자가 외국인인 경우가 대부분이라 대개 「해외 저자」에서 먼저 걸린다
6. `page_title` 기준 upsert. 위키문헌에서 사라졌거나 제외 조건에 걸리게 된 문서는 표에서 지운다
7. 보고: 신규 / 갱신 / 삭제 / 제외(사유별, 10종) / 저자를 못 읽은 작품 목록 / 저자별 거부 내역 / 표에 남은 번역물 수

`--dry-run`을 지원한다 — 쓰기 없이 무엇이 바뀔지만 보고한다. **이 프로젝트는 개발용 DB가 따로 없어 스크립트가 곧 운영을 바꾼다.** 쓰기 전에 확인할 수단이 반드시 있어야 한다.

**속도 조절** (위 실측을 근거로):

- `User-Agent`는 식별 가능한 값 (기존 수급과 동일)
- **순차 요청**, 병렬화 금지
- 요청 사이 **최소 2초**
- 묶음 크기 **20개**
- 제한 응답이면 **10초 → 20초 → 30초 → 40초 → 50초 백오프로 최대 5회 재시도**
- 총 요청 약 **51회**(작품 메타 47 + 저자 문서 조회 4, 2026-09-09 저자 판정 추가로 47에서 늘었다) × 2초 ≈ **2분**, 백오프가 걸리면 더 길어진다. 사람이 드물게 돌리는 스크립트라 무해하다

2. **번역물** — `translator`가 있는 것. PRD §5.11: 원작이 만료여도 번역본은 별개다. **다만 2026-09-09 개정 이후에는 이 조건이 거의 발동하지 않는다** — 번역물의 원저자는 대개 외국인이라 위 「동기화 스크립트」 5단계의 「해외 저자」 검사가 표 단계에서 먼저 걸러낸다(293개 표에 번역물 0건). 조건 자체는 지우지 않는다 — 한국인이 만료된 한국 저자를 번역한 경우까지는 저자 검사로 잡을 수 없어서다

`[ ] 등록 불가 포함해서 보기`를 켜면 회색으로 이유와 함께 보인다. 기본은 꺼짐.

### 한 번에 가져오기

표에 저자와 장르가 이미 있으므로 `가져오기`는 **입력 없이** 동작한다. 각 행이 `page_title`·`author`·`category`를 서버 액션에 제출한다.

**개정 (2026-09-09):** 원래 이 자리에는 "저자가 비어 있는 행은 숨기지 않는다 — 저자 칸을 `—`로 두고 `가져오기`를 누르면 기존 임포트 화면으로 보내 저자를 입력받는다"고 적혀 있었다. **판단이 뒤집혔다.** 저자는 사망 연도·국적·금지 명단 세 검사의 입구다 — 저자를 모르면 셋 다 판정할 수 없고, 그러면 기계가 아무것도 보증하지 못하는 행을 "가져올 수 있는 목록"에 두는 셈이 된다. 그래서 지금은 **저자를 못 읽은 작품을 표에 아예 담지 않는다**(동기화 스크립트 4단계). 어휘 부족 문제를 고친 뒤 이 경우는 329편 중 1편(「모비딕」, 머리말 틀 자체가 없다)뿐이다. 그런 작품은 이 목록에 나타나지 않고, 「남기는 것」 절의 주소 입력 화면(`/admin/books/import`)에서 사람이 저자를 직접 입력한다 — 그 입력에는 여전히 금지 명단 검사(`blockedAuthorReason`)가 걸린다.

**장르 이름을 우리 것으로 옮긴다.** 위키문헌은 `단편소설`이라 부르고 `books.category`는 `소설`을 쓴다(실측: 기존 16권이 `소설` 12 · `시` 4):

| 위키문헌 장르 | `books.category` |
|---|---|
| 단편소설, 중편소설, 장편소설, 소설, 한국의 소설, 역사소설, 신소설, 추리소설 | 소설 |
| 시집 | 시 |

범위를 좁힌 결과 **`books.category`에 새 값이 생기지 않는다** — 기존 `소설`·`시` 둘로 전부 덮인다. (앞선 판본에서 `수필`·`희곡`을 새로 도입하려 했으나 그 장르들이 범위에서 빠졌다.)

기존 안전장치는 **그대로 지난다** — 금지 저작자 검사, 중복 검사, `assertClean`(빈 껍데기·껍데기 잔여·태그 균형). 목록에서 걸러도 가져오기 시점의 검사를 없애지 않는다: 목록은 동기화 시점의 스냅숏이고, 게이트는 실제 파일을 본다.

### 금지 저작자 명단을 공용 모듈로

지금 명단이 `books/import/actions.ts` 안의 모듈 private `Map`이다. 그 파일은 `"use server"`라 export가 전부 서버 액션이 되므로 목록 화면이 쓸 수 없다.

`src/lib/book-rights.ts`로 옮긴다 — 명단, 이름 정규화(NFC + zero-width 제거), 조회 함수. 임포트 액션과 목록 화면이 **같은 명단**을 본다. 두 벌이 되면 한쪽만 고쳐진다.

## 테스트

이 저장소의 정책은 **순수 함수만**이다(`vitest.config.ts`: Supabase 빌더 모킹 금지, 환경은 node).

`src/lib/wikisource-meta.ts` + `src/lib/wikisource-meta.test.ts`:

- `parseHeader(wikitext)` → `{ title, author, translator }`
  - `저자`와 `지은이` 둘 다 인식
  - `[[저자:현진건|현진건]]` → `현진건`, `[[저자:현진건]]` → `현진건`
  - **빈 `|역자 =` 다음 줄의 `|부제 = `를 값으로 끌어오지 않는다** (실제로 틀렸던 경우)
  - 머리말 틀이 없으면 전부 null (「강촌 (두보)」)
- `parseCategories(categories[])` → `{ genre, pubYear, pdTag, isSubpage, isCollaborationist }`
  - `1924년 작품` → 1924. 둘이면 **가장 이른 것**(「상록수」: 1935/1936 → 1935)
  - 장르가 여러 개면(실측 17건) 우선순위로 하나를 고른다: 장편소설 → 중편소설 → 단편소설 → 역사소설 → 신소설 → 추리소설 → 한국의 소설 → 소설 → 시집
  - 범위 밖 장르만 있으면 genre는 null → 후보에서 제외
  - `하위 문서` → `isSubpage`, `친일문학` → `isCollaborationist`
  - `PD-old-*` → pdTag. 없으면 null → 제외
- `toBookCategory(genre)` → `소설` 또는 `시`
- `isCandidate({genre, pdTag, isSubpage, isCollaborationist})` → boolean — **표에 담을지의 첫 관문**을 판정한다. 장르·하위 문서·친일문학·PD 태그, 이 네 가지만 본다
- `checkAuthor(info)` · `eraConsistent(pubYear, info)` (개정, 2026-09-09) — 저자 문서의 사망 연도·국적으로 §5.11을 직접 구현한다. **표에 담을지의 두 번째 관문**이고, `isCandidate`와 합쳐야 "표에 담을지"의 전부가 된다 — 브랜치 전체 검토가 찾은 문제는 정확히 이 관문 없이 PD 태그만 보고 있었던 것이다
- `isListable({author, translator})` → `{ ok, reason }` — **목록에 보일지** 판정한다(위 두 관문을 통과한 행에만 적용). 금지 저작자는 여전히 표에 남고 화면에서만 숨는다(저자 문서 기준으로는 명단을 대체할 수 없다 — 정지용이 실측 예). 번역물도 검사는 남아 있지만 원저자가 대개 해외 저자 검사에서 먼저 걸려, 293개 표 기준으로는 이 조건에 걸리는 행이 없다. 판정을 표/화면 두 층으로 나누는 이유는 그대로다 — 한 함수에 섞으면 표에서 지워야 할 것과 가려야 할 것이 구별되지 않는다

픽스처는 **실측한 실제 위키텍스트·분류 모양**을 쓴다. 단순화한 픽스처가 위 세 파싱 오류를 하나도 못 잡았다.

## 알려진 한계

- **범위를 좁힌 대가**: 「홍염」처럼 장르 분류가 없는 작품, 수필·시 낱편, PD 태그 없는 문서는 목록에 없다. 주소 입력 화면이 그 경로다
- **`PD-old-*`는 위키문헌의 판단이고 우리 기준과 다르다.** 우리 기준은 PRD §5.11의 한국 저작권법(1962년 이전 사망)이다. **2026-09-09부터는 이 기준을 저자 문서의 사망 연도·국적으로 직접 구현한다**(`checkAuthor`) — 태그는 여전히 **후보를 모으는 그물**일 뿐 등록 허가가 아니지만, 더 이상 그물이 곧 판정도 아니다. 손으로 쓴 금지 목록은 그 태그와도, 이 기계 판정과도 무관하게 따로 있다 — 「저자:정지용」이 기계 판정은 통과하고(1950년 사망, 북한 분류 없음) 명단으로만 막히는 실제 사례다. 「저자:박태원」·「저자:홍명희」는 저자 문서 자체가 없어 기계 판정으로도 걸리지만, 위키문헌 쪽 사정에 기대는 것이라 명단은 그대로 둔다
- **목록은 동기화 시점의 스냅숏이다.** `synced_at`을 화면에 적는다
- **빈 껍데기는 목록에서 알 수 없다.** 「감자」는 분류상 정상 단편소설이지만 ws-export가 본문 2자만 내준다(기존 실측). 가져오기 시점의 `MIN_BODY_CHARS` 검사가 잡는다
