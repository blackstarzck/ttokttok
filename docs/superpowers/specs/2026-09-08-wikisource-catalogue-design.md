# 위키문헌 작품 목록 — 표에서 골라 가져오기 (설계)

## 문제

지금 위키문헌 임포트(`/admin/books/import`)는 관리자가 **위키문헌 문서 주소를 직접 찾아 붙여넣어야** 한다. 무엇을 가져올 수 있는지 앱 안에서 알 방법이 없어, 브라우저로 위키문헌을 따로 뒤진 뒤 돌아와야 한다. 저자와 카테고리도 손으로 적는다.

관리자가 원하는 것은 **가져올 수 있는 작품이 표로 먼저 보이고, 그중 하나를 골라 가져오는 것**이다. 표에 저자명·작품명·장르·출간일이 있고 검색·필터·정렬이 된다.

## 실측 — 데이터가 실제로 있는가

설계 전에 위키문헌 API로 직접 확인했다(2026-09-08). 아래 숫자는 전부 실측이다.

### 무엇을 뼈대로 긁을 것인가 — 저작권 태그

처음에는 장르 분류(`분류:단편소설` 등)를 뼈대로 삼으려 했다. **틀렸다.** 이미 등록된 16권으로 커버리지를 검증한 결과:

| 크롤 기준 | 기존 16권 중 잡히는 것 |
|---|---|
| 장르 분류 (`장편소설` 포함) | **15/16** — 「홍염」 누락 |
| **저작권 태그 (`PD-old-*`)** | **16/16** |

「홍염」의 분류는 `1927년 작품 / PD-old-70 / 연도 미입력 작품`뿐이다 — 장르가 없다. 장르 분류를 뼈대로 쓰면 이런 작품이 목록에서 사라진다. (처음 측정에서 「태평천하」·「상록수」·「인간문제」·「꿈하늘」도 누락됐는데, 그건 `분류:장편소설`을 크롤 목록에서 빼먹은 내 실수였다. 그걸 더해도 「홍염」은 여전히 빠진다.)

**저작권 태그를 뼈대로 삼는다.** 우리가 찾는 것은 "위키문헌이 공개 저작물로 판단한 문서"이고, 그것이 곧 등록 후보다. 덤으로 번역물이 자연히 빠진다 — 「고향 (현진건 역)」은 PD 태그가 없다.

규모:

| 분류 | 문서 수 |
|---|---|
| PD-old-70 | 1,626 |
| PD-old-50 | 703 |
| PD-old-80 | 21 |
| **중복 제거 합계** | **2,350** |

### 작품마다 붙는 메타데이터

`prop=categories` 실측:

```
운수 좋은 날  →  1924년 작품 / PD-old-50 / 단편소설
님의 침묵     →  1926년 작품 / PD-old-70 / 시집
태평천하      →  1938년 작품 / PD-old-50 / 장편소설
홍염          →  1927년 작품 / PD-old-70 / 연도 미입력 작품
```

- **출간 연도**: `NNNN년 작품`. 「상록수」처럼 두 개가 붙은 경우가 있다(`1935년 작품 / 1936년 작품`) → 가장 이른 연도를 쓴다
- **장르**: `단편소설`·`장편소설`·`시집`·`시`·`수필`·`소설`·`희곡`. **없을 수 있다**(「홍염」)
- **저작권 태그**: `PD-old-50`·`PD-old-70`·`PD-old-80`
- 데이터 품질 표시: `연도 미입력 작품`

표본에서 장르 분류가 두 개 이상 붙은 문서는 없었다. 그래도 결정적으로 고르기 위해 우선순위를 둔다(아래 파싱 규칙).

### 저자는 본문 `머리말` 틀에서 나온다

`prop=revisions`로 위키텍스트를 받아 파싱한다. 실측한 형태:

```
{{머리말
|제목 = 운수 좋은 날
|지은이 = [[저자:현진건|현진건]]
|역자 =
|부제 =
}}
```

**항목 값은 줄바꿈으로 끝난다.** 이 사실이 파싱 규칙을 지배한다.

- 저자 항목 이름이 **둘**이다: `저자`(표본 30개 중 23) 와 `지은이`(7). 둘 다 봐야 한다
- 값은 `[[저자:현진건|현진건]]` — 링크의 표시명(파이프 뒤)을 쓰고 없으면 대상명을 쓴다
- **`역자`가 채워져 있으면 번역물**이다

**파싱을 세 번 틀렸다. 이유를 규칙으로 남긴다:**

1. `[^|}\n]*`로 값을 끊으면 `[[저자:현진건|현진건]]` **안의 파이프에서 잘려** `[[저자:현진건`이 된다
2. `\s*`는 **줄바꿈까지 먹는다.** 값이 빈 항목(`|역자 =`)에서 다음 줄 `|부제 = `를 값으로 끌어와, 99개 중 60개가 번역물로 오판됐다
3. 정답: 줄 단위로 읽고 `=` 주변은 `[ \t]*`만 허용한다

```js
const AUTHOR     = /^[ \t]*\|[ \t]*(?:저자|지은이)[ \t]*=[ \t]*(.*)$/m;
const TRANSLATOR = /^[ \t]*\|[ \t]*역자[ \t]*=[ \t]*(.*)$/m;
const TITLE      = /^[ \t]*\|[ \t]*제목[ \t]*=[ \t]*(.*)$/m;
const LINK       = /\[\[(?:저자:)?([^|\]]+)(?:\|([^\]]*))?\]\]/;
```

**검증 (99개 표본):** 저자 추출 **98/99**. 실패는 「강촌 (두보)」 — 두보 한시로 다른 틀을 쓴다. 번역물 **1건 검출**: 「가던 길 멈춰서 — 저자 윌리엄 데이비스 / 역자 pk0001」, 영시를 위키문헌 사용자가 번역한 것으로 PRD §5.11이 "원작이 만료여도 번역본은 별개"라 규정한 정확히 그 경우다.

## 설계

### 후보 목록을 우리 DB에 둔다

2,350개를 화면 열 때마다 긁으면 요청이 100회 필요하다. 검색·정렬·필터도 위키문헌 API로는 할 수 없다. **후보를 우리 표에 담고 화면은 우리 DB만 읽는다.**

`supabase/migrations/<다음 번호>_wikisource_works.sql` — **번호는 작업 시점에 `ls supabase/migrations/ | tail -1`로 확인한다.** master가 활발히 움직여 이 문서 작성 시점(마지막 `20260907000001`)과 달라질 수 있다.

```sql
create table public.wikisource_works (
  page_title  text primary key,   -- 위키문헌 문서 제목. books.source_ref와 같은 형식
  title       text not null,      -- 표시용 제목 (머리말의 제목, 없으면 page_title)
  author      text,               -- 머리말 저자|지은이. 파싱 실패 시 null
  genre       text,               -- 분류에서. 없을 수 있다
  pub_year    int,                -- 분류 "NNNN년 작품" 중 가장 이른 것
  pd_tag      text not null,      -- PD-old-50 등. 이 표에 있는 근거이므로 not null
  translator  text,               -- 역자. null이 아니면 번역물
  synced_at   timestamptz not null default now()
);

create index wikisource_works_genre_idx  on public.wikisource_works (genre);
create index wikisource_works_author_idx on public.wikisource_works (author);
create index wikisource_works_year_idx   on public.wikisource_works (pub_year);
```

`page_title`이 기본 키다. 위키문헌 문서 하나가 후보 하나이고, `books.source_ref`와 바로 짝지어 "이미 등록됨"을 판정한다. **두 값은 반드시 같은 정규화를 거친다** — `src/lib/wikisource.ts`의 `toPageTitle`. 형식이 어긋나면 등록 여부 판정이 조용히 깨진다.

RLS는 `books`의 형태를 따르되 읽기를 공개하지 않는다 — 어드민 전용 후보 목록이다:

```sql
alter table public.wikisource_works enable row level security;

create policy "wikisource_works_admin_read" on public.wikisource_works
  for select using (public.is_admin());
```

쓰기 정책은 두지 않는다. 동기화 스크립트가 유일한 필자이고 service role은 RLS를 우회한다.

### 동기화 스크립트

`scripts/sync-wikisource-works.mjs` / `npm run wikisource:sync`

1. `PD-old-50`·`PD-old-70`·`PD-old-80`을 `categorymembers`로 나열(namespace 0, `cmcontinue`로 이어받기). 실측 7회 요청
2. 제목을 **50개씩 묶어** `prop=categories`와 `prop=revisions`를 요청. 실측 약 94회
3. 분류에서 장르·연도를, 위키텍스트에서 제목·저자·역자를 뽑는다
4. `page_title` 기준 upsert. 위키문헌에서 사라진 문서는 표에서도 지운다
5. 보고: 신규 / 갱신 / 삭제 / 저자 추출 실패 수

`--dry-run`을 지원한다 — 쓰기 없이 무엇이 바뀔지만 보고한다. **이 프로젝트는 개발용 DB가 따로 없어 스크립트가 곧 운영을 바꾼다.** 쓰기 전에 확인할 수단이 반드시 있어야 한다.

`User-Agent`는 기존 수급과 같은 식별 가능한 값을 쓴다(위키문헌 API 예절). 요청을 **순차로** 보내고 사이에 짧은 간격을 둔다 — 101회를 한꺼번에 던지는 것은 무료로 쓰는 남의 서비스에 대한 예의가 아니고, 차단당하면 기능 자체가 죽는다. 병렬화는 하지 않는다: 이 스크립트는 사람이 드물게 돌리는 것이라 몇 분 걸려도 무해하다.

### 화면

`/admin/books/wikisource` — 서버 컴포넌트. 검색·필터·정렬 상태는 **주소에 담는다**(FRONTEND.md §4: URL 상태 = searchParams).

| 컬럼 | 정렬 | 내용 |
|---|---|---|
| 작품명 | ✓ | `title`. 기본 정렬 |
| 저자 | ✓ | `author`. 없으면 `—` |
| 장르 | ✓ | `genre`. 없으면 `—` |
| 출간 | ✓ | `pub_year`. 없으면 `—` |
| 상태 | | `✓ 등록됨` 또는 `가져오기` |

- **검색** `?q=` — 작품명·저자 부분 일치
- **필터** `?genre=` `?year=` — 장르, 연도(10년 단위)
- **정렬** `?sort=&dir=`
- **페이지** `?page=` — 50개씩. 2,350행을 한 번에 그리지 않는다
- **`[ ] 등록된 것 숨기기`**
- `synced_at`을 화면에 적는다 — 언제 기준의 목록인지 보여야 한다

**목록에서 숨기는 것** (사용자 결정: 보이는 목록은 곧 가져올 수 있는 목록이어야 한다):

1. **금지 저작자의 작품** — PRD §5.11 등록 금지 목록 7명
2. **번역물** — `translator`가 있는 것

`[ ] 등록 불가 포함해서 보기`를 켜면 회색으로 이유와 함께 보인다. 기본은 꺼짐.

### 한 번에 가져오기

표에 저자와 장르가 이미 있으므로 `가져오기`는 **입력 없이** 동작한다. 각 행이 `page_title`·`author`·`category`를 서버 액션에 제출한다.

**저자가 비어 있는 행**(「강촌 (두보)」 같은 경우)은 숨기지 않는다. 저자 칸을 `—`로 두고, `가져오기`를 누르면 기존 임포트 화면으로 보내 저자를 입력받는다.

**장르 이름을 우리 것으로 옮긴다.** 위키문헌은 `단편소설`이라 부르고 `books.category`는 `소설`을 쓴다(실측: 기존 16권이 `소설` 12 · `시` 4):

| 위키문헌 장르 | `books.category` |
|---|---|
| 단편소설, 장편소설, 중편소설, 소설 | 소설 |
| 시, 시집 | 시 |
| 수필 | 수필 |
| 희곡 | 희곡 |
| (그 외 / 없음) | null → 임포트 화면에서 입력 |

`수필`·`희곡`은 `books.category`에 없던 새 값이다. 그 컬럼은 자유 입력이라 제약은 없지만, 도입한다는 사실을 PRD §5.10에 한 줄로 남긴다.

기존 안전장치는 **그대로 지난다** — 금지 저작자 검사, 중복 검사, `assertClean`(빈 껍데기·껍데기 잔여·태그 균형). 목록에서 걸러도 가져오기 시점의 검사를 없애지 않는다: 목록은 동기화 시점의 스냅숏이고, 게이트는 실제 파일을 본다.

### 금지 저작자 명단을 공용 모듈로

지금 명단이 `books/import/actions.ts` 안의 모듈 private `Map`이다. 그 파일은 `"use server"`라 export가 전부 서버 액션이 되므로 목록 화면이 쓸 수 없다.

`src/lib/book-rights.ts`로 옮긴다 — 명단, 이름 정규화(NFC + zero-width 제거), 조회 함수. 임포트 액션과 목록 화면이 **같은 명단**을 본다. 두 벌이 되면 한쪽만 고쳐진다.

## 남기는 것

**주소 입력 화면(`/admin/books/import`)을 남긴다.** PD 태그가 없는 문서는 목록에 뜨지 않는다. 목록 화면에 링크를 둔다: "목록에 없는 작품은 주소로 직접".

## 테스트

이 저장소의 정책은 **순수 함수만**이다(`vitest.config.ts`: Supabase 빌더 모킹 금지, 환경은 node).

`src/lib/wikisource-meta.ts` + `src/lib/wikisource-meta.test.ts`:

- `parseHeader(wikitext)` → `{ title, author, translator }`
  - `저자`와 `지은이` 둘 다 인식
  - `[[저자:현진건|현진건]]` → `현진건`, `[[저자:현진건]]` → `현진건`
  - **빈 `|역자 =` 다음 줄의 `|부제 = `를 값으로 끌어오지 않는다** (실제로 틀렸던 경우)
  - 머리말 틀이 없으면 전부 null (「강촌 (두보)」)
- `parseCategories(categories[])` → `{ genre, pubYear, pdTag }`
  - `1924년 작품` → 1924. 두 개면 **가장 이른 것**(「상록수」: 1935/1936 → 1935)
  - 장르 분류가 여러 개면 우선순위로: 장편소설 → 중편소설 → 단편소설 → 소설 → 시집 → 시 → 희곡 → 수필
  - 장르 분류가 없으면 null (「홍염」)
  - `PD-old-*` → pdTag
- `toBookCategory(genre)` → `소설`·`시`·`수필`·`희곡`·null

픽스처는 **실측한 실제 위키텍스트·분류 모양**을 쓴다. 단순화한 픽스처가 위 세 파싱 오류를 하나도 못 잡았다.

## 알려진 한계

- **PD 태그가 없는 문서는 목록에 없다.** 대개 번역물이거나 저작권 미확인 문서라 그게 맞는 동작이지만, 정상 작품인데 태그가 안 붙은 경우도 있을 수 있다. 주소 입력 화면이 그 경로다
- **`PD-old-*`는 위키문헌의 판단이고 우리 기준과 다르다.** 우리 기준은 PRD §5.11의 한국 저작권법(1962년 이전 사망)이며, 금지 목록은 그 태그와 무관하게 따로 있다. 태그는 **후보를 모으는 그물**일 뿐, 등록 허가가 아니다
- **목록은 동기화 시점의 스냅숏이다.** `synced_at`을 화면에 적어 언제 기준인지 보이게 한다
- **빈 껍데기는 목록에서 알 수 없다.** 「감자」는 분류상 정상 단편소설이지만 ws-export가 본문 2자만 내준다(기존 실측). 가져오기 시점의 `MIN_BODY_CHARS` 검사가 잡는다
- **2,350개 중 실제로 등록할 것은 수십 개다.** 나머지는 한시·낱편 시·수필처럼 도서로 낼 대상이 아닐 수 있다. 목록은 후보지 계획이 아니다
- 「강촌 (두보)」처럼 다른 틀을 쓰는 문서는 저자가 빈다(99개 중 1개). 목록에는 남고 가져올 때 저자를 입력받는다
