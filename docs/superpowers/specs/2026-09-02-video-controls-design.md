# 영상 재생 컨트롤 통합 · 유튜브 크롬 제거

작성일 2026-09-02 · 상태: 승인 대기 · 관련: PRD §5.3, `2026-09-01-home-feed-overlay-design.md`

## 문제

유튜브 임베드가 **자기 UI를 우리 화면 위에 그린다.** 상단에 제목·채널 바, 하단에 "동영상 더보기"·YouTube 로고 바, 가운데에 재생 컨트롤이 뜬다. 우리 크롬(액션 레일, 도서 정보 바)과 겹쳐서 남의 서비스가 우리 피드에 얹힌 것처럼 보인다.

두 번째 문제는 **조작이 유형마다 다르다는 것**이다. mp4 게시물에는 음소거 버튼이 있고 유튜브 게시물에는 아무 조작도 없다. 같은 피드에서 게시물마다 되는 게 다르다.

## 실측으로 확인한 것

추측이 여러 번 틀렸으므로 확인된 사실만 적는다 (2026-09-02, Chrome, 480px 프레임).

| 확인 | 결과 |
|---|---|
| `controls=0` · `modestbranding=1` | 크롬을 막지 못한다 |
| iframe에 `pointer-events: none` | **부족하다.** 크로스 오리진 iframe은 별도 프로세스라 브라우저가 히트 테스트를 건너뛰고 포인터 이벤트를 그대로 넘기는 경로가 있다 |
| 우리 문서 안에서 iframe을 덮는 층 | 포인터를 막는다 (`elementFromPoint`가 우리 층을 반환) |
| iframe을 위아래로 키워 잘라내기 | 상·하단 띠가 시작 순간에도 안 보인다 |
| `playlist=` 제거 | 가운데 ⏮ ⏭ 가 사라진다. ⏸ 하나만 1~2초 남는다 |
| 영상 우상단 주황색 ↺ | 파라미터와 무관하게 남고 위치가 영상 프레임 기준 — **영상에 박힌 워터마크**이지 유튜브 UI가 아니다 |
| 루프 재시작 | 돌 때마다 크롬이 다시 뜬다 (사용자 확인) |
| iframe은 replaced 요소 | `top`·`bottom`만 주면 안 늘어나고 기본 150px로 돌아간다 — 높이를 직접 줘야 한다 |

**검증 환경 주의:** 브라우저 패널이 화면에서 가려지면 페이지가 합성을 멈춘다. IntersectionObserver가 안 돌아 영상이 마운트되지 않고, 마운트돼도 크롬이 iframe 재생을 1.5초 안에 멈춘다(`playVideo()`를 불러도 `paused`로 떨어진다). 영상 동작은 **반드시 패널이 보이는 상태에서** 확인한다.

## 설계

### 구조

```
src/components/feed/
  video-player.tsx        소스 분기 + 뷰포트 판정만
  upload-video.tsx        <video> 제어 + 우리 컨트롤
  youtube-video.tsx       유튜브 IFrame API 배선 + 시작 마스크
  video-chrome.tsx        mp4 전용 컨트롤 (탭 레이어 + 가운데 글리프)
  mute-button.tsx         음소거 버튼 — 두 유형이 공유하는 유일한 컨트롤
  use-youtube-player.ts   API 스크립트 로드 + 플레이어 수명주기
```

훅은 조건부로 호출할 수 없으므로 소스별 컴포넌트를 나눈다. 훅은 피드 전용이라 `src/hooks/`로 올리지 않는다 (FRONTEND.md §1 — 미리 일반화하지 않는다).

### 컨트롤 주체는 유형별로 나눈다 (2026-09-02 개정)

처음 설계는 두 유형을 **우리 컨트롤 한 벌**로 통일하는 것이었다. 실제로 만들어 보니 유튜브 쪽에서 성립하지 않았다 — 플레이어가 재생·정지 순간 그리는 상태 전환 글리프는 끌 파라미터가 없고(§공식 문서 조사), 가리는 것은 약관 위반이며, 축소·덮개로 우회하면 정작 그 버튼이 조작 대상일 때 너무 작아 못 누른다. 그래서 주체를 나눴다.

| | 재생/일시정지 | 음소거 |
|---|---|---|
| mp4 | 우리 탭 레이어 + 가운데 글리프 (`video-chrome.tsx`) | `MuteButton` |
| 유튜브 | **플레이어 자체 버튼** — 우리 층은 포인터를 막지 않는다 | `MuteButton` (`controls=0`에서 유튜브가 음소거 UI를 주지 않는다) |

**모양을 맞추는 방법**: 구성이 같다 — 가운데 원형 글리프 + 우측 상단 음소거 버튼. 음소거 버튼은 실제로 같은 컴포넌트(`mute-button.tsx`)이므로 한쪽만 바뀔 수 없고, mp4의 가운데 글리프는 유튜브 것과 같은 자리·같은 원형·같은 페이드로 만든다. 유튜브 UI는 우리가 바꿀 수 없으니 **닮게 만드는 쪽은 항상 mp4다.**

z 계층 (게시물 컨텍스트 기준, `post-item.tsx` 주석 참조):

- iframe·video, 마스크, (mp4의) 탭 레이어 → z 없음(본문층). 위치를 가진 형제라 DOM 순서대로 쌓인다
- 가운데 글리프, 음소거 버튼 → `z-[3]` (스크림 위)

유튜브 게시물에서는 마스크가 `pointer-events-none`이고 탭 레이어가 없으므로, 화면 가운데를 누르면 포인터가 iframe에 그대로 닿는다 (실측: `elementFromPoint` → `IFRAME`).

### 유튜브 UI를 다루는 세 겹

| 겹 | 대상 | 방법 |
|---|---|---|
| 크롭 | 상단 제목·채널 바, 하단 "동영상 더보기"·로고 | `absolute -top-30 h-[calc(100%+240px)]` — 띠가 그려지는 자리를 article의 `overflow-hidden` 밖으로 민다. 플레이어는 영상을 iframe 중앙에 맞추므로 세로로만 키우고 같은 양을 위로 당기면 영상 위치·크기가 안 변한다 |
| 파라미터 | ⏮ ⏭ | `playlist=` 제거. 루프는 API가 맡는다. `modestbranding`은 폐기됐으므로 넘기지 않는다 |
| 마스크 | 로딩 중 검은 화면 | 유튜브 썸네일을 덮었다가 플레이어가 **처음** `PLAYING`에 들어간 시점부터 `POSTER_HOLD_MS`(700ms) 뒤 페이드아웃 |

**가운데 글리프는 더 이상 가리지 않는다.** 그것이 유튜브 게시물의 재생 컨트롤이다. 한때 있었던 3배 축소(`scale(1/3)`)와 덮개(`YT_GLYPH_MS`)는 제거했다 — 조작 대상을 작게 만들거나 덮으면 안 된다. `disablekb`도 넘기지 않는다: 키보드(스페이스·k)도 플레이어가 받아야 조작 경로가 남는다.

썸네일은 `https://i.ytimg.com/vi/<id>/hqdefault.jpg` — `maxresdefault`는 없는 영상이 있어 깨진다. `next/image`를 쓰므로 `next.config.ts` `remotePatterns`에 `i.ytimg.com`을 추가한다 (FRONTEND.md §6). 영상이 레터박스로 들어가므로 마스크도 `bg-black` + `object-contain`으로 같은 모양을 만든다.

### 시트가 덮으면 멈춘다 (2026-09-02 추가)

도서 상세·댓글·로그인 시트가 열리면 재생을 멈추고 닫히면 재개한다. 시트 뒤에서 소리가 계속 나고 데이터가 흐르는 것을 막는다.

새 개념을 만들지 않고 **기존 `active`로 환원**한다: `active = 화면에 보임 && 열린 시트 없음`. 자식 재생기 둘은 이미 `active`만 보므로 변경은 `video-player.tsx` 한 줄이다.

| 조각 | 역할 |
|---|---|
| `components/overlay-presence.tsx` | 열린 오버레이 수를 세는 셸 컨텍스트. 불리언이 아니라 카운터인 이유는 시트 위에 시트가 겹치기 때문이다(도서 시트 안의 로그인 시트) |
| `components/ui/drawer.tsx` | 열려 있는 동안 등록. **배선은 이 한 곳뿐** — 모든 시트가 이 래퍼를 거치므로 새 시트도 자동으로 지켜진다 |
| `components/feed/video-player.tsx` | 뷰포트 판정에 곱한다 |

사용자가 직접 멈춰 둔 영상은 시트를 여닫아도 멈춘 채 남는다. 별도 분기 없이 성립한다 — `active`가 false로 내려가는 것이 먼저이고 우리가 `pause`를 부르는 것은 그다음이라, 재생기들이 "사용자가 멈췄다"고 기록하는 경로(화면에 있는 동안 도착한 정지)를 타지 않는다.

### 루프

`ENDED` 상태로 보내지 않는다 — 종료 화면과 크롬이 거기서 나온다. 재생 중 250ms 간격으로 `getCurrentTime()`을 보고 `duration - 0.25s`를 넘으면 `seekTo(0, true)`. 폴링은 재생 중에만 돈다.

`ENDED`가 오더라도(폴링이 늦은 경우) 같은 처리를 한다 — 안전망이다.

### 뷰포트 이탈

지금은 화면 밖이면 iframe을 떼어 재생을 멈춘다. API가 생기면 `pauseVideo()`로 바꾼다. 되돌아왔을 때 초기화도 마스크도 없이 이어진다 — 마스크는 플레이어 생성 직후 한 번만 쓴다.

스크롤 창(앞뒤 2~3개) 밖으로 나가면 FeedScroller가 슬롯을 비우므로 컴포넌트가 언마운트되고, 그때 `player.destroy()`로 정리한다.

`<video>` 쪽은 지금 동작(`play()`/`pause()`)을 그대로 둔다.

### API 스크립트가 막히면

`https://www.youtube.com/iframe_api`는 광고 차단기에 막힐 수 있다. 로드 실패(또는 8초 타임아웃) 시 지금 방식 — 파라미터 임베드(`autoplay`·`mute`·`loop`·`playlist`) + 크롭 — 으로 폴백하고 컨트롤은 숨긴다. 크롬이 조금 보이더라도 영상이 아예 안 나오는 것보다 낫다.

### 문서 갱신

- PRD §5.3 — "탭으로 음소거 해제"를 새 규약으로 교체: 탭은 일시정지/재개, 음소거는 버튼, 유튜브도 같은 컨트롤
- PRD §11 — 결정 기록 한 줄 (유튜브 자체 UI를 쓰지 않고 우리 컨트롤로 통일한 이유)

DESIGN.md는 손대지 않는다 — 새 토큰 없이 기존 크롬 처방(흰색 한 벌, `bg-black/50` 원형 버튼)을 그대로 쓴다.

## 검증 기준

**패널이 화면에 보이는 상태에서**, 375px 뷰포트로 확인한다.

- 유튜브 게시물에서 제목 바·"동영상 더보기" 바·⏮⏭ 가 보이지 않는다 (가운데 글리프는 **보여야 한다** — 그게 컨트롤이다)
- 유튜브 게시물의 영상 가운데를 누르면 재생/일시정지가 토글된다 (`elementFromPoint`가 `IFRAME`을 반환하고, 플레이어가 자기 글리프로 반응한다)
- 16초 지점(루프)에서 종료 화면이 뜨지 않고 영상이 처음으로 돌아간다
- mp4 게시물은 화면을 탭하면 멈추고 가운데 ▶ 가 뜬다. 다시 탭하면 재개한다
- 음소거 버튼이 두 유형에서 같은 자리·같은 모양이고 둘 다 소리를 켜고 끈다
- 다음 게시물로 스크롤하면 재생이 멈추고, 돌아오면 이어진다. 플레이어 버튼으로 직접 멈춘 영상은 돌아와도 멈춰 있다 (mp4와 동일)
- 액션 레일·도서 바·읽기 버튼은 여전히 눌린다 (iframe이 포인터를 받게 됐어도 `z-[3]`이 위에 있다)
- 도서 상세·댓글·로그인 시트를 열면 재생이 멈추고, 닫으면 재개한다. 직접 멈춰 둔 영상은 여닫아도 멈춘 채로 남는다
- `npm run build` 통과


## 공식 문서 조사 (2026-09-02)

"유튜브 UI를 끄는 정식 방법이 있는지" 확인한 결과를 남긴다 — 없다는 것을 모르면 다음 사람이 같은 곳을 다시 뒤진다.

**파라미터로는 불가능하다.** [플레이어 파라미터 문서](https://developers.google.com/youtube/player_parameters) 전체를 확인했다.

| 파라미터 | 사실 |
|---|---|
| `controls=0` | 컨트롤 **바**만 숨긴다. 상태 전환 글리프는 대상이 아니다 |
| `modestbranding` | **2023-08-15 폐기, 효과 없음.** 그래서 코드에서 뺐다 |
| `showinfo` | 2018 폐기 — 채널 아바타·영상 제목은 재생 전 항상 표시된다 |
| `autohide` | HTML5 플레이어에서 폐기 — 컨트롤 표시·숨김은 플레이어가 정한다 |
| `loop` | IFrame 임베드에서 제한적 지원 — API로 되감는 현재 방식이 맞다 |

가운데 재생/일시정지 글리프를 가리키는 파라미터는 존재하지 않는다.

**약관과 어긋난다.** [Required Minimum Functionality](https://developers.google.com/youtube/terms/required-minimum-functionality)는 임베드 플레이어의 어떤 부분(컨트롤 포함)도 오버레이·프레임으로 앞을 가리거나 가려선 안 되고, API 문서에 없는 플레이어 변경도, 플레이어 위 마우스오버·터치로 동작을 일으키는 것도 금지한다. 최소 크기는 200×200(16:9는 480×270 이상)이고 자동재생은 절반 이상 보일 때만 허용된다.

우리가 썼던 기법 중 크롭·마스크·덮개·탭 레이어·축소가 그 조항에 걸린다. 피드의 액션 레일·도서 바도 플레이어 위에 얹혀 있다. **즉 "유튜브 UI를 감추고 우리 컨트롤로 통일"은 끝까지 갈 수 없는 방향이다.**

**결정 (2026-09-02)**: 현행 유지 — 단, 재생 컨트롤은 플레이어에 돌려줬다. 덮개·축소·탭 레이어(유튜브 쪽)를 지웠으니 위반은 크롭과 마스크, 그리고 원래부터 있던 액션 레일·도서 바로 줄었다. 완전 준수는 두 길뿐이었고 둘 다 택하지 않았다 — 피드를 mp4 전용으로 돌리거나(운영 부담), 유튜브 게시물만 별도 레이아웃으로 만들어 플레이어 앞을 비우거나(틀이 유형마다 달라진다). 재검토 트리거는 PRD §11-42에 적어 뒀다: 사용자 획득 시작 또는 유튜브 Data API 도입 시점.
## 알려진 한계

- **두 유형의 컨트롤은 "같은 구성"까지만 같다.** 유튜브 글리프의 크기·페이드 타이밍은 유튜브가 정하므로 픽셀 단위로 맞출 수 없다. 닮게 만드는 쪽은 항상 mp4다.
- **진입 후 0.7초는 썸네일이 덮는다.** 마스크가 걷힐 때 되감지 않으므로 영상은 그 지점부터 보인다.
- **영상에 박힌 워터마크는 못 지운다.** 우상단 주황색 ↺ 같은 것은 영상 픽셀이다.
- 유튜브가 임베드 UI를 바꾸면 크롭 값(120px)이 어긋날 수 있다. 띠가 다시 보이면 그 값을 조정한다.
- **mp4에는 없는 조작이 유튜브에는 생긴다** — 플레이어를 길게 누르거나 우클릭하면 유튜브 컨텍스트 메뉴가 나오고, 키보드로 포커스하면 플레이어가 받는다. 조작 주체를 넘긴 대가이고, 막으려면 다시 오버레이로 가리는 길밖에 없다.
- 이전 시도의 기록: `pointer-events: none`만으로는 크로스 오리진 iframe의 포인터를 막지 못했고(브라우저·버전에 따라 다르다), 우리 층으로 덮어야 막혔다. 지금은 **막지 않는 것이 목표**라 이 사실이 쓸모를 잃었지만, 다시 가리는 방향으로 돌아갈 일이 생기면 필요한 정보다.
