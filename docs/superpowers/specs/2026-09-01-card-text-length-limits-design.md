# 카드 텍스트 길이 상한

작성일 2026-09-01 · 상태: 승인 대기 · 선행: `2026-09-01-home-feed-overlay-design.md`

## 문제

오버레이 전환으로 카드 본문의 가용 폭이 375px 기준 **327px → 255px(-22%)**로 줄었고, `article`에 `overflow-hidden`이 붙었다. 그리고 `TemplateCard`는 `justify-center`라 넘치면 **위아래 양쪽으로** 잘린다.

훅·부연에는 길이 제한이 **없다**(`maxLength`·zod 스키마 모두 부재. 길이 제한은 댓글 1000자가 유일하다). 전에는 넘친 텍스트가 하단 바 위로 흘러 흉하지만 읽혔다. 지금은 스크롤 없이 하드 클립돼 **사라진다.**

지금 당장 깨진 것은 없다 — 실측하면 여유가 237px 남는다. 이 스펙은 **가드레일이 없는 상태**를 고치는 것이지 현존 버그를 고치는 것이 아니다.

## 확정 사항 (사용자 답변)

| 질문 | 답 |
|---|---|
| 가드레일 방식 | **글자 수 상한 + 편집기 카운터** (미리보기 오버플로 감지 대신) |
| 훅의 용도 | **원문 인용도 허용** — 짧은 카피로 한정하지 않는다 |
| 훅 상한 | **60자** |
| 부연 상한 | **90자** |

## 상한값의 근거

375px 뷰포트, 카드 본문 가용 폭 255px에서 실측했다.

| | 폰트 | 줄높이 | 한 줄 최대 (한글만) | 한 줄 최대 (공백 포함) |
|---|---|---|---|---|
| 훅 | 20px / 700 | 27.5px | 13자 | 17자 |
| 부연 | 14px / 400 | 22.8px | 19자 | 25자 |

`break-keep` 때문에 한국어 어절이 쪼개지지 않아 실제 줄바꿈은 **공백 없는 최악값** 쪽에 붙는다. 그 값으로 계산한다.

**예산:** 훅+부연이 쓸 수 있는 높이는 **311px**이다 (현재 사용 74px + 여유 237px, 템플릿 a 기준).

**375px에서:** 훅 60자 = 5줄(137.5px), 부연 90자 = 5줄(114px) → 251.5px. 예산 대비 **60px 여유**.

### 320px는 빠듯하다 (명시적으로 감수)

320px에서는 가용 폭이 200px로 줄어 훅 10자/줄, 부연 15자/줄이 된다. 훅 6줄(165px) + 부연 6줄(137px) = 302px로 예산 311px에 **9px 여유**밖에 안 남고, 서지가 한 줄 더 접히면 넘친다.

`docs/FRONTEND.md`가 **375px를 기준 뷰포트로 문서화**했으므로 그 기준으로 잡는다. 320px 기기에서 훅·부연을 상한까지 채운 게시물은 잘릴 수 있다 — 알려진 한계다. 320px까지 보장하려면 훅 50자여야 하는데, 그러면 아래 "기존 콘텐츠"의 시드 인용문이 깨진다.

## 기존 콘텐츠

두 곳을 실제로 세었다. **둘 다 봐야 한다** — 시드 파일은 `npm run seed`가 DB에 쓸 내용이라, 상한이 시드를 거부하면 재시드가 깨진다.

| 출처 | 훅 길이 | 부연 길이 |
|---|---|---|
| **실제 DB** (post_cards 8건) | 10 14 15 15 15 15 17 **20** | 33 34 36 37 40 42 42 **43** |
| **시드 파일** (`scripts/seed.mjs`) | 23 33 34 36 38 50 **54** | 33 34 36 37 40 42 42 **43** |

DB와 시드가 다르다 — DB는 짧은 카피, 시드는 원문 인용이다. 같은 영역이 두 방식으로 쓰이고 있고, 사용자가 **둘 다 허용**하기로 했다.

훅 60자는 시드 최장 54자를 담고, 부연 90자는 양쪽 최장 43자에 2배 여유를 준다. **마이그레이션도 시드 수정도 불필요하다.**

## 강제 지점 세 곳

### 1. `REGION_REGISTRY` — 단일 출처

`RegionEntry`에 `maxLength?: number`를 추가하고 `hookRegion`에 60, `descRegion`에 90을 둔다. `input`·`required`가 이미 사는 자리라 새 개념을 만들지 않는다.

`maxLength`는 **선택 필드**다. `input: null`인 영역(커버·장르·서지)은 텍스트 입력이 없으므로 값을 갖지 않는다.

### 2. 어드민 편집기 — 입력 차단 + 카운터

`post-editor.tsx`의 `Input`/`Textarea`에 `maxLength` 속성을 넘겨 초과 입력 자체를 막고, 그 아래에 `n/60` 카운터를 둔다. 길이가 **상한의 90% 이상**이면(훅 54자, 부연 81자) 카운터를 `destructive`로 바꿔 근접을 알린다.

`maxLength`가 없는 영역에는 카운터를 렌더하지 않는다.

**세는 단위는 `String.length`(UTF-16 코드 유닛)다.** 한글은 1, 이모지는 2로 세어질 수 있지만, 카드 문구는 한국어 산문이라 실용상 문제가 없고 브라우저 `maxLength`와 세는 방식이 같아 편집기와 서버가 어긋나지 않는다.

### 3. 서버 액션 — 방어선

`posts/actions.ts`의 `readLayout()`이 필수값을 검사하는 자리에서 길이도 검사하고, 초과분은 기존 오류 규약(`{ error: string }` 반환 → `redirect`로 메시지 노출)을 그대로 따른다.

**검사 대상은 `.trim()` 이후 값이다** — `readLayout()`이 이미 `.trim()`한 뒤 필수 여부를 판단하므로 같은 값에 길이를 잰다. 앞뒤 공백만으로 상한을 넘기는 일이 없다.

브라우저 `maxLength`는 formData 위조로 우회되므로 서버 검사가 필요하다. 이건 중복이 아니라 **다른 신뢰 경계**다.

## 검증 기준

측정 가능한 것만 적는다.

- `REGION_REGISTRY`의 `hook.maxLength === 60`, `desc.maxLength === 90`
- 편집기에서 훅 입력란에 61자를 붙여넣으면 60자에서 잘린다
- 카운터가 현재 길이와 상한을 표시하고, 상한의 90% 이상(훅 54자 / 부연 81자)에서 색이 바뀐다
- `maxLength` 없는 영역(커버·장르·서지)에는 카운터가 없다
- 서버 액션에 61자짜리 `region-hook-text`를 직접 던지면 저장되지 않고 오류 메시지가 뜬다
- `npm run seed`가 상한 위반 없이 통과한다 (시드 최장 훅 54자 < 60)
- `npm run build` 통과

## 알려진 한계

- **320px 기기에서 상한까지 채운 게시물은 잘릴 수 있다** (위 "320px는 빠듯하다").
- 글자 수는 **근사치**다. 실제 잘림은 조합(템플릿 a/b, 커버 유무, 서지 길이)으로 결정되므로, 상한 안에서도 특정 조합은 잘릴 수 있고 반대로 여유가 남는데 막힐 수도 있다. 정확한 방어는 미리보기 오버플로 감지인데, 사용자가 편집자 예측 가능성("몇 자까지"가 목표가 되는 것)을 우선해 글자 수 상한을 택했다.
- 훅·부연 외 영역(커버·장르·서지)의 텍스트는 도서 레코드에서 오므로 이 상한의 대상이 아니다. 서지가 길어 여러 줄로 접히는 경우는 여전히 예산을 잠식한다.
