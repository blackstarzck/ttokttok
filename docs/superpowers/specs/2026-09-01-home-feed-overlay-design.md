# 홈 피드 오버레이 계층 — 분할 레이아웃 해체

작성일 2026-09-01 · 상태: 승인 대기

## 문제 (계층 개념 교정)

현재 `PostItem`은 게시물 한 장을 세로 flex로 **분할**한다. 액션 레일이
카드의 가로 형제이고, 하단 도서 정보 바가 세로 형제(`border-t` 포함)다.
그래서 카드 영역은 "화면 전체"가 아니라 "레일과 바를 뺀 나머지"다.

실제 의도는 다르다. **홈의 구조적 형제는 둘뿐**이다:

1. 하단 액션 바 (`BottomNav`: 홈 / 탐색 / 프로필)
2. 컨텐츠 영역

나머지는 전부 컨텐츠 영역 **위에 얹히는 오버레이 레이어**다 — 우측 세로
액션 레일, 하단 도서 정보 바. 화면상 결과는 비슷해 보이지만 이유가 다르고,
그 차이가 여백·색·가독성 처방을 전부 바꾼다.

## 확정 사항 (사용자 답변)

| 질문 | 답 |
|---|---|
| 계층 | 홈 = 하단 액션 바 + 컨텐츠 영역, **나머지는 컨텐츠 영역 위 레이어** |
| 피드 캔버스 | **사용자 테마를 따른다** (원칙 2 · 결정 기록 §11-34 유지) |
| 카드 레이아웃 | **풀블리드** — 카드에 별도 표면(`card`)을 주지 않는다 |
| 크롬 처방 | **게시물 유형별로 나누지 않고 하나로 통일** |
| 통일 방향 | **검정 스크림 + 흰 텍스트 고정** (영상 처방을 카드에도) |
| 스크림 세기 | **A 유지** — 키우지 않는다 |
| 레일 가독성 | 필·배경 대신 **아이콘·숫자에 그림자** (L2) |

깔린 가정: 텍스트 카드가 피드의 주력이고, 영상 게시물은 소수다. 크롬이
한 벌이라는 단순함을 라이트 테마의 시각적 대비보다 우선한다.

## 선례 조사 (실측)

결정 근거로 인스타·유튜브·틱톡을 직접 띄워 계산된 CSS를 읽었다. 네 케이스
모두 **문서가 라이트 테마인 상태**에서 측정했다.

| 대상 | 레이아웃 | 스크림 | 텍스트 | 테마 |
|---|---|---|---|---|
| YouTube Shorts (m.youtube.com, 375px) | 오버레이 | `rgba(0,0,0,0.4)` 상단 96px + 하단 160px, 검정 하드코딩 | `#ffffff`, text-shadow 없음 | 면제 (`html` 배경은 `#fff`) |
| YouTube Shorts (데스크톱 1196px) | 레일을 미디어 밖으로 | 미디어 안쪽 하단 116px | 미디어 위 `#fff` / 밖 `rgb(15,15,15)` | 미디어 밖은 테마를 따름 |
| TikTok (375px) | 오버레이 | `rgba(0,0,0,0.24)` 상단 87px | `#ffffff` | 면제 (`data-theme=light`) |
| Instagram (릴 embed) | **분할** | 없음 (그라디언트 0개) | `rgb(0,0,0)` | 따름 |

두 가지가 드러났다.

1. **아무도 "테마를 따르는 스크림"을 쓰지 않는다.** 크롬이 미디어 위면
   검정 + 흰색으로 테마를 면제하고, 테마를 따르려면 크롬을 미디어 밖으로 뺀다.
2. **같은 콘텐츠도 표면이 바뀌면 처방이 정반대가 된다.** 인스타 릴은 앱에선
   풀스크린 오버레이지만 embed로 카드가 되면 스크림 0개·검정 텍스트·완전 분할이다.

다만 넷 다 캔버스가 **항상 영상**이라 테마 면제가 공짜다. 우리는 텍스트
카드가 주력이라 조건이 다르고, 그 차이가 아래 "알려진 한계"로 남는다.

## 레이어 계층

```
MainLayout (h-dvh, flex-col)
├── main (flex-1, min-h-0)          ← 컨텐츠 영역
│   └── FeedScroller
│       └── PostItem (h-full, relative)
│           ├── z-0   본문        : TemplateCard | VideoPlayer  (풀블리드)
│           ├── z-2   스크림      : 하단 그라디언트
│           └── z-3   크롬        : 액션 레일 · 도서 정보 바 · 음소거 버튼
└── BottomNav (z-50)                ← 형제. 자기 높이를 차지한다
```

z 스케일을 문서화한다 — 지금은 `BottomNav`의 `z-50`만 명시돼 있어서
오버레이가 늘어나면 겹침 사고가 난다.

| 층 | z | 내용 |
|---|---|---|
| 본문 | 0 | 카드 본문, 영상 |
| 스크림 | 2 | 하단 그라디언트 |
| 크롬 | 3 | 액션 레일, 도서 정보 바, 음소거 버튼 |
| 셸 | 50 | `BottomNav` (현행 유지) |
| 시트·모달 | portal | Radix가 관리 (현행 유지) |

## 크롬 사양

크롬은 **게시물 유형·테마와 무관하게 한 벌**이다. 테마를 타는 것은 카드
본문과 `BottomNav`뿐이다.

### 스크림

```css
/* 컨텐츠 영역 하단. 검정 고정 — 테마 면제 */
background: linear-gradient(
  to top,
  rgb(0 0 0 / 0.45) 0%,
  rgb(0 0 0 / 0.26) 35%,
  rgb(0 0 0 / 0.15) 60%,
  rgb(0 0 0 / 0.06) 80%,
  transparent 100%
);
height: 120px;
```

세 번 조정했다 (2026-09-01 리뷰 피드백).

1. 처음 값은 유튜브 실측을 따라 160px 2-stop 선형(바닥 0.55) — "범위가
   너무 넓고 서서히 투명해지는 느낌이 아니다"로 기각. 2-stop 선형은 상단
   경계에서 기울기가 뚝 끊겨(마흐 밴드) 전체가 띠로 인식된다.
2. 다음은 120px + 하단 60%를 거의 평평하게 유지하는 커브(바 구간 가독성
   우선) — 여전히 "점차 투명해지는 느낌이 아니다"로 기각. 평평한 하단이
   어두운 띠로 보이고, 위쪽에서만 급히 사라진다.
3. 전 구간 단조 감소로 바꾼 뒤에도 바닥 0.55는 무겁다는 피드백 — 바닥을
   0.45로 내리고 중간 스톱도 같은 비율(×0.82)로 함께 내렸다. 커브 모양은
   유지하고 전체 농도만 낮춘 것이다.

최종 커브는 **전 구간 단조 감소(ease-out)**다. 구간별 기울기가 위로
갈수록 줄어 어디에도 경계가 없고 처음부터 끝까지 점차 옅어진다. 대가로
도서 정보 바 구간 농도가 낮아진다(바 중심 ≈0.23, 바 상단 ≈0.09) —
흰 텍스트 가독성은 스크림이 아니라 글리프 그림자(`feed-chrome-text`)가
담당한다는 원칙("그림자 (L2)")을 바 텍스트까지 확장한 셈이다.

### 색 (전부 고정값, 토큰 아님)

| 대상 | 값 |
|---|---|
| 레일 아이콘 · 카운트 | `#ffffff` |
| 읽기 라벨 | `#ffffff` |
| 도서 제목 | `#ffffff` |
| 장르 · 저자 | `rgba(255,255,255,.9)` |
| 읽기 CTA | 배경 `#ffffff` · 아이콘 `#111111` |
| 미니 커버 · 채널 아바타 | 배경 `rgba(0,0,0,.28)` · 테두리 `rgba(255,255,255,.5)` · 글자 `#ffffff` |

미니 커버와 아바타의 배경이 **어두운 반투명**인 점이 중요하다. 현재
`BookCover` 폴백은 `bg-card`라 흰 배경 위에서 흰색이 되어 사라진다.

### 그림자 (L2)

스크림은 레일 전체 높이를 덮지 못한다 — 레일이 세로 약 200px인데 그라디언트는
위로 갈수록 약해진다. 실측하면 레일 상단 세 항목이 밝은 배경에서 대비 **1.06**
까지 떨어진다. 그림자가 이 구간을 담당한다.

```css
/* 아이콘 — SVG 획 모양을 따라간다 */
filter: drop-shadow(0 0 1px rgba(0, 0, 0, 0.65))
        drop-shadow(0 1px 1px rgba(0, 0, 0, 0.3));

/* 숫자 · 라벨 */
text-shadow: 0 0 1px rgba(0, 0, 0, 0.65),
             0 1px 1px rgba(0, 0, 0, 0.3);

/* 읽기 CTA — 흰 원의 가장자리를 세운다 */
box-shadow: 0 0 0 1px rgba(0, 0, 0, 0.22),
            0 1px 2px rgba(0, 0, 0, 0.2);
```

가독성을 만드는 것은 **1px 밀착 윤곽**이고, 넓은 헤일로는 번짐만 만든다.
그래서 헤일로 없이 윤곽 + 짧은 낙차 두 겹으로 끝낸다.

### 치수 · 세이프존

분할이 만들던 여백을 이제 컨텐츠의 패딩이 만든다.

| 항목 | 값 | 근거 |
|---|---|---|
| 레일 위치 | `right: 8px` · `bottom: 100px` | 바 하단 여백(12) + 도서 바(76) + 여유(12) |
| 레일 항목 | 44×44 이상 · 항목 간 `gap: 16px` | 터치 타깃 하한 (DESIGN.md "인접 타깃 간 8px 이상") |
| 읽기 CTA | 지름 44~46px, 레일 마지막 자리 | 엄지에 가장 가깝게 (PRD §5.1) |
| 도서 정보 바 | 높이 76px · `bottom: 12px` · `padding: 0 12px` · 풀블리드 | 바닥에 붙이지 않는다 — BottomNav와 숨통 (2026-09-01 피드백) |
| 카드 본문 패딩 | 상 20 · **좌우 각 60** · 하 96 | 좌우 대칭이라야 중앙정렬이 안 어긋난다. 하 96 = 12 + 76 + 8 |

좌우 60px = 레일 우측 여백 8 + 레일 폭 44 + 여유 8. 우측만 넓히면 중앙정렬
콘텐츠가 프레임 중심에서 왼쪽으로 밀려 보인다(측정값 −22px).

### 영상 게시물

풀블리드가 되므로 `object-contain` → `object-cover`로 바꾼다. 지금 레터박스가
생기는 건 분할된 상자에 맞추려던 타협이었다.

음소거 버튼은 `top: 14px; right: 14px`로 두어 레일과 같은 우측 열에 정렬한다.
배경은 현행 `rgba(0,0,0,.5)`를 유지한다 — 크롬 중 유일하게 이미 자기 배경을
가진 요소이고, 상단에는 스크림이 없어 그림자만으로는 부족하다.

## 알려진 한계

**WCAG 대비 수치는 낮게 남는다.** 대비비 공식은 균일한 배경 위의 전경색을
재는 것이라 윤곽선·그림자를 모델링하지 못한다. 흰 글리프의 면은 밝은 카드
위에 그대로 있으므로 숫자는 오르지 않는다. 실제로 읽히는 이유는 1px 근검정
윤곽이 글리프 경계를 만들기 때문이다.

이는 **의도적 선택**이다. 대안(크롬마다 `rgba(0,0,0,.6)` 배경)은 측정상
5.99:1로 통과하지만 크롬이 물성을 얻어 원칙 1("UI는 무채색으로 물러나고,
콘텐츠 위 오버레이는 최소한으로")과 정면으로 어긋난다. 형태를 우선했다.

인스타·유튜브·틱톡도 같은 지점에서 같은 타협을 한다(유튜브 레일 상단은
스크림 밖에 있다). 다만 그들의 캔버스는 영상이라 밝은 프레임이 가끔이고,
우리 카드는 항상 밝다는 차이가 있다. **접근성 재검토가 필요해지면 이
문단이 출발점이다.**

## 검증 기준

측정 가능한 것만 적는다.

- 카드 본문의 어떤 텍스트도 레일·도서 바와 바운딩 박스가 겹치지 않는다
- 중앙정렬 콘텐츠의 중심이 프레임 중심과 일치한다 (오차 0px)
- 모든 터치 타깃이 44×44px 이상이고 인접 타깃 간격이 8px 이상이다
- 12px 미만 텍스트가 없다
- 순백(`#ffffff`) 카드에서 레일 아이콘과 카운트(655 / 0 / 43)가 판독된다
- 영상 게시물의 라이트·다크가 `BottomNav`를 제외하면 동일하다
- 테마를 전환해도 크롬의 색이 변하지 않는다
- 페이지 레벨 가로 스크롤이 없다
- 스냅 스크롤이 게시물 단위로 유지된다 (오버레이 전환으로 깨지지 않는지)
