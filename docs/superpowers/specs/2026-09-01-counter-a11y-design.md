# 글자 수 카운터 접근성

작성일 2026-09-01 · 상태: 승인됨 · 선행: `2026-09-01-card-text-length-limits-design.md`

## 문제

어드민 카드 편집기의 글자 수 카운터가 **시각 전용**이다. `aria-describedby`도 라이브 영역도 없다.

더 중요한 건 `maxLength`가 입력을 **조용히** 차단한다는 것이다. 60자에 도달하면 키를 눌러도 글자가 나타나지 않는데, 시각 사용자는 카운터가 `60/60`에서 멈추고 `text-destructive`로 바뀐 것을 보지만 스크린리더 사용자에게는 **아무 신호도 없다.** 왜 입력이 안 되는지 알 방법이 없다.

## 왜 `aria-live`를 카운터에 그냥 붙이면 안 되는가

카운터 내용은 타이핑마다 바뀐다. `aria-live="polite"`를 붙이면 "1/60", "2/60", "3/60"…이 연속으로 읽혀 화면 낭독이 불가능해진다. 널리 알려진 안티패턴이다.

## 설계

역할이 다른 두 장치를 나눈다.

### 1. `aria-describedby` — 포커스 시 한 번

카운터 `<p>`에 `id={`region-${key}-count`}`를 주고, 입력란이 `aria-describedby`로 참조한다. 포커스가 들어올 때 "훅 문구, 편집, 0/60"처럼 한 번 읽힌다. 타이핑 중에는 조용하다.

`maxLength`가 없는 영역은 카운터가 없으므로 `aria-describedby`도 `undefined`다.

### 2. 시각적으로 숨긴 라이브 영역 — 경계에서만

`sr-only` + `aria-live="polite"` 영역을 카운터 옆에 둔다. 내용은 숫자가 아니라 **상태 문구**이고, 경계에서만 바뀐다.

| 길이 | 내용 |
|---|---|
| `< 90%` | 빈 문자열 (무음) |
| `>= 90%`, `< 상한` | `글자 수 상한에 가까워요.` |
| `>= 상한` | `상한에 도달했어요. 더 입력할 수 없어요.` |

값이 두 경계에서만 바뀌므로 54자에서 60자까지 타이핑해도 안내는 **두 번**뿐이다. 방향당 한 번씩이다.

세 번째 상태가 이 설계의 핵심이다 — 입력이 조용히 막히는 것을 알리는 **유일한** 신호다.

이 구조(숨긴 라이브 영역 + 포커스 시 설명)는 GOV.UK Design System의 character count 컴포넌트가 쓰는 것과 같다. 새로 발명하지 않았다.

### 임계값은 한 곳에서

지금 카운터가 `entry.maxLength * 0.9`를 인라인으로 쓴다. 라이브 영역도 같은 임계를 써야 시각 신호와 청각 신호가 어긋나지 않으므로, `NEAR_LIMIT_RATIO = 0.9` 상수로 뽑아 양쪽이 참조한다.

### 디바운스는 넣지 않는다

GOV.UK는 1초 디바운스를 두지만, 그건 라이브 영역이 매 입력마다 갱신되는 구조이기 때문이다. 이 설계는 경계에서만 바뀌므로 디바운스가 할 일이 없다.

## 범위

- `src/components/admin/post-editor.tsx` — 위 두 장치와 상수
- `docs/FRONTEND.md` §2 접근성 최소선 — 새 규약 한 줄 추가. 지금은 "아이콘 단독 버튼에 `aria-label`, 활성 탭에 `aria-current`, 자동재생 음소거" 셋뿐이라, 적어두지 않으면 다음 사람이 `aria-live`를 카운터에 직접 붙인다.

## 검증 기준

- 입력란의 `aria-describedby`가 카운터 `<p>`의 `id`와 일치한다
- `maxLength` 없는 영역(커버·장르·서지)의 입력란에는 `aria-describedby`가 없다
- 라이브 영역이 `sr-only` + `aria-live="polite"`이고, 길이가 상한의 90% 미만일 때 내용이 빈 문자열이다
- 훅 53자 → 54자에서 내용이 `글자 수 상한에 가까워요.`로 바뀐다
- 훅 60자에서 `상한에 도달했어요. 더 입력할 수 없어요.`로 바뀐다
- 시각 카운터의 색 전환과 라이브 영역의 첫 문구가 **같은 길이**에서 일어난다 (같은 상수를 쓰므로)
- `npm run build` 통과

## 알려진 한계

`aria-live` 안내는 스크린리더가 켜져 있을 때만 의미가 있다. 시각 장애가 없지만 인지적으로 도움이 필요한 사용자에게 입력 차단은 여전히 조용하다 — 시각 카운터의 색 전환이 그 몫이고, 이 스펙은 그것을 바꾸지 않는다.
