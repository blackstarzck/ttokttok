# 모노레포 실행·배포 전환

사용자 앱은 기존 주소를 유지하며, 관리자는 별도 앱에서 `/admin`으로 접속한다. 저장소·브랜치·DB 구조는 그대로다. 2026-09-10 같은 Git 저장소의 master에 통합한 뒤 두 Vercel 프로젝트로 전환했다. 운영 DB 구조·데이터 이관은 없었다.

## 구조와 실행

| 위치 | 책임 |
|---|---|
| `apps/client` | 사용자 화면, 소셜 로그인, 피드·댓글·독서 기록, 전자책 뷰어. 기본 포트 3000 |
| `apps/admin` | 관리자 로그인·권한 확인, 콘텐츠 작성·파일 업로드·신고 처리. 기본 포트 3001 |
| `packages/shared` | 타입·검증·카드 입력 정의·순수 EPUB 변환. React·Next·DOM·네트워크 금지 |
| `packages/database` | 브라우저·서버 접속 팩토리, 비밀 키 사용의 서버 경계, 생성된 DB 타입 |
| `packages/ui` | 공용 React 화면, 카드 본문과 편집 미리보기, 기본 컴포넌트·테마 |
| `packages/content` | 관리자와 루트 스크립트가 공유하는 외부 EPUB 수집. 네트워크 작업을 순수 shared에서 분리 |
| 루트 | npm 워크스페이스·잠금 파일, 테스트 설정, scripts·supabase·docs·AGENTS.md |

루트에서 `npm ci` 후 `npm run dev`로 두 앱을 함께 실행한다. `dev:client`, `dev:admin`, `build:client`, `build:admin`, `start:client`, `start:admin`으로 개별 실행도 가능하다. `npm run build`는 두 앱을 순서대로 빌드한다. 각 앱 디렉터리에서 `npm run build`를 실행해도 된다.

환경 파일은 Next.js의 앱별 읽기 규칙을 따른다. `apps/client/.env.example`, `apps/admin/.env.example`을 같은 디렉터리의 `.env.local`로 복사한다. 루트 `.env`는 기존 운영 스크립트용으로 유지한다. 루트 환경 파일이 각 앱에 자동 적용된다고 가정하면 안 된다. 로컬 이동 시 기존 설정에서 필요한 값만 앱별 파일에 복사했으며 이 파일은 Git에서 제외한다.

## 운영 영향

| 대상 | 유지되는 것 | 전환 시 확인할 것 |
|---|---|---|
| 사용자 URL·소셜 로그인 | 기존 사용자 도메인, `/auth/callback`, 기존 Supabase 사용자 쿠키 이름 | 사용자 프로젝트의 빌드 루트 변경. Google/Kakao 및 Supabase의 기존 사용자 콜백 허용 주소 유지 |
| 관리자 URL·로그인 | `/admin` 및 하위 경로, 비밀번호 로그인, 관리자 역할 검사 | 새 관리자 도메인. 관리자는 새 쿠키로 한 번 다시 로그인 |
| 기존 `/admin` 즐겨찾기 | 하위 경로와 검색 조건을 보존해 새 관리자 앱으로 이동 | client의 `ADMIN_URL`에 admin의 최종 **출처** 지정. 같은 출처를 넣으면 루프 대신 503 반환 |
| 기존에 열려 있던 관리자 폼 | 기존 배포가 남아 있는 동안 기존 폼 동작 | 전환 후 예전 폼 제출은 새 앱을 여는 303 이동. 배포 직전 편집을 저장하고 새 화면을 열 것. 오래된 서버 액션을 다른 배포에 전달하지 않음 |
| 관리자에서 사용자 화면 열기 | 서비스 보기·게시물 보기 동작 | admin의 `CLIENT_URL` 지정. 발행한 게시물은 사용자 앱의 절대 주소로, 임시저장 게시물은 관리자 편집 미리보기로 연결 |
| 콘텐츠 갱신 | 같은 DB와 저장소 사용, 데이터 이관 없음 | 앱별 서버 조회는 `no-store`. 관리자 저장 후 사용자 앱의 다음 요청에서 새 데이터 확인. 이미 열린 화면의 자동 실시간 갱신은 기존과 동일하게 제공하지 않음 |
| 전자책·파일 | 기존 버킷·파일 경로·서명 주소 방식 | 비공개 EPUB을 여는 client에도 서버 비밀 키가 필요. admin만 비밀 키를 가진다고 가정하면 읽기가 깨짐 |
| CSS·폰트·아이콘 | 기존 화면 디자인과 폰트 라이선스 | 앱별 정적 자산과 공용 테마 소스 탐색 경로. 앱 바깥 공용 패키지를 빌드에 포함 |

## Vercel 전환 순서

2026-09-10 적용한 설정이다. 연결 앱의 계정에서는 403이 발생했지만, 이 컴퓨터에 로그인된 기존 Vercel CLI 계정으로 실제 프로젝트를 조회하고 설정했다.

| 항목 | 사용자 | 관리자 |
|---|---|---|
| 프로젝트 | ttokttok | ttokttok-admin |
| 운영 주소 | https://ttokttok-virid.vercel.app | https://ttokttok-admin.vercel.app/admin |
| 빌드 루트 | apps/client | apps/admin |
| Git | blackstarzck/ttokttok, master | 같은 저장소, master |
| 빌드 | npm run build, Next.js, Node 24.x | 동일 |
| 루트 밖 공용 소스 | 포함 | 포함 |

미리보기와 운영에 필요한 환경 설정을 각각 등록했고 값의 일치도 확인했다. 기존 사용자 도메인과 Git remote·브랜치는 유지했다. 이후 master 푸시는 두 프로젝트의 자동 배포로 연결되며, 변경 없는 앱은 Vercel의 변경 감지로 생략될 수 있다. Git 푸시로 두 프로젝트의 배포가 생성되는 것도 확인했다.

아래 순서는 이후 재전환에도 적용한다.

1. 기존 사용자 프로젝트와 도메인을 보존한다. 같은 Git 저장소에 관리자 프로젝트를 추가하고 Root Directory를 `apps/admin`으로 지정한다. 프레임워크는 Next.js, 빌드 명령은 앱 기준 `npm run build`, 출력은 기본값을 사용한다. 앱 루트 밖의 공용 소스를 포함하는 설정을 켠다. 설치는 저장소 루트의 npm 워크스페이스와 단일 잠금 파일을 사용해야 한다.
2. 관리자 프로젝트에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `CLIENT_URL`을 등록한다. `CLIENT_URL`은 현재 사용자 사이트의 출처다. `ADMIN_EMAIL`·`ADMIN_PASSWORD`는 배포 앱에 필요하지 않다. 관리자 도메인에서 로그인·업로드·발행·사용자 화면 보기까지 확인한다.
3. 기존 사용자 프로젝트 Root Directory를 `apps/client`로 변경한다. 사용자용 Supabase 값과 `NEXT_PUBLIC_SITE_URL`은 유지하고 `ADMIN_URL`을 새 관리자 출처로 지정한다. 공용 소스 포함 설정과 루트 잠금 파일 설치를 확인한다. 사용자 도메인은 변경하지 않는다.
4. 두 프로젝트의 미리보기 배포에서 각각 E2E를 실행하고 배포 검토를 마친 뒤 운영 전환한다. 이 저장소의 자동 테스트는 로컬 전용 DB만 허용하므로 운영 데이터에 그대로 실행하지 않는다. 운영에서는 읽기·로그인·별도 승인한 테스트 콘텐츠만으로 확인한다.
5. 같은 커밋의 두 빌드가 동시에 원자적으로 바뀌지는 않는다. 이번 변경은 DB·카드 형식을 바꾸지 않으므로 기존 단일 앱과 새 관리자 앱이 전환 중 공존할 수 있다. 새 관리자 검증 후 사용자 프로젝트를 전환하는 순서를 권장한다.

Vercel은 앱별로 필요한 의존성만 설치할 수 있으므로 각 앱에 TypeScript·Node/React 타입을 직접 선언했다. 사용자 앱 안의 단위 테스트도 빌드 중 타입 검사되므로 테스트 도구 의존성도 사용자 앱에 명시했다. 공통 루트에만 선언해 로컬에서 우연히 설치되는 상태에 의존하지 않는다.

`NEXT_PUBLIC_*` 값은 빌드 시 결정된다. 테스트 DB로 만든 로컬 `.next`를 운영 환경에서 재사용하지 말고 운영 설정으로 다시 빌드한다. 미리보기와 운영 환경 변수는 각각 설정한다. 관리자는 라이트 고정이며 사용자 테마 설정에 영향을 주지 않는다.

## 복구

문제 발생 시 사용자 프로젝트를 직전 정상 단일 앱 배포 `dpl_3wPMJbLPbzfRRaNs1RuHUwDXdtFn`으로 되돌릴 수 있다. 해당 배포는 기존 소스 `9d934b9`이며 전환 전 설정은 로컬 `.tmp/vercel-client-before.json`에 보관했다. 단순히 소스 브랜치만 되돌려 새 빌드를 만들 경우 Root Directory도 기존 루트로 복원해야 한다. 새 관리자 주소 안내를 중단하고 기존 사용자 도메인의 `/admin`으로 접속한다. DB 마이그레이션이 없으므로 콘텐츠·사용자 기록을 롤백할 필요가 없다. 새 앱에서 저장한 기존 형식 데이터는 이전 앱에서도 읽힌다. 재전환할 때 각 앱 배포·환경 설정·도메인 연결을 다시 확인한다.
